# Phoenix 研究质量基准

[English](README.md) | 中文

**本套件是可复现的审计，不代表语言模型已经达到高准确率或高速度。**
仓库中提交的案例特意使用**合成数据**，从而保证自动测试具备确定性、
不需要密钥，也不冒充实时新闻。合成样例获得 100/100 仅证明
**评分器**能够工作，不代表 Kira 的实际研究能力达到该分数。

## 之前缺少什么

Phoenix 基础配置安装了 `web_search`，却禁用了 `web_fetch`。
只有搜索摘要无法确认重要来源的全文、方法、日期或限制。
本次修改在基础配置中启用现有的匿名 HTTP 阅读器，屏蔽私有和
保留网络地址，禁止发送凭证，仅允许同源重定向，并限制内容大小、
超时与 Cookie。对模型选择的 URL 绝不可启用 `allowPrivateNetworks`。

**安全性：**本版本在验证 URL 与同源重定向之外，还把每个实际
出站连接的 DNS 查询绑定到经过检查的公共 IP 地址。
它不会发送 Cookie 或密码库中的秘密。高安全等级部署
仍应通过限制出站连接的防火墙或代理进一步防护。

## 三阶段验证

1. **离线来源访问测试：**生产 Cordis 配置启用公共
   `web_fetch` 阅读器，阻止私有网络目标；已有提供商测试
   验证安全重定向、HTTP 解析、超时和资源限制。
2. **离线基准契约测试：**独立固定的语料核查事实、
   原始来源引用、真实抓取回执、独立域名、时效性、
   执行时间和令牌。伪造 URL、未阅读的搜索摘要和无依据结论
   都会自动失败。
3. **Phoenix Desktop/headless 实际挑战（真实能力声明必须完成）：**
   让 Phoenix 与对照系统处理相同任务，使用相同时间与模型预算，
   保存实际会话工具结果及令牌用量，再请独立审核者核实
   所有重要事实。在第三阶段完成前，不可声称 Phoenix 达到
   90/100 或超过 ChatGPT。

## 运行离线门禁

```sh
node --test scripts/phoenix-research-benchmark.test.mjs
node scripts/phoenix-research-benchmark.mjs \
  --cases reports/research-quality/cases.synthetic.json \
  --run reports/research-quality/fixtures/reference-run.synthetic.json \
  --output research-score.json
```

`cases.synthetic.json` 是**外部、可信的标准参考**；
评测中的模型不得撰写或修改标准文件。一次运行包含：

```json
{
  "cases": [{
    "id": "mcp-diagnosis",
    "answer": "A grounded user-facing answer with direct markdown URL citations",
    "observedWebFetchUrls": ["https://primary.example.com/mcp/endpoint"],
    "elapsedMs": 24000,
    "promptTokens": 2400,
    "completionTokens": 1050
  }]
}
```

`observedWebFetchUrls` 必须来自持久化会话事件日志中
**真正成功的 web_fetch 工具回执**，而非 Kira 自称阅读过的网页。
评分脚本自身不访问模型或互联网，无法验证提交的 JSON
是否真实采集。实时测试期间必须由独立的轨迹验证器或审核者
保护这一证据边界。

## 建议的实时挑战：Phoenix 与对照系统使用相同任务

- **A. 快速时事事实（90 秒目标）：**查找指定官方指标的
  最新数值和发布日期。引用主管机构的*实际*公告，
  不能只使用搜索摘要。
- **B. 硕士水平认知神经科学（180 秒目标）：**比较
  某项特定干预最近两项合格实证论文，包括研究设计、
  样本量、效应、限制、DOI 和证据强度。
- **C. GitHub MCP 诊断（90 秒目标）：**将实际观察到的
  HTTP 响应或端点与推断的 OAuth 状态区分开；责怪凭证前，
  核实真实服务器 URL 和源代码。不得泄露秘密。
- **D. 互相矛盾的现行文件（120 秒目标）：**根据新版
  与旧版原始文档核实已更改的政策或产品规格，
  说明在*实际运行日期*哪一版有效。
- **E. 研究延续性（90 秒目标）：**首次任务后重复一项
  相关请求。核实是否能利用有效记忆，同时避免过期事实、
  重复幻觉和重复付费搜索。

每次实际挑战必须独立记录：模型与路由、真实日期、
从开始到最终回答的耗时、工具调用时间线、搜到并**实际打开**的
不同原始 URL、令牌、引文、缺失的必要事实、矛盾、
无依据陈述和面向用户的消息。每个案例独立运行两次，
以免挑选最佳结果。

## 宣称测得 10/10 之前的验收目标

独立验证的报告不得有虚构引文或重要无依据主张；
必须覆盖**用户要求的所有子问题**，区分可靠与初步发现，
直接引用原始来源并说明不确定性。目标为每个选定实际案例
审计分数至少 90/100，尽快给出有价值的首个发现，
无重复同一查询的循环，并在合理时间与令牌预算内完成。
自动评分不能取代对研究质量、来源可信性、因果解释
及临床风险的人类判断。

若提供商被禁用、屏蔽或返回零来源，应将访问标记为
**不可用**，而不能声称信息不存在。公共 HTML 搜索可能受到
速率限制；需要身份验证的来源仍须获得用户已有授权。
不得为提高评测分数而抓取个人数据或绕过权限。

## 在本地 Phoenix 安装上运行真实模型

该命令确实会使用当前本地账户配置的模型与提供商，
以 **headless** 模式为每个案例启动一次 Phoenix，
而非使用模拟助手。凭证不会进入报告，并强制只读权限，
不会改变用户现有的身份验证或源代码工作区。

```sh
node scripts/phoenix-research-live.mjs \
  --cases reports/research-quality/live-prompts.json \
  --case mcp-live \
  --output phoenix-research-live-result.json
```

省略 `--case mcp-live` 将运行全部预定案例，每个案例
都有自己的最长执行时间（最多四分钟）。脚本使用一次性、
相互隔离的 JSONL 会话存储，在提取访问来源回执与令牌数据后
删除存储。仅保留模型最终答复、公开来源的域名与路径 URL
（去除查询参数）、用时、令牌计数和工具调用次数。

若本地未安装 Phoenix 依赖或尚未完成模型授权，
运行将明确失败；CI 的合成基准**不能**代替真实运行。
如果模型适配器未输出令牌用量，数值为 `null`，
绝不伪造零消耗。发布实际评测结果之前必须检查
内容是否包含个人数据。

真实运行器返回**未评分**的 JSON 报告。若需要打分，
独立审核者必须在**不参考模型输出**的前提下创建
包含真实当代原始文本、核实事实、发布日期和矛盾检查的
标准证据文件，然后将其交给
`phoenix-research-benchmark.mjs --cases <independent-corpus> --run <live-report>`。
只有把相同问题分别运行两次，并与独立对照系统比较，
才能宣称 Phoenix 的研究能力达到或超过 ChatGPT。
