# Phoenix Comic Studio — coordinación de Kira

**Intención natural.** Ante «crea un cómic de…» o «continúa mi serie», detecta la necesidad y ejecuta el motor sin pedir nombres de scripts, archivos, modelos o parámetros técnicos. Reutiliza las capacidades universales de orquestación, generación de imágenes, almacenamiento, memoria y publicación. No impongas una historia predeterminada. Identifica la serie por su ID existente; no sobrescribas ni reinicies su canon durante una nueva conversación.

**Fuente de verdad:** `node scripts/phoenix-comic-studio.mjs help` y `docs/phoenix-comic-studio.md`. Comienza con `list`, `show` y `audit` para una serie existente. La memoria duradera está bajo `PHOENIX_COMICS_HOME` o `~/.dsh/comic-studio`, no en un chat ni en staging.

**Recuperación ante «sigue», timeout, Canva o JSON inválido — OBLIGATORIO:** ejecutar primero `node scripts/phoenix-comic-recovery.mjs status SERIE ENTREGA [workspace]`, usando el mismo proyecto y directorio persistente. Si hay un plan previo, conservarlo; si se conoce el número exacto de páginas interiores, crearlo una sola vez con `plan SERIE ENTREGA plan.json` (por ejemplo `{"interiorPages":4}`). Después de CADA llamada del generador, guardar la respuesta original recibida, sin transcribir IDs, en un JSON con `attemptId`, `slot`, `provider`, `response`, `workspace` y posible `error`, y ejecutar `record SERIE ENTREGA resultado.json`. Las respuestas no JSON y las que agotan tiempo se registran como evidencia no confirmada; un error no prueba que el fichero se perdió. `status` distingue `imported-verified`, `generated-needs-review`, `provider-id-only`, `malformed-json` y `missing`. Para arte realmente presente, comprobar continuidad y estética y solo entonces ejecutar `accept SERIE ENTREGA revision.json` con `slot`, `filePath`, `workspace` y, cuando proceda, `attemptId`. Si el estado refleja un archivo real candidato pero no aprobado, primero revisarlo, no regenerarlo. Nunca convertir `design_id` en `asset_id`, reconstruir IDs de Canva a mano, repetir sin límite un lookup rechazado ni afirmar que el resultado existe solo porque haya un enlace. Ante un proveedor bloqueado, consultar las capacidades realmente registradas; cambiar de proveedor solo si existe herramienta comprobada, guardando recibos y contexto. Cuando no hay ninguna capacidad de imagen operativa, informar el bloqueo y conservar el plan para reanudar sin empezar de cero. El motor de recuperación no genera imágenes ni abre MiniBrowser.

**Secuencia de trabajo obligatoria:** biblia del universo → personajes con firmas visuales y referencias frontal/perfil/tres cuartos → lugares → plan de entregas y páginas → brief visual `art-brief` → dibujo con la herramienta de imagen genuinamente disponible, condicionando por imágenes originales aprobadas → importación inmutable de cada ilustración → diálogos como capas editables → auditoría → exportación HTML/PDF/CBZ → revisión visual de cada página. Continuar del checkpoint si se interrumpe. Conservar las páginas y referencias ya revisadas; ante un fallo concreto reparar la viñeta específica.

**Formato editorial mínimo:** un cómic completo o demo incluye una portada realmente ilustrada, al menos una página interior secuencial y contraportada ilustrada. Genera arte específico para cubierta y contracubierta sin textos rasterizados cuando sea posible, impórtalo como `asset SERIE ID ruta`, y regístralo mediante `covers SERIE ENTREGA cubiertas.json` con `frontAsset`, `backAsset`, `tagline`, `backBlurb`, `credits` e `imprint`. El comando `render` no debe publicar ediciones no borrador sin ambas cubiertas. La portada, página interior y contraportada deben estar en ese orden en PDF, CBZ y visor del chat. Si no puede generar una cubierta, explicar el bloqueo real, sin simular cumplimiento.

**Dirección de páginas:** usar por defecto layouts cinematográficos no uniformes con siluetas irregulares, márgenes profesionales, lectura natural y ritmo narrativo; no tiras horizontales iguales. `page.layout.mode="auto"` selecciona composiciones distintas para 2-20 viñetas; `mode="freeform"` requiere `slots` por ID con coordenadas enteras de 0 a 1000 (`x,y,width,height`), `shape` (`slant-left`, `slant-right`, `trapezoid`, `angled-top`, `angled-bottom`, `circle`, `hexagon`, `burst`, `rectangle`) y `overlay:true` únicamente para insertos superpuestos intencionales. Añadir `sfx` a la viñeta cuando proceda. El motor valida límites y superposiciones; siempre revisar legibilidad de textos y relación causal entre viñetas.

**Calidad visual:** nunca resolver una petición de cómic final con cajas vacías, bocetos genéricos, imágenes de personajes incompatibles o el mismo retrato reutilizado sin cambios de acción. La referencia de identidad no equivale a una comprobación de likeness. Inspeccionar cambios de rostro, pelo, vestuario, accesorios, fondo, escala, manos, anatomía, transiciones, globo/lector y tipografía, comparando con la ficha aprobada. No declarar excelencia automática ni publicar un borrador como terminado. Los activos deben ser creaciones originales o tener licencia y procedencia.

**Memoria narrativa:** cada nueva viñeta registra cambios de heridas, objetos, localizaciones y relaciones mediante `changes` contra un estado anterior. Si aparece contradicción, investigar en el guion y corregirla, no forzar artificialmente el canon. Los personajes y lugares también pueden alimentar libros, animaciones, juegos Godot y productos comerciales, sin trasladar efectos particulares de cómics a todas las misiones Phoenix.

**Entrega en el chat — OBLIGATORIO:** ejecutar `render SERIE ENTREGA` sin abrir MiniBrowser, comprobar el recibo y llamar a la herramienta real `phoenix_comic` con `title`, `series_id` e `issue_id`. Publica un artefacto nativo con las páginas ilustradas, no abre otra pestaña ni la URL de Phoenix. Solo informar «publicado» si la herramienta devolvió `artifactId`, número de páginas y viñetas. Si no existen recursos de imagen auténticos, explicar el bloqueo, NO crear un cómic ficticio ni dar una URL vacía. Está prohibido abrir `127.0.0.1:3080` o `localhost` dentro del navegador para presentar un cómic. La previsualización queda en el chat; la exportación PDF/CBZ real cuando Chrome funciona es independiente. La tienda, anuncios o pagos exigen autorización y recibos verificables aparte. Entregar RESULTADO / EVIDENCIA / RIESGO / ESTADO con ubicaciones reales y pruebas ejecutadas.
