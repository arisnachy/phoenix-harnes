# Agent Note: 浏览器表单提交前验证自动补全选项已确认

Status: implemented

[English](2026-10-16-form-autocomplete-verified-before-submit.md) | 中文

## Problem

浏览器表单的自动补全输入框可能保留草稿文本，但没有真正确认任何已选标签。只检查输入值会产生虚假的成功，提交摘要中的该项仍为空。随后代理反复尝试键盘与鼠标、重复提交，并把大量模型回合浪费在进度播报上。

## Decision

结构化浏览器元素匹配同时使用 CSS 选择器与精确文本，因此可以区分建议按钮、具有相同文字的草稿输入框及其他控件。`verify_form` 可检查唯一可见非输入元素（如已经选中的自动补全标签）的预期文字。Kira Max 的正式指令要求在提交前验证已选择的标签，将无进展的不同修复尝试限制为两次，并禁止在收到提交摘要后自动再次提交。浏览器操作仍遵守原有权限检查。

## Alternatives considered

**相信自动补全输入框的值。** 输入框有内容并不能证明控件的已选选项状态已经改变。

**不断尝试键盘和鼠标直到摘要变化。** 无限重试可能点击到遮罩下的元素，导致重复提交并消耗模型请求。

**跳过自动补全测试。** 这只是回避差异，无法保证自动化结果完整且可验证。

## Consequences

表单代理可以用 CSS 与精确文本定位建议项，并验证已选择的标签而不是草稿文字。只要某个选项未确认，即使其他输入都通过验证，表单仍未完成。代理将在有限尝试后报告未完成字段，而不是反复提交。通用 DOM 验证无法证明不可访问的跨域或原生控件内部状态，这些情况仍须明确说明。实际网页耗时与模型是否遵循指令仍需现场验收。

## Testing

无需密钥的 DOM 测试创建带草稿的自动补全输入框、同文字按钮以及独立的已选标签。点击前的标签验证失败；结合选择器和文本的点击准确选择唯一按钮；点击后的标签验证成功。
