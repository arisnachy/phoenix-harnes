# Agent Note: 对话中的紧凑体育卡片

Status: implemented

[English](2026-11-01-compact-sports-conversation-cards.md) | 中文

## 问题

体育赛事、赛程和智能数据面板采用不同尺寸。单场比赛比多个赛程项目还大，并在聊天中重复展示大队徽、数据提供者名称、来源信息和次要细节。多项目赛程在窄屏上难以浏览。

## 决定

共享体育渲染器把单场比赛和智能面板限制为响应式的 420 像素宽卡片，队徽约 23–25 像素，并优先展示比分。赛程使用小型响应式赛事网格，不增加新页面或导航。场地、球员、研究资料、逐球事件和新闻链接仍可通过原生展开控件访问。

提供者身份继续保留在经过验证的数据、网络端点和内部动作中，但聊天界面使用中性的体育标签、更新时间和状态文字。这不改变数据准确性、许可责任或原始数据中的出处。

赔率和投注单也使用更紧凑的间距，同时保留区分研究结果与已被接受下注的风险提示。

## 备选方案

- **独立全屏赛事中心。** 需要额外导航，使问题与答案分离。
- **直接隐藏全部详情而不提供展开方式。** 能缩短卡片，却会丢失研究所需的信息。
- **为每个运动分别写布局。** 新增联赛后间距和无障碍行为容易分歧，不如共享渲染器稳定。

## 后果

初始界面优先显示球队、比分、状态和时间；详情可以按需展开。展开后卡片仍可自然增长。中性数据标签不改变赛事 ID、实时轮询、赔率验证或历史结果。

## 测试

体育富界面测试覆盖预览、原生展开以及中性显示。现有赛事中心和实时适配器测试继续验证轮询、取消及数据缺失处理。合并到 main 和 stable 前必须通过 CI。
