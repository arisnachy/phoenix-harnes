# Agent Note: 待办隐私与对话副本整洁性

Status: implemented

[English](2026-09-15-pending-work-privacy-transcript-hygiene.md) | 中文

## 问题

在人性化存在感改进之后，像“我还有什么待办？”这样的请求仍可能显得机械。模型可能先叙述自己“准备检查任务”，把局部查询夸大成全局完整结论，把无关的家庭/资料信息作为建议话题主动提出来，并用不必要的菜单式问题收尾。与此同时，Tools 折叠控件和 Phoenix 工作状态等短暂技术 UI 也可能污染普通的对话选择/复制，出现类似 `svgToolssvg` 的内容；这些 SVG 实际上属于界面而不是助手正文。

## 决策

人性化存在感契约现在把个人资料与记忆明确视为私有背景上下文：只有当个人或家庭信息与当前请求直接相关，或用户明确要求时，才可以提及。简单的状态、查询和审阅请求应先静默检索，再直接给结果，不要叙述检查过程。待办审阅必须在目标范围内检查所有可用且权威的未完成工作来源，对结果去重；除非该范围确实已完整覆盖，否则不得声称“没有其他待办”。如果覆盖范围有限，就自然说明这个范围。无关记忆不得被转化为建议话题或回答结尾的菜单。

已同意进入模型上下文的用户资料区块也携带同样的相关性边界，因此不能因为用户允许模型看到某条资料，就把它当成应该主动说出的内容。

短暂技术 UI 在 Phoenix 中仍然可见且可交互，但 Tools 折叠控件与运行中的回合状态被设为 `user-select: none`。它们是界面控制/状态而不是对话正文，因此普通的对话选择和复制会跳过它们，同时详细工具信息仍可通过专用 UI 查看。

## 验证

`packages/profile/user-profile/tests/user-profile.spec.ts` 固定验证私有记忆的相关性、状态请求结果优先、待办结论必须完整或明确限定范围，以及禁止把无关记忆变成菜单。`packages/client/ui-conversation/tests/technical-chrome-copy-isolation.client.spec.ts` 固定验证 Tools 折叠控件和 Phoenix 短暂状态不会进入普通复制选择。

## 影响

Phoenix 仍可在相关时使用个人上下文、计划任务、目标、任务使命、收件箱状态和项目/会话状态；本次修改改变的是相关性、范围声明和呈现方式，而不是删除能力。技术活动仍可在 UI 中检查，但普通复制时不再表现得像助手正文。
