# Agent Note：只在评审期间解析议题策略引用

Status: implemented

[English](2026-09-23-lazy-issue-policy-resolution.md) | 中文

## 问题

议题策略只适用于已请求人工评审或已有已提交评审的人类拉取请求。但工作流在检查此条件之前就解析了关联议题，因此尚未进入评审的拉取请求也可能因不属于当前策略范围的议题字段或 Project API 调用而失败。

## 决策

拉取请求快照先读取拉取请求、已请求的评审者和评审记录。当 `requiresPullRequestPolicy` 为 false 时，快照返回空的议题引用和空的议题映射，不调用议题或 Project 接口。开始评审后，工作流仍按原有方式解析并校验关联议题。拉取请求生命周期事件继续独立投影议题状态。

## 备选方案

**为每个拉取请求解析所有关联议题。** 不予采用，因为人工评审开始前策略尚未生效，而且这些额外调用可能在工作流到达现有策略判断之前失败。

**将议题字段或 Project API 故障视为空元数据。** 不予采用，因为策略生效时，这会掩盖真实的配置或 API 故障。

## 影响

尚未进入评审的拉取请求不再依赖关联议题字段或 Project 访问权限。首次请求评审或提交评审后，原有议题校验仍会运行，并报告其 API 故障。模拟 API 测试会验证策略未生效的路径不会请求议题或 GraphQL 接口。
