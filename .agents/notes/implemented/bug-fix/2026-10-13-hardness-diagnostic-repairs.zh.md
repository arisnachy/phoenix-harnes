# Agent Note: HARDNESS 邮箱恢复与资源契约

Status: implemented

[English](2026-10-13-hardness-diagnostic-repairs.md) | 中文

## Problem

用户提供的诊断复现了抽象游戏缺少资源来源要求、链式媒体播放的误拒绝、Devpost 安装输出显示内部连接器名称，以及显式邮箱恢复与较弱的启动注册合并。其他一些失败来自过时的测试数据和提示词字面预期，而不是缺少产品行为。

## Decision

显式邮箱恢复将共享注册请求升级为需要所有者恢复。受控状态屏障覆盖启动与显式调用重叠。Console 密钥迁移可以列出现有邮箱，但仍不能注册或创建另一个邮箱。权限失败保留结构化的 `message_send` 拒绝，同时传入邮件接收保持连接。

自动所有者查询期间提供的显式所有者，在查询完成后具有优先权。重置与释放在提供者 IO 前使延迟注册失效；清理失败仍使内部重置屏障完成，同时将原始错误传播给调用者。现有[所有者恢复](2026-10-06-agentmail-recovery-owner-repair.zh.md)与[注册回退](2026-10-06-agentmail-ensure-403-fallback.zh.md)决策仍有效；这些生命周期修复保留其提供者和凭据边界。

请求资源的抽象游戏在评审契约中包含现有清单与来源要求。音频验证器将链式 `.play()` 与具名声音助手分别识别，同时保留嵌入格式检查。精选连接器的批准、结果和展示使用可读名称，而不改变安装器 ID。主动性测试验证当前有界、已授权且不重复的策略，不为满足过时措辞而改写提示词。

## Alternatives considered

**削弱验收要求。** 删除来源或音频检查会掩盖缺失的成品证据。

**把每个失败测试都视为产品缺陷。** 禁止列出邮箱与复用现有邮箱矛盾；在异步赋值前读取预期 ID 也无法验证结果。

**在启动时重试提供者注册。** 不确定的提供者注册仍需要受治理的恢复和持久凭据。

## Consequences

修复保留权限边界、提供者身份和现有任务语义。本地测试证明修复后的契约与确定性交错，不证明真实 AgentMail 投递、浏览器可听性或完整游戏质量。原生语音与运行时加载修复具有独立证据。

## Verification

定向适配器测试覆盖报告中的失败。真实 Loader 评审场景对请求资源的抽象游戏实际模型请求建立快照，只替换外部评审模型。发布前须通过广泛 HARDNESS 测试和包类型检查；真实服务仍属于独立验证层级。
