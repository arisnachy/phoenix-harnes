# 人类化输出卫生

## 问题

对话模型，尤其是较小模型，可能把仅供模型使用的实现细节或与当前请求无关的个人记忆复制到普通的用户可见回复中。因此，一个能力询问也可能暴露内部指令文件名、工具方法名或不必要的隐私说明，即使回答用户根本不需要这些内容。

## 修复

Host 侧 HARDNESS adapter 现在会在 `llm/stream` seam 安装一个 response-hygiene interceptor。普通 session 回复会先缓冲到完整 text block，在任何可见文本发出之前完成清理，然后继续转发相同的非文本 chunk、tool call、usage 与 finish 信息。辅助模型调用和非 session 调用保持不变。

Sanitizer 使用最近一条直接来自用户的 prompt 来保留显式透明度。用户明确要求调试 Phoenix 内部机制时，可以显示实现细节；用户明确询问 memory 或个人上下文时，也可以讨论这些主题。否则会移除内部指令文件、hidden-prompt 术语、类似方法名的 tool 名称以及无关的私人上下文说明。对于简单能力问题，清理后只保留第一句真正有用的用户可见回答。

HARDNESS 面向模型的 protocol 也明确了同样的行为：memory 默认静默用于个性化；除非用户明确调试，否则实现细节保持内部；足够清晰且可执行的请求直接执行而不是制造不必要的澄清；回复使用面向人的能力语言，而不是 API 式叙述。

## 验证

回归覆盖包括最初的 Gmail 能力回复故障、必须保持不变的普通行动回复、显式 Phoenix 内部调试、显式个人 memory 问题，以及英语/西班牙语 protocol 断言。最初的回归测试已在 sanitizer 存在之前观察到失败；最终分支在推广前由仓库 build 与 CI gate 验证。
