# Agent Note：Kira 混合命令与命名空间操作后的验证证据

状态：已实现

[English](2026-11-22-kira-mutation-evidence-boundaries.md) | 中文

## 问题

完成质量 guard 只识别少数固定的修改操作名。GitHub 的合并、引用更新或其他带命名空间的写操作成功后，证据账本可能错误地保持已验证状态。若一次终端调用同时执行修改和测试，优先匹配测试命令也可能误把尚未独立核验的最终状态标记为已验证。

## 决策

规范化工具名称后识别修改操作族，而非只匹配具体文件操作。GitHub PR、引用及文件库写操作都计入修改。同一次 shell 调用同时包含修改与验证时，优先将其判为修改；另外识别常见 GitHub CLI 合并及 git push/tag 命令。保留原有基于 generation 的有界、低延迟纠正机制，不增加新的模型评审轮次。

## 局限

工具名称和命令文本匹配只是启发式判断，并非权威副作用元数据。新的工具类别仍可能需要由适配器声明写入效果。混合终端命令采取保守分类，即使最后一条子命令恰好是测试。质量 guard 不会独立执行测试，也不能保证外部提交成功或实际部署运行正常。

## 验证

回归测试覆盖 GitHub 带命名空间的写操作、文件库修改、混合修改与测试的终端调用，以及模拟成功合并 PR 后端到端的纠正提醒。Windows 实际启动、模型供应商调用和仓库完整 CI 仍是独立的发布门槛。
