# Agent Note: HARDNESS 验证回归

Status: implemented

[English](2026-10-01-hardness-validation-regressions.md) | 中文

## 问题

HARDNESS 验证混合了过时的策略预期、不完整的 agent 测试对象和产品缺陷。序列化的 shell 参数隐藏了字符串开头的命令；broker 向自定义市场 provider 转发未限制的蜡烛图数量；新建的遥测缓存可能在一毫秒内阻止首次探测。

简短社交引导还暴露了历史重建不一致：请求筛选历史，而不变量要求完整日志。现在每个相关步骤记录确定性的历史投影，请求构建和校验共用该投影。SDK 快照覆盖持久化策略，负向不变量测试继续拒绝缺失或篡改的消息。

## 决策

Shell 修改分类读取实际 command 参数。代码模式调用的嵌套工具仍通过自己的执行 hook 分类。模拟交易 broker 将请求数量和返回的蜡烛图数量限制为 1–1000。运行时遥测忽略初始缓存截止时间并执行首次探测，随后保留常规 TTL 和并发刷新行为。

测试使用完整的 agent 测试对象，并为授权遥测和浏览器位置过期使用受控时钟。策略快照保留现行快速模式和自动图像 provider 规则。错误断言区分 schema 层的非有限数字拒绝与 adapter 层的范围验证；可视化 schema 保留现有的可扩展对象契约。

## 考虑过的替代方案

为满足过时的字符串断言而修改产品 prompt 会逆转现行策略。在 shell 正则表达式中增加引号会将无关 JSON 元数据识别为命令。取消遥测缓存会增加重复的账户探测。因此拒绝这些方案。

## 影响

边界测试覆盖 provider 输出上限、带引号的资源路径、不产生修改的 shell 元数据、即时遥测刷新、TTL 复用和位置过期。这些更改不授予新的执行或连接权限。现有 mission 和 Loader 测试继续验证组装后的 HARDNESS 行为。
