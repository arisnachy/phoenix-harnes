# Agent Note: ChatGPT Web 在设置往返后保留默认模型

Status: implemented

[English](2026-08-31-chatgpt-web-empty-models.md) | 中文

## 问题

捆绑的 `chatgpt-web: {}` 路由是一个由 Phoenix 自己声明默认模型的本地桥接路由。设置加载器会把省略的 `models` 列表物化为空列表。Profile 解析器把这个物化值当作有意的空 catalog，因此 `resolveRouteModels` 拒绝该路由，整个 web profile 在模型选择器挂载前就失败了。

## 决策

只有 `chatgpt-web` 路由会把空的 `models` 列表当作省略，并恢复 `gpt-5.6-sol` 与 `gpt-5.6-luna`。非空列表仍会替换默认值。回归测试同时覆盖 `{}` 与 `{ models: [] }`，包 README 也记录了设置往返规则。

## 考虑过的替代方案

**在模型列表为空时移除该路由。** 否决，因为空列表是加载器对省略值的表示，不是用户要求停用桥接；移除它会让模型选择器在设置往返后消失。

**让通用 catalog 解析器接受空的手动声明路由。** 否决，因为没有模型的手动声明路由仍然无效；回退只属于拥有明确内置默认值的路由。

## 后果

Phoenix 可以使用设置界面持久化的路由启动，即使尚未查询 `/v1/models`，选择器也有稳定的本地桥接条目。桥接仍必须在配置的端点运行，请求才能成功；本修复只恢复配置加载，不声称桥接连通性。
