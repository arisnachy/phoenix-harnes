# Agent Note: 嵌套检查的锁所有权

Status: implemented

[English](2026-09-07-nested-gate-lock-ownership.md) | 中文

## Problem

消费者聚合任务在持有工作区锁时启动其他检查聚合任务。子任务重新获取该锁时会等待父任务，而父任务正在等待子任务，导致验证一直延迟到锁等待超时。

## Decision

锁创建、借用准入、所有者释放和过期恢复通过持久化本地 SQLite 互斥文件中的短 `BEGIN IMMEDIATE` 事务串行化。关闭连接会释放操作系统锁，进程死亡时也会释放。进程内 FIFO 防止获取轮询饿死释放操作。正常释放时不删除互斥文件，因为替换文件可能使并发进程使用不同的文件系统锁。

检查运行器将随机所有权令牌传给子进程。嵌套聚合任务会先以原子方式创建 `.phoenix-gates.lock.borrower-*` 租约，再确认继承的令牌仍指向当前工作区记录。借用句柄只删除自己的租约。恢复已退出的所有者时会删除已死亡的租约，但只要匹配的借用进程仍在运行就保留锁，因此孤儿子进程不会与新的聚合任务重叠。外层聚合任务会等待借用租约结束后再释放记录，聚合任务内部的执行顺序由调度器依赖图控制。

## Verification

工作区锁测试通过检查执行器启动真实子进程，验证子任务释放后仍保留父记录、拒绝其他工作区的令牌、排除独立聚合任务、替换已退出进程的所有权，并复现父进程崩溃而借用进程仍存活的情况。三个同步进程竞争恢复同一过期记录，并断言没有竞争者删除新的所有者记录。崩溃测试持有并等待每个子进程。调度器测试继续覆盖依赖关系和子进程失败，并验证令牌会传入子进程环境。

## Alternatives considered

- 在 CI 中禁用锁：允许独立命令修改相同的构建产物。
- 增加超时时间：延长父子任务死锁，无法解决问题。
- 信任继承的布尔标志：绕过工作区所有权，不检查当前记录。
- 只在记录中保留父进程 PID：父进程退出后，仍存活的孤儿借用进程可能与替代聚合任务重叠。
- 在无锁读取后删除过期记录：并发恢复者可能删除新所有者的记录。

## Consequences

嵌套检查共享聚合任务的所有权，而不是获得独立的修改权限。借用租约是锁旁边的临时文件，会在进程退出或释放时清理。令牌协调协作的本地构建进程；它不是针对能够读取工作区的进程的安全边界。现有的显式禁用锁功能保持不变。

互斥使用仓库存储测试已要求的 Node 内置 SQLite，不增加包依赖。它协调单主机上的本地工作区；同时运行不同版本的检查运行器或从外部删除互斥文件不在保证范围内。
