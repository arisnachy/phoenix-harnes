# Agent Note: 为 Phoenix 的全部任务限制工具链进度播报

Status: implemented

[English](2026-10-16-global-tool-progress-narration.md) | 中文

## Problem

在普通浏览器表单测试中，十三次浏览器调用总共花费约十秒，而模型处理花费超过四分钟，并在约二十个步骤间反复播报进度。这并非表单专属问题：全局系统提示要求每两三次工具调用播报一次，AgentLoop 也会在每一个无文本、仅工具的步骤后注入新的模型可见进度提醒。这两种行为都会把有效的工具执行链变成重复的模型对话。

## Decision

现在全局身份提示仅在出现重要发现、阻塞、计划变化或约二十秒没有可见进度时要求简洁更新，而非每几次工具调用就更新。具体 AgentLoop 会跟踪当前执行区间最近的可见进度；仅在仍需调用工具且有二十秒无可见进度时，注入一次可记录的提醒。模型输出实际可见进度后重置间隔。自动续行消息要求代理复用已验证成果并完成任务，而不是重启规划。Kira Max 的人格提示对任何领域的工作采用同样的通用规则，并明确要求在满足实际验收标准后停止续行。

## Alternatives considered

**彻底关闭进度更新。** 长时间运行的操作将对用户完全不透明，也更难解释真正的阻塞。

**只优化浏览器操作。** 测量中工具耗时仅占总时长的一小部分，而重复播报指令影响所有工具领域。

**为全部任务强制固定模型步数。** 正当的复杂工作无法使用统一计数限制而不损失完整性；现有的目标证据检查和工具预算仍保留各领域适用的权限。

## Consequences

简短的仅工具执行序列不再强制额外播报，也不会因此产生额外的对话历史 token。长时间无声工作仍收到偶尔的状态提醒。显式用户输入、工具授权、现有会话事件、目标完成检查以及验证语义保持不变。模型仍可能主动过多播报；此修改移除特定系统级诱因并统一 Kira 的指令，但不保证每个模型或任务都获得性能提升。

## Testing

聚焦的 AgentLoop 测试覆盖即时工具续行不产生提醒，以及二十秒判定阈值。TypeScript 与 Windows 构建检查在 GitHub CI 中执行；端到端模型延迟仍需在用户环境测量。
