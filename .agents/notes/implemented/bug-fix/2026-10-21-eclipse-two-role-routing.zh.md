# Agent Note: Eclipse 协调器和子代理路由

Status: implemented

[English](2026-10-21-eclipse-two-role-routing.md) | 中文

## Problem

用户需要一个 Kira 协调器模型与一个子代理模型，Eclipse 却分别提供规划器、协调器和专家选项。选择器混入其他提供方、隐藏已声明的推理等级并列出旧模型版本。配置错误可能阻止保存这些偏好。执行策略还会忽略任务难度而强制使用昂贵的推理。

缺失的嵌套设置对象被实例化为空对象，其必填路由字段随后在注册时验证失败。因此 Host 描述中缺少两个模型设置命名空间。可选对象现在使用显式 undefined 默认值，而存在的对象仍验证其必填字段。

## Decision

通过 Codex 账号目录提供两个模型及推理设置组。保留已公布的最新 GPT 代际及系列修订版本，同时保留账号可见的专用模型标识。将仅配置规划器的旧设置读取为协调器偏好，编辑器保存时清除过时的规划器及专家覆盖设置。已配置的协调器处理 Kira 的每个阶段；子代理组用于委派的工作者。显式推理等级优先。

自动推理使用现有请求文本和执行证据，不增加分类器请求。范围明确的操作使用 high，复杂工作使用 xhigh，特殊任务可使用 max。普通对话保留快速路径。仅在独立工作值得委派时，通过新上下文及限定任务启动子代理；委派本身不代表输出质量已经提高。

## Consequences

针对性路由测试覆盖所选模型、推理优先级、任务推理等级及子代理调度。组装后的浏览器场景通过合成目录、真实设置 RPC 和文件提供方检查两个设置组、支持的推理选项、保存及浏览器重载。这验证路由行为与持久化，不代表已测得 token 节省或提供方质量基准。

## Alternatives considered

仅隐藏规划器字段仍会保留其调度覆盖。硬编码模型菜单会过时，也可能公布不可用模型。为了选择另一个模型而先调用模型会增加成本和延迟。对每项操作强制 max 无法满足按任务分配预算的要求。
