# Agent Note：恢复 Kira Team 集成的发布检查

Status: implemented

[English](2026-10-04-team-release-gate-fixtures.md) | 中文

## 问题

Team 集成验证发现既有聊天和 Host 测试夹具没有提供当前投影、插槽、子代理选项或附件限制契约。未修改的仓库还超过重复率阈值，并在连接器与邮件代码中存在类型感知 lint 失败，阻止发布检查通过。

## 决策

更新相关测试夹具以验证当前契约，不削弱断言。在 `packages/attachment/attachment-local/src/store.ts` 中用一个私有发布方法共享两个附件发布路径，保留原子发布、失败清理和调用方取消语义。移除类型已证明冗余的连接器条件，通过所属对象调用注册表方法。在既有清理边界内等待邮件身份查询。保持 lint、覆盖率和重复率阈值不变。

vendor 重命名检查仅在既有 stores 和测试排除项之外，将 `packages/client/ui-layout/src/client/service.ts` 排除于上游 `cordis` 名称匹配：该字面量标识工作区占用者，并非导入的包。其他包引用仍接受检查。将 `apps/cli/src/superpowers.ts` 中的 `SuperpowersSkillRecord` 保持为模块内部接口，因为只有所属模块使用它；这会移除未使用的导出，不改变运行时行为。

高级 ACP 和 headless 回放夹具通过仅用于测试的定义适配器保留手动 Cordis 审批生命周期：适配器设置 `autoApprove: false`，并在释放时恢复原方法。两个回放配置均明确要求 Host 审批，仍使用真实的定义、激活和审批回执。主分支提交 `b075e3a33e` 修改了生产环境 `cordis_define` 和 `cordis_run` 的工具描述，因此更新这两项 ACP 请求头描述及其系统提示副本，以及对应的策略句子，以匹配当前文案；审批行为的预期输出保持不变。产品 headless 配置的预期输出还记录新增的持久化默认 `agent/model-selection` 事件，并调整三处源事件引用，同时保留工具往返行为和原有运行时上下文文本。其无密钥 CLI-mock 覆盖配置仅禁用无关的原生 `subagent-codex` 账户探测，使成功和模型失败断言无需真实账户配置即可保持确定性。

其余所属测试夹具区分指令、时间上下文消息与其他插件消息，固定不存在的项目标记，并检查稳定的身份开头，而非重复整段策略文字。pi-ai 夹具包含已注册的离线和免费提供方，显式声明实验性视觉模型，在验证请求协议前解压请求体，并为注册和释放测试模拟目录发现。Windows 运行时发现仍经过显式验证，自动配置则遵循实际主机平台。恢复现有 GenerativeUi 组件导入但缺失的样式表，使其所属测试可以加载；这不会新增界面集成。

## 考虑过的替代方案

**放宽阈值或跳过失败测试。** 这会隐藏既有发布失败并削弱集成证据。

**重新开展之前的连接器与邮件功能。** 这会超出已批准的 Team 范围；只需要机械性检查修复和准确的测试夹具。

结构化子代理还可能在记录最终答案后重新启动，因为后续被拒绝的调用添加了自动故障恢复输入。调度器屏障之间保留已结束状态，只在结束后抑制这种自动恢复；真实用户输入保持独立。既有结构化终止测试暴露该故障，相邻调度器测试验证普通恢复仍然可用。

## 后果

这些是限定范围的发布检查修复，不是重新开展之前的连接器或邮件功能工作。既有附件、连接器和邮件定向测试验证其行为；Team 与 Host 测试保留实际聊天、路由和投递断言。原始重复数量记录在 `/tmp/phoenix-orquesta-duplication-head.log`；抽取发布方法通过减少重复行修复问题，没有增加排除规则。
