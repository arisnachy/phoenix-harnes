# Agent Note：AgentMail 恢复与所有者修复

Status: implemented

[English](2026-10-06-agentmail-recovery-owner-repair.md) | 中文

## 问题

AgentMail 凭据被拒绝或所有者邮箱写错后，Kira 邮箱可能陷入无法恢复的状态。待验证状态的每次恢复都会再次走绑定所有者的注册流程，即使现有密钥仍然有效也会轮换密钥。服务商返回裸 `403` 时，Settings 可能不断重复恢复。恢复卡片只显示已保存的所有者邮箱，却不能修改，因此邮箱拼写错误会持续把验证码发送到错误地址。已验证邮箱在远端邮箱被删除后，也可能继续保存过期的 inbox id，即使 AgentMail 在凭据恢复时返回了有效的新邮箱。

## 决策

待验证状态现在优先调用 `POST /v0/agent/human`。这是 AgentMail 官方用于重新发送 OTP 和修复所有者的路径，不会在现有密钥有效时轮换密钥。如果该请求证明保存的凭据已失效，Phoenix 再回退到按所有者幂等注册来轮换凭据。已就绪邮箱通过轮换并验证凭据恢复，不再无故降级为待验证状态。

Settings 在待验证或结果不确定的恢复界面中提供所有者邮箱编辑。修改后会调用显式的所有者修复操作：对于仍可访问的未验证组织，Phoenix 通过 `/agent/human` 更新人类所有者；如果保存的密钥不可用或被拒绝，用户明确修改后的邮箱会启动新的绑定所有者注册，而不是继续使用错误地址循环。破坏性替换也会携带当前编辑后的所有者邮箱。

凭据恢复会验证本地保存的 inbox。如果该 inbox 已不存在，但 AgentMail 的幂等注册返回了由新凭据拥有的另一个 inbox，Phoenix 会验证并采用这个返回的 inbox，而不是继续卡在过期的本地 id。

## 影响

常见的过期密钥或裸 `403` 不再需要用户粘贴 API key。重新发送 OTP 不再产生不必要的密钥轮换，所有者邮箱拼写错误在可能时可以原地修复，过期的本地 inbox id 也可以自动自愈。服务商的验证与配额限制仍然保持明确；Phoenix 不会绕过 AgentMail 验证，也不会请求付费升级。

## 测试

定向 onboarding 测试覆盖：不轮换密钥的 OTP 重发、所有者邮箱修复、裸 `403` 回退、结果不确定注册后的邮箱纠正，以及过期 inbox 的自动采用。Settings 测试覆盖编辑错误所有者邮箱并发起修复操作。
