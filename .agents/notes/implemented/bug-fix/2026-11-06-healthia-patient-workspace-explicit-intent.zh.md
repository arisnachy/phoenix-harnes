# Agent Note：HealthIA 患者工作区需明确意图

Status: implemented

[English](2026-11-06-healthia-patient-workspace-explicit-intent.md) | 中文

## Problem

医学学术病例曾触发 PHOENIX 调用全局 HealthIA 激活工具；该工具返回所有会话患者档案，而聊天渲染器将激活误认为需要显示患者登记界面。同一研究流程也可能将超长问题传给 500 字符限制的规划器，并在开始搜索前失败。

## Decision

将医学研究和模拟病例保留在 PHOENIX Research APEX 中，不激活患者记录工具。全局 HealthIA 激活不再返回患者列表或界面协议。患者列表读取只用于不可见的后台元数据；只有在用户要求档案操作时，显式 `health_patient_workspace` 工具才能显示患者管理界面。保留第一方患者创建确认与有界纵向快照。对于超长的研究问题，将其压缩为包含主题和标识符的搜索查询，而原始用户请求仍留在对话中。

## Alternatives considered

**在聊天中隐藏所有 HealthIA 结果：** 不采用，因为用户明确创建或打开的患者档案必须仍可访问。

**激活后总是显示登记界面：** 不采用，因为激活只是开放工具，并不能证明用户想操作患者记录。

**不缩短查询而直接提高规划器限制：** 不采用，因为无限增长的搜索文本会降低来源匹配度和性能。

## Consequences

学术临床问题不会再把后台激活回执变成患者登记界面。显式患者浏览需要专门的工具调用，而来源研究仍遵守现有 500 字符规划器约束。模型仍可能选择不必要的激活工具；提示词已防止这种选择，但 UI 不再将激活视为记录操作意图。

## Verification

单元测试覆盖不含患者元数据的激活、显式患者工作区、伪造的 UI 回执和超长临床问题。宣布发布就绪前，仍需观察 CI、来源集成与客户端渲染检查。
