# Agent Note: 客户端启动重叠预取与入口创建

Status: implemented

[English](2026-10-12-overlap-client-boot-prefetch.md) | 中文

## Problem

浏览器启动立即层预取后，要等它完成才创建完整插件图。真实浏览器追踪显示后续 bundle 在第二波 HTTP 请求中才开始。单个服务器请求快，并不能证明界面很快可用。

## Decision

客户端启动在立即层预取仍运行时开始创建入口。现有模块到达注册表对重叠请求去重，依赖导入保留原有顺序。启动等待两项操作后才检查 Loader 静止和激活状态。失败报告、全部 ACTIVE 审计以及单次渲染器挂载仍然有效。

[客户端插件加载模型](../architecture/2026-07-23-client-plugin-loading-model.zh.md)和 [Web 客户端架构](../architecture/2026-07-19-gui-web-client-architecture.zh.md)仍保持有效：此变更只重叠下载，不改变模块身份、服务注入、两阶段启动职责或渲染器所有权。

## Alternatives considered

**在服务器缓存所有 bundle。** 后续测量发现服务器 CPU 间歇性升高，连很小的 manifest 都有首字节延迟。测量未证明文件读取是原因；bundle 缓存也不能解决已经证实的调度等待。

**在插件稳定前渲染。** 部分激活会掩盖缺失服务，并改变现有启动保证。

**删除立即预取。** 现有预加载优先级可以与入口导入重叠，无需删除。

## Consequences

依赖 bundle 可以更早开始到达，同时不重复实例化。此变更不消除 HTML 传输延迟、提供者推理时间或原生语音等待最终结果的时间。浏览器追踪能识别调度等待，只有受控前后测量才能量化加速。

## Verification

启动测试必须在预取未完成时观察入口创建，保留失败处理，并证明应用在操作稳定后挂载。构建后的应用烟雾测试提供 Loader 与渲染器组合证据。实时测量使用隔离浏览器，不中断用户活动会话。
