# Agent Note: 浏览器填写表单时复用 CDP 连接

Status: implemented

[English](2026-10-16-browser-form-transport-overhead.md) | 中文

## Problem

Chrome 连接器过去针对每次 DOM 操作、截图和验证都重新建立 DevTools WebSocket。MiniBrowser 在填写表单时也频繁刷新 JPEG 预览，而共享的 DOM 批次可能保留被前一个字段事件替换的控件引用。

## Decision

`CdpConnectionPool` 按标签页复用 DevTools 连接，用命令 ID 匹配并发响应，在每条连接上只配置一次视口，关闭空闲连接，并在断开时拒绝未完成的请求。批量填写仅在目标缺失或已脱离页面时刷新共享 DOM 控件列表。MiniBrowser 展开时每三秒、普通模式每四秒更新一次 JPEG 预览；隐藏页面仍暂停截图。

## Alternatives considered

**每次操作都重新连接。** 虽然命令隔离，但重复建立连接、配置视口并增加截图竞争的开销。

**每个字段都重新扫描整个 DOM。** 虽然不会保留旧引用，但重新引入了批量操作原本要避免的重复文档遍历。

**完全关闭预览。** 虽然可减少截图开销，但用户无法在聊天中观察浏览器实时操作。

## Consequences

结构化的 `fill_form` 和 `verify_form` 仍可在单次调用中处理最多三十个控件，无需模拟逐字鼠标操作或自动截图。如果先前的输入替换了表单部分，后续动态控件仍可被找到。浏览器操作仍需明确授权，且模糊选择器、隐藏与禁用字段、密码验证和文件上传的限制不变。预览画面可能比实时页面慢几秒，代理必须使用 DOM 验证而不是预览画面确认填写成功。

## Testing

CDP 连接池具有聚焦测试，覆盖连接复用、视口只初始化一次、命令错误和关闭标签页后的重连。浏览器交互测试覆盖批次中同步替换字段的场景。实际加速效果仍需在 Windows 的真实 Chrome 环境中测量。
