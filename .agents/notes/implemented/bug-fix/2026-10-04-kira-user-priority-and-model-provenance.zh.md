# Agent Note: Kira 用户优先级与实际模型来源

Status: implemented

[English](2026-10-04-kira-user-priority-and-model-provenance.md) | 中文

## 问题

用户向忙碌的队友提问时，需要得到答复，同时避免中止当前操作或丢失原有任务。对话答复不同于操作任务已经完成的证据。Kira 还需要保留固定视觉身份，并展示每次输出实际来自哪个模型；选择器中的路由名称不能证明模型身份。

## 决策

已接受的 Team 用户请求在下一个安全的 Step 边界进入目标子 agent（智能体）。子 agent 回答用户，然后继续原有任务，除非用户明确更改或取消任务。`team_chat_answer` 为已接受的对话请求发布受限、幂等的答复，不会完成任务。操作请求及肯定的操作完成声明必须具有匹配的执行证据。反应仍然可选，不能替代执行。

现有[主对话所有权](../feature/2026-10-01-kira-main-chat.zh.md)继续负责持久化参与者、公开输出、投递回执和反应。本记录负责更具体的安全边界及对话答复规则。

Kira 保留固定头像。旁边的小标记表示实际输出来源：Sol 使用太阳，Luna 使用月亮，Astra 使用星星，其他模型使用闪电，无障碍标签和提示显示确切的 provider/model。客户端对已完成输出使用持久化 `assistant/message` 的来源。流式输出使用附属于所属 Step 的已准备 `request/header` 配置；重试可以替换配置，未变化的路由会延续到下一个 Step。缺少证据时不显示标记。更改选中的路由不会改写历史消息的模型标记。

Conversation Definition 的 `match(event, location)` 可通过第二个可选参数接收引擎分配的不可变 Location。请求模型 Definition 为每个 Step 使用一个 Context，因此重试中的多个 header 更新同一个 Location-data 所有者。仅接收事件的现有匹配实现仍然有效；输出来源不依赖全局选中模型状态。

## 考虑过的替代方案

**每次提问都立即中断子 agent。** 这可能在操作回执产生前中止进行中的操作。安全边界保留当前操作，同时在进一步自主工作之前接纳用户请求。

**子 agent 回答时就完成任务。** 对话确认无法证明原始任务或新的操作请求已经完成。答复发布与执行证据保持独立。

**为所有头像使用当前选中的模型或路由名称。** 选择器记录路由意图，而非实际执行各请求的模型；将其应用到旧消息会伪造来源。头像保持稳定，标记依据实际的逐输出事实。

**每个 header 发布一个请求模型 Context。** 同一 Step 中的多个重试 header 会争用同一个 Location-data key。每个 Step 的单一 Context 允许更新，避免所有权冲突或可变的全局记录。

## 影响

用户对 Team 的干预保留进行中的工作，并与已接受的投递保持持久关联。显式答复不会解除操作证据要求。模型身份显示在 Kira 旁边，不替换头像，也不暴露凭据。引擎新增的 Location 参数让现有 Definition 能够关联不携带 turn/step 标识的事件，同时保留历史分页和引用稳定性。

## 验证

Team 服务及工具测试固定已接受请求的权限、安全边界投递、对话答复幂等性、缺少证据时拒绝操作答复，以及可选反应。客户端 assembler 和作者测试固定 Sol/Luna/Astra/其他模型标记、缺少来源、同一 Step 的重试 header 变更、未变化路由的延续、最终来源优先级，以及后续 header 和历史回放/前插后的身份。修正过时的 fixture 输入和 disclosure/生命周期假设后，更广泛的 chat-view 测试全部 64 项通过，并保留持久消息交接、slot 所有权和 Turn 操作断言。非 Codex 提供商即使模型 ID 包含 Codex 家族名，也保留其他提供商标记。用户反应行不继承移动端头像缩进。
