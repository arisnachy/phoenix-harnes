# Agent Note: 有界 MiniBrowser 恢复与精确浏览器目标

Status: implemented

[English](2026-10-16-bounded-minibrowser-recovery.md) | 中文

## Problem

挂起的预览请求会阻止后续所有画面加载。重复发现标签页、写入描述文件与建立 WebSocket 会与浏览器任务争用资源。显式指定的标签页消失后，Chrome 连接器可能转向无关页面，导致继续检查和重试错误的应用。

## Decision

MiniBrowser 为 HTTP 请求及其响应体读取设置统一时限，并在卡片失活时取消请求。它保留最后一张有效图片，并在用户操作完成后立即刷新。启动浏览器具有单独时限；结果不明确的超时不会触发反复自动启动。隐藏的会话暂停轮询和截图。FIFO 队列保留快速连续的用户操作；任何操作失败时停止依赖它的排队操作，不会在状态不确定时继续重放。

Web bundle 按目标复用 CDP 连接，匹配并发命令，共享同时进行的截图，并在每次状态读取中仅列出一次标签页。共享浏览器描述文件只在内容变化时写入；读取显式指定的预览不会改变全局所选标签页。操作超时及 HTTP 连接断开会取消未完成的 CDP 命令，阻止后续修改步骤。Chrome 连接器关闭故障连接，并拒绝不存在的显式目标。等待文本时只读取页面文字，不收集表单控件。序列化 DOM 操作提供自己的编译器命名辅助函数，使源码和构建启动器都能在全新页面上下文中执行。这些修改扩展了现有的[表单传输决策](2026-10-16-browser-form-transport-overhead.zh.md)。

## Alternatives considered

**提高轮询频率。** 这会增加截图流量，却仍不能解决未完成请求永久阻塞预览的问题。

**自动重复超时操作。** 没有收到响应不能证明浏览器修改失败；重放可能重复操作或改变错误页面。

**合并桌面 WebView2 与隔离 Chromium 配置文件。** 这会改变 cookies、隔离和权限归属，而修复预览并不需要这种变化。桌面控制保留经过身份验证的原生通道；浏览器预览与浏览器工具共享所选 CDP 目标。

## Consequences

短暂的预览故障保留最后一张图片，但不会将它视为最新验证结果。显式目标不可用时需要重新选择，不会静默使用其他标签页。本地 HTTP 应用仍可通过共享浏览器访问，浏览器 DOM 工具直接验证其结果。原生 Computer 验证必须通过可信 Host 进程运行；独立测试进程会被桌面代理拒绝。
