# Agent Note：临床影像先读证据、后生成解释性插图

状态：已实现

[English](2026-11-07-evidence-first-clinical-vision.md) | 中文

## 问题

用户上传放射影像或诊断报告并要求解释具体发现时，PHOENIX 可能先生成泛化的人体解剖图。纯文本模型若未启用视觉回退便无法看到图像，即使图像可访问，也未充分优先读取源文件的可见发现及报告中已有的诊断。

## 决策

在 Web API 网关启用现有的视觉回退路径。原始图像继续存储在持久附件库中；视觉模型先提取可见发现、报告原文、书面诊断及局限，再将文字交给纯文本模型。若没有可用的视觉模型，保持拒绝无依据解读。强化临床视觉基础指令和图像生成指引：先解释实际来源，区分报告已记载的诊断与独立、初步的推测，再制作仅由证据支持的示意图。

## 局限

低分辨率截图不能排除疾病，也不能代替原始放射影像或 DICOM。单张投影无法确定患者专属的三维几何结构。概念性三维解说必须标注为示意；原有研究用途 CT/MR 重建流程另行处理。本变更不声称提供已验证的自动诊断、通用 PDF 解析或新的专科影像模型。

## 验证

API 代理回归测试检查真实视觉旁路调用、原图引用、用户问题上下文、证据优先指令和持久消息传递；图像生成单测检查来源依据要求。真实放射诊断准确率、多页 PDF 及部署层模型覆盖验证不在无密钥测试范围内。
