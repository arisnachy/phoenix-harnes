# Agent Note: 设置资料 hydration 与响应式导航

Status: implemented

## Problem

资料表单可能在构造后才收到第一份持久化设置快照；旧逻辑先把该快照设为比较来源，再把仍为空的草稿误判成用户本地修改，因此宿主已经保存的数据重新打开时仍显示为空。设置外壳还为「资料」与「连接器」使用通用图标，并在切换可能较重的分区时承担全屏 backdrop blur 的合成成本。

## Decision

资料控制器在接受新的宿主快照之前，先相对上一份宿主快照判断本地草稿是否真正 dirty。干净表单采用新的持久化值；正在编辑的表单保留本地草稿。设置导航把「资料」映射为人物轮廓，把「连接器」映射为专用插头图标。分区正文使用 deferred active id，使导航选中状态可以先于较重的目标内容更新；模态遮罩保留原有暗化效果，但不再使用 backdrop blur。

## Alternatives considered

**让每一份传入资料快照都覆盖表单。** 这样能修复重新打开的问题，但后台设置刷新会清掉用户正在输入的内容。

**继续使用通用设置或个性化图标。** 这可以避免新增 primitive，但两个高频入口仍然难以区分，也不符合产品期望的图标语义。

**保留 backdrop blur，只增加 CSS transition 提示。** transition 提示无法消除全屏合成器工作；设置遮罩无需模糊也能维持焦点层级。

## Consequences

持久化资料现在会在首次 hydration 时重新显示，后续宿主刷新也不会覆盖真实的本地编辑。「资料」与「连接器」在导航中可以直接辨认。设置分区的功能行为不变，但较重的正文工作会在紧急导航状态之后调度，同时遮罩不再触发全窗口模糊重绘。
