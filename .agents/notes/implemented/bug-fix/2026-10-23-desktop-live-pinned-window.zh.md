# Agent Note: Desktop Live 固定窗口预览

Status: implemented

[English](2026-10-23-desktop-live-pinned-window.md) | 中文

## Problem

在仅通过 `pnpm phoenix` 启动浏览器界面的会话中，Desktop Live 展示的是上一次 Computer 操作之后保存的一张 PNG，而不是实时窗口画面。聊天界面可能在 90 秒内反复展示该图片，并在浏览器标签页隐藏时停止轮询。如果没有指定窗口，Windows 原生截图会跟随前台应用，因此用户切换到 Chrome 或 Phoenix 时，Paint 画面会变成聊天界面的递归截图。即使驱动已识别目标 HWND，操作后的截图也可能仍然截取整个桌面。

## Decision

**Phoenix Web** 增加由用户明确点击的 `Compartir ventana en directo` 操作，调用浏览器原生 `getDisplayMedia` 选择器。仅接受 `displaySurface === 'window'`，立即停止整个屏幕或浏览器标签页的共享，不将其误标为应用视频。录制必须由用户主动操作授权。用户切换会话、停用该视图、通过浏览器结束共享或点击停止后，视频流立即结束。视频只显示在当前聊天界面，不上传到 Desktop Live 路由，也不作为模型输入。原有经验证、按会话归属的 Computer 截图仍然可以使用，并明确标为 `captura reciente`，而不是视频。桌面状态轮询不再依赖浏览器标签页是否处于前台。

**Phoenix.exe** 将 `PrintWindow` 截图固定到所选顶层窗口的 HWND 和 PID，不再动态追踪当前前台应用。新会话接管时清除先前的窗口选择器；窗口关闭、最小化或句柄被替换时，不会静默切换到其他有焦点的应用。原生预览每 500 毫秒获取一张新截图，并非编码的视频流。明确的 `computer focus(target)` 提供应用选择器。没有新增输入注入接口或跨会话截图路由。

**Computer 验证**使用以代理会话内存对象为键的 WeakMap 保存最近确认的 HWND。后续没有新选择器的截图及输入操作继续使用该应用；`windows` 仍列出全局窗口，明确的 `focus` 则切换目标。截图采用针对目标应用的 `PrintWindow`，而不是对操作后碰巧位于前台的其他窗口截图。裁剪截图说明明确区分窗口局部图像坐标与 `computer windows` 返回的绝对桌面坐标；鼠标输入仍要求后者。Windows 前台输入保护仍拒绝向错误的窗口发送按键或点击。旧版 Desktop.exe 截图回退仅保留给未指定目标的观察操作。

## Alternatives considered

**持续录制整个桌面。** 不采用：切换焦点时可能暴露无关窗口，并递归录入 Phoenix 聊天界面。

**为每一帧或输入强制重新激活目标窗口。** 不采用：会抢夺用户焦点，并增加键盘或鼠标输入落到错误应用的风险。

**自动给予所有代理浏览器共享权限。** 不采用：浏览器捕获必须由用户明确授权，不能静默绕过浏览器隐私控制。

## Consequences

用户可以在 Phoenix Web 中持续看到自己明确共享的应用窗口，而原生预览即使在聊天界面获得焦点时也继续观察相同的 HWND。应用关闭或最小化时，界面报告无法捕获，而不会将旧图片伪装成实时画面。窗口共享需要用户授权，不等于获得独立的桌面控制权限。部分最小化、受 DRM 保护、特权运行或 GPU 加速的窗口无法通过 `PrintWindow` 捕获。Windows 后台输入仍受到已有的安全前台焦点检查；本次修改没有新增后台键鼠执行器。

## Testing

单元测试覆盖拒绝整个屏幕与标签页来源、会话固定目标以及窗口局部坐标提示。Desktop Live 原生 Windows 合约与聊天界面测试覆盖了变更的功能。要完整验证端到端交互流程，仍需在真实 Windows Paint 会话中进行人工测试。
