# Agent Note: 共享加载与结束处理

Status: implemented

[English](2026-09-08-shared-loading-and-settlement.md) | 中文

## 问题

账本加载、仓库文本扫描、锁身份解析和运行时结束处理存在重复实现，可能在故障处理上产生分歧。

## 决策

两个记忆账本共享按顺序处理的 JSONL 读取器。它保留物理行号、文件缺失时的行为、解析错误原因，以及后续无效行之前已应用的记录。各账本仍负责验证。仓库扫描器共享已跟踪文本枚举，包括符号链接文本、二进制排除和缺失文件处理。门锁共享身份解析，同时保留所有者专属验证。

Python 和工作线程提供者共享活动运行快照的结束处理。各提供者先拒绝新运行，再结束现有运行并等待完成。使用快照可防止回调修改活动集合时遗漏运行。

## 考虑过的替代方案

先解析全部行再应用记录会改变损坏账本的恢复行为。结束处理期间直接遍历活动集合会让回调跳过其他运行。忽略重复报告会保留这些规则的独立副本。因此拒绝这些方案。

## 验证

针对性测试覆盖无效 JSON、物理行号、部分应用、缺失文件、验证错误、已跟踪文件过滤、锁所有权以及集合变更期间的结束处理。提供者子进程测试独立于共享辅助函数，验证执行和释放。

## 后果

辅助函数集中现有行为，但不合并账本验证或提供者进程管理。除辅助函数测试外，仍须进行真实提供者和仓库检查。
