# Agent Note：增加有界认知运行时投影

Status: implemented

[English](2026-09-12-cognitive-runtime-foundation.md) | 中文

## 问题

PHOENIX 已经记录会话事件并派生带有来源信息的认知记录，但消费者仍需要一个确定性的进程内视图，在有界工作记忆分区中表示最相关的内容。该视图不能成为第二个持久化记忆权威，也不能获得执行权限。

## 决策

`@phoenix-ai/dsh-cognitive-runtime` 消费 `@phoenix-ai/dsh-session-learning` 所拥有的准确会话投影，并通过确定性的注意力分数派生包含 `focus`、`active`、`background` 和 `suppressed` 分区的 `CognitiveState`。原始会话事件日志仍是规范来源，学习日志仍拥有认知记录；运行时只保存脱离引用的进程内快照。

基础组合在 `session-learning` 之后挂载一个 `cognitive-runtime` 行，并使用明确的有界配置：最多 64 个候选、8 条活动区记录、16 条后台区记录，以及重要性、置信度、新近度、紧迫性、目标相关性和新颖性的单位权重。配置校验将每个候选和分区预算限制为最多 128，并拒绝非有限或负的权重。

运行时在启动时重建所有活动会话，并在持久会话事件之后刷新。它忽略 assistant 流式分块和明确标记为可忽略的事件，串行化刷新，在刷新失败后保留上一次成功快照，并在会话释放时删除状态。排名使用持久化记录时间戳和稳定的事件／来源顺序；它不读取当前墙上时钟、不使用随机数、不调用 LLM，也不添加持久事件类型。

`suppressed` 是预算分区，不是安全抑制。运行时不宣称具有意识、感知能力、与人等同或主观体验，也不改变提示、工具、权限、审批、凭据、目标或 agent-loop 控制。未来的模型、界面或操作消费者需要各自明确的契约和安全评审。

## 结果

消费者可以检查稳定的会话状态，而无需自行重建日志，同时重放和启动重建仍保持确定性。失败保留机制防止暂时的读取失败擦除最后已知的投影。由于规范事件日志和学习日志仍是持久化权威，进程内快照可以丢弃并重新构建。

第一阶段不会推断新的语义记忆、学习技能、运行实验、提供模型上下文消费者或浏览器面板。这些能力仍是独立工作，并且必须保留事件记录、来源信息和权限所有权。

## 考虑过的替代方案

**用 `CognitiveState` 替换会话日志或学习日志**被否决，因为派生投影必须可以重建，不能成为事件或记忆记录的唯一副本。

**让运行时改变目标、权限、工具或提示**被否决，因为这些权威已经有明确的交互、审批和循环契约；只读投影使认知排序与授权保持分离。

**使用环境时间、随机数或 LLM 排名**被否决，因为可重放的启动和事件刷新要求相同的持久化输入在未来消费者应用任何模型特定解释之前产生相同状态。

## 验证

纯注意力和工作记忆投影的聚焦测试达到语句、分支、函数和行 100% 覆盖率。服务、不变量和组合包测试覆盖启动重建、持久事件刷新、可忽略事件、失败保留、队列恢复、有界配置、分区不变量和基础排序。`verify-cordis-config` 验证仓库的 Cordis 配置文件，并且该包已加入 Host TypeScript 聚合。
