# Agent Note: Codex 运行时模型自动发现

Status: implemented

[English](2026-09-16-codex-runtime-model-autodiscovery.md) | 中文

## 问题

Phoenix 已经通过 `codex app-server` 和 `model/list` 支持按账户发现 Codex 模型，但此前只有“模型”设置里的发现界面使用这条能力。运行时模型枚举和精确模型解析仍依赖已安装的 pi-ai 目录或显式设置，因此一个刚对已登录 Codex 账户开放的模型可能已经存在于 Codex 中，却仍无法被 Phoenix 使用，直到代码或配置随后更新。

## 决策

`openai-codex` 适配器现在会在运行时叠加账户可见的 Codex 模型目录。Phoenix 在列出 Codex 模型时，以及精确的 Codex 模型 id 不存在于不可变配置快照中时，都会调用现有的 Codex app-server 发现通道。新出现的模型会沿用该路由现有的 Codex 传输与兼容性骨架，而它的 id、显示名称和已公布的推理能力来自实时、按账户范围返回的模型目录。

成功的发现结果缓存 15 秒。模型选择器重复渲染以及相邻的解析调用会复用该目录，而不会反复启动 Codex app-server。已有一次成功读取后，如果后续刷新失败，则继续使用最近一次有效目录；在首次成功读取之前，如果实时发现失败，模型列表会退回已安装目录，避免本地 CLI 的暂时故障把选择器清空。

实时发现发生在调用准备之前。随后解析出的模型描述符会与请求的不可变快照一起固定，因此目录刷新不会在一次回复进行到一半时切换模型。

## 曾考虑的替代方案

**每秒轮询 `codex debug models`** — 未采用，因为即使没有人在使用模型选择器，也会持续创建 CLI 进程。按需发现配合短缓存既能获得新鲜的账户状态，又不会把 Phoenix 变成持续轮询循环。

**硬编码新观察到的 Codex 模型 id** — 未采用，因为每次模型发布都需要再发一个 Phoenix 版本，而且列表仍会与账户实际可见的 Codex 目录逐渐偏离。

**让实时发现继续只存在于设置界面** — 未采用，因为能在设置中看到模型、却无法在运行时解析和执行它，并没有解决原来的缺口。

## 后果

Phoenix 可以展示并使用刚发布或刚对账户开放的 Codex 模型，而无需把模型 id 写入设置，也无需等待一个专门写入该名称的 Phoenix 代码版本。已有的内置 Codex 条目继续保留其权威的容量与兼容性元数据；真正新的 id 则继承 Codex 传输骨架，并对 `model/list` 尚未提供的字段采用路由回退值。未来出现的推理标签不会被盲目发送：Phoenix 只映射 pi-ai 当前能够实际分派的 effort id。回归测试固定了自动列出、立即运行和缓存复用这三项行为。
