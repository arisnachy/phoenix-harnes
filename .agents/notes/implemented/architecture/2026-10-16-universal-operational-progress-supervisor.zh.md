# Agent Note：通用执行进度防护

Status: implemented

[English](2026-10-16-universal-operational-progress-supervisor.md) | 中文

## Problem

Goal 驱动器原本只衡量完成门槛的变化，因此即使连续多轮只输出助手文字或重复同样的工具请求，没有任何持久进展，系统仍会无限修订执行窗口。新的 Sol 策略或专家重复检查，即便缺乏新证据，也会被误认为前进。大型 HTML 发布在没有直接文件输入契约时也暴露出相同循环。

## Decision

在修订与重启之间跟踪真正的目标工作凭证：独特且成功的工具调用（由稳定的工具与参数组合确定，而不是调用 ID）、新完成的清单或团队项目，以及独立验证的完成条件。口头计划、新回合或重复读取都不算进展。停滞两轮后优先使用其他已授权工具；停滞三轮后采用最小可执行修复。如果完整完成五轮却没有新增证据，则必须**阻断而非标记完成**，并说明缺少什么。获得真人授权的继续操作可重置防护。不引入新的预算选择器、审阅者、队友或外部副作用。

模型延续机制以及两套发布中的 Kira 人格均明确避免重复检查，也避免通过切碎的模型文本搬运大型作品。现有完成门槛、用户明确取消、配额阻断和并行团队数量限制仍具有最终效力。

## Verification

纯进度账本回归测试覆盖只有助手消息的回合、新读取、相同工具与参数重复调用、成功编辑。Host 集成测试验证连续五轮只有助手输出时，会持久写入 `no-progress` 阻断，而不是继续循环。部署前仍需验证运行时构建及真实 Windows 任务。

## Consequences

停滞的 Goal 会带证据地阻断，而不是被误报为完成；取消操作和配额限制仍然有效。

## Alternatives considered

拒绝把叙述的计划、新回合 ID 和重复检查视为真实进度，否则停滞任务可能无限循环。
