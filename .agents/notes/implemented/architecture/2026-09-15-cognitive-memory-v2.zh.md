# Agent Note: Cognitive Memory v2

Status: implemented

## Problem

PHOENIX 已经能够持久化会话事件和可复用经验，但自动召回主要为当前项目的程序性指导优化，而不是为重建工作历史设计。因此，新会话可以记住“先验证工作目录”这样的纠正，却仍可能无法根据证据回答跨项目的“昨天做了什么？”之类问题。

## Decision

`@phoenix-ai/dsh-session-learning` 继续作为规范的持久认知存储。普通认知搜索默认限制在当前项目，只有定向自传式检索才能显式启用 `includeCrossProject`，因此更广的历史问题不会削弱普通项目隔离。

`@phoenix-ai/dsh-tool-session-learning` 从可观察的会话工作记录有界任务情景。情景保留用户任务、项目、时间戳、公开工具名称、终止结果和验证状态；原始工具参数与原始工具结果不会进入情景。已验证的 `goal/change` 完成会生成高置信度任务证据，错误可以生成未验证证据。现有 `ProceduralLearningEngine` 仍独立消费已验证完成事件，因此情景连续性不会建立第二套程序存储。

面向模型的消费者把显式记忆问题分类为工作历史、学习历史、向后任务引用、诊断历史、个人资料记忆或普通工作。定向历史查询可以扩大项目范围并应用有界时间窗口；普通轮次继续使用轻量的当前项目召回。工作历史优先使用结构化任务情景，在安装中存在早于任务情景功能的工作时，则回退到已经持久化的用户任务事件。

定向呈现只包含生成自然回答所需要的证据。它不会暴露存储 ID、会话 ID、来源 URI、事件名称、置信度标签、层标签、文件系统路径或原始工具载荷。除非用户明确询问个人资料记忆，个人资料主题不会混入工作历史或学习历史回答。

模型看到的定向证据都可以从持久会话与认知事件重建。无密钥 headless snapshot 通过真实 Loader 组合启动应用，记录已验证任务，重启运行时，询问以前的项目，并固定组装出的面向人的记忆上下文。

## Alternatives considered

**持久化 `RecentTaskLedger`。** 这可以让有界任务列表跨重启保留，但会在认知日志之外建立第二套持久历史机制，也无法自然支持时间、项目、生命周期和来源过滤。

**让所有自动召回都跨项目。** 这样更容易找到历史，但会在普通轮次混入无关项目并增加无用上下文。因此跨项目访问保持显式并由意图驱动。

**从 Git 提交或仓库新近度推导历史。** 仓库状态可以作为代码工作的证据，但无法表示非代码任务、失败尝试、对话或 Git 之外的工作。由会话派生的情景继续作为规范连续性来源。

**在情景中保存完整工具参数与结果。** 更丰富的载荷能提供更多取证细节，但会增加秘密泄露、提示词体积和存储耦合。情景只保留公开工具名称和高层结果，而规范会话日志继续按现有策略保存详细事件历史。

## Consequences

PHOENIX 可以在重启后重建有界工作历史，包括显式跨项目与相对时间问题，同时不会把普通记忆变成全局个人资料转储。安装可以立即从任务情景功能之前已经持久化的用户任务事件获得部分连续性，新完成的工作则生成结构化任务记录。该设计只为有界情景和定向召回增加认知日志存储与动态提示 token，并有意放弃任务情景载荷中的原始逐工具取证细节。
