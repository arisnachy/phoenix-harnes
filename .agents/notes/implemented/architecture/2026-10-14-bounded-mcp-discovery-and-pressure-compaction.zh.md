# Agent Note: 有界 MCP 发现与有效的压力压缩

Status: implemented

[English](2026-10-14-bounded-mcp-discovery-and-pressure-compaction.md) | 中文

## 问题

完整的已连接 MCP 目录会在每次原生请求和每个专家请求中重复发送庞大的模式。即使可移除的对话前缀只有几个 token，固定提示词开销也可能超过较早的压缩阈值。总结这个前缀会增加一次模型请求，却无法降低压力；对同一个无法缩小的区域反复尝试会重复产生这一开销。

## 决策

工具注册表在原生模式下通过限定作用域的 `tool_search` 发现机制呈现大型 MCP 目录。原生工具保持可见。发现操作仅搜索调用者获准访问的实时定义，返回有界元数据，并使选中的完整模式可用于后续请求。单个大型模式仍可被发现。活动发现窗口有大小上限，各 agent（智能体）之间独立，并在 agent 进入空闲状态时清除。注册、权限检查、参数验证、审批和实际 MCP 执行保留原有的权威来源。代码模式和组合呈现模式保留现有 SDK 与函数工具呈现。

自动压力压缩在请求摘要之前先计算最小持久化检查点的开销。无法缩小的过小区域会被跳过。对于确定性的无法缩小错误，同一定价前缀与替换代次上的再次压力尝试会被抑制；区域发生有意义的变化或模型路由变化时允许重新尝试。手动压缩和溢出恢复保留各自独立的行为，暂时性的提供方错误不会导致永久抑制。

## 考虑过的替代方案

**禁用已连接工具或降低模型推理强度。** 这些做法会削弱能力或更改用户要求的模型策略，却没有解决反复发送固定上下文和无效摘要请求的问题。

**截断每个模式和指令。** 参数约束和操作指令承载行为；盲目截断可能使有效操作无法访问或变得不安全。

**仅依靠更早的压缩。** 摘要无法移除固定工具目录，而过早的阈值可能反复选中极小的前缀。

## 后果

原生请求无需携带无关的 MCP 模式。首次使用之前，发现操作可能增加一次工具往返；从有界活动窗口淘汰的工具可以再次被发现。选中的超大模式仍会在下一次请求中产生完整模式的开销。代码模式保留完整 SDK 的开销。确定性压力错误不再引发重复摘要调用，而真实的历史增长、显式压缩和可恢复的提供方错误仍受支持。本地无密钥组合测试和回归测试用于验证行为；生产配额节省仍需后续使用观测。
