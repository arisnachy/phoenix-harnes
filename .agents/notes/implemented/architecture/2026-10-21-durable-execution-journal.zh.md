# Agent Note：持久化执行日志

Status: implemented

[English](2026-10-21-durable-execution-journal.md) | 中文

## 问题

原生引擎会在工作完成前确认请求。响应丢失、Host 重启、使命取消、磁盘刷新失败或模型变更，都不能静默重复任务，也不能把不确定的操作报告为成功。

## 决策

复用现有 Lead Session、Team 日志及统一使命账本。`team/execution` 保存带版本的完整快照，`team/execution-progress` 保存有界且按原生事件去重的元数据，`team/execution-context` 在派发前记录选择性记忆及其来源。不新增平行的使命或记忆数据库。

执行运行时在预留时固定提供商、模型、推理级别、能力、使命标识及取消纪元。同一幂等键拒绝不同的显式模型选择。预留操作可在持久化屏障修复后首次启动；已准备、已派发、运行中及不确定的原生工作必须核对同一绑定，不能启动替代任务。执行刷新失败后，读取回执会被阻止，直到下一次串行事务成功刷新保留的事件。适配器缺失时保持可恢复性。

用户中止会立即阻止派发，持久化取消会拒绝迟到的完成结果。使命取消仅影响捕获的那一个使命。Host 关闭会中止拥有的工作，并在现有处置预算内等待；超时是错误，操作仍被追踪，迟到的原生结果保持不确定。模型回合结束不会关闭仍有未完成执行的使命。

仅 Lead 可用的工具用于派发、列出有界回执摘要、恢复和取消。按能力路由选择一个已连接且兼容的引擎，同时保留实际模型路由。现有提供商继续通过内部适配器执行。可选学习服务仅提供有作用域和字节限制的过程参考资料，不传递指令或完整历史。Eclipse 执行引擎偏好独立于其两个模型角色和对话选择器。

## 备选方案

独立执行数据库会重复使命所有权并产生相互竞争的恢复依据。复用 Session 日志使请求、原生绑定、授权和结果位于同一持久流中。确认丢失后自动重新提交可能重复原生效果，因此恢复只核对原始原生标识。

## 后果

本地停止之后，已派发的外部工作保持不确定，直到原生引擎证明终态。不确定操作保留绑定并阻止使命关闭。原生引擎不可用时可用性会降低，但重复的键不能静默创建替代任务。

## 验证与限制

引导操作在联系同一正在执行的原生回合之前预留有界输入回执。重复的键返回现有回执，包括结果不确定或中断的提交，绝不盲目重发。Codex 使用带预期回合标识的 `turn/steer`，拒绝其他 Root 或已关闭的连接。关闭时在现有处置预算内等待输入回执完成。其他适配器在实现等效受支持操作之前拒绝引导。

针对性测试覆盖并发幂等性、模型不匹配、派发前中止、持久化失败修复、进度限制、使命隔离、冷恢复及有界处置。原生 Codex 已单独演示持久化回合完成后重启进程并恢复同一线程。协议夹具不能证明真实 OpenClaw 兼容性。组装 Loader、真实 Gateway、产物验证、更新集成、完整回归和发布晋级仍是独立门槛；本说明不声称它们已经通过。

## Token 与缓存影响

稳定工具模式新增五个仅 Lead 可用的操作。回执列表最多返回 32 个标识和状态；记忆默认限制为 4096 字节，每个操作最多记录 1024 个进度回执。没有原生用量对比测量时，不声称已降低计费 token 或提高质量。
