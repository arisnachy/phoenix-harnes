# Agent Note: 执行效率与完成质量桥接

Status: implemented

## Problem

外部 A/B 运行暴露出一个共同问题：PHOENIX 在流程性开销上消耗了过多时间，同时仍可能把不完整的证据当作任务已完成。

在相同模型、推理级别和任务下，PHOENIX 用时 20 分 20 秒，而 Codex 用时 8 分 18 秒。即使已经知道精确目标路径，先确认工作目录再执行根目录 `glob("*")` 仍可能耗尽递归搜索超时。普通修改任务还可能绕过 HARDNESS mission/goal judge。另一个任务图实现虽然通过了全部 16 个提供的测试，却仍违反明确的 `CycleError` 消息契约，并保留 O(n²) 的关键路径状态。

## Decision

HARDNESS 路由默认采用零额外轮次。确定性路由规则在 intent framing 阶段直接应用；仅在需要物化可检查的序列化计划，或新证据改变任务状态时，才调用 `hardness_workflow`。

资源解析采用精确路径优先。会话 cwd 被视为权威状态；已知或已观察的路径直接读取，失败后才升级到范围受限的搜索，工作区级 basename glob 只作为最后手段。现有 filesystem observation 状态继续作为唯一的文件版本账本。

只读的 `glob` 与 `grep` 使用现有 concurrency-safe scheduler 并行执行。Shell 执行继续保持保守和互斥，除非其他子系统明确证明可安全并行。

quality-policy 现在会识别用户请求中需要定向证据的明确信号。若用户明确要求公共错误契约或扩展性/资源行为，通用测试套件全绿不能单独关闭这些要求。HARDNESS 软件质量契约要求把每项验收标准映射到证据，并在相关时验证可观察错误契约和受控的规模/资源行为。

普通任务的完成审查改为自适应，而不是每次都自动运行。对于低风险且已有新鲜确定性证据的修改，确定性验证本身即可完成任务。只有当风险足以证明额外成本合理时，才调用只读语义 judge：例如用户明确要求 audit/review；安全、鉴权、权限、密钥、支付、迁移、生产部署或公共 API；并发、性能、延迟、内存、扩展性、复杂度、大规模数量或公共错误契约；相关修改/验证失败；修复后需要复审；或跨多个目标的大范围修改。通常最多只运行一次独立 judge；只有首轮返回 `needs_changes` 且 worker 完成修复或补充新证据时，才允许第二次复审。如果 judge 因基础设施不可用而 blocked，会为该任务打开 circuit breaker，不再重复尝试同一路径。Judge 输入压缩为变更目标与短验证回执，只保留 `read`、`read_image`、`glob`、`grep` 四个只读工具。Judge 本身不设置人为 token 上限；效率来自选择性触发与精简证据，而不是削弱审查能力。

## Verification

实现增加了针对需求信号识别、搜索工具并行模式、错误/扩展性质量要求、自适应 judge 触发、精简只读工具面以及不受人为 token 上限限制的 judge 审查能力的回归覆盖。合并前还依赖仓库 main guard、typecheck/build 和相关包测试。

## Alternatives considered

**新增第二套已知文件缓存。** 拒绝，因为 `fs-observation-policy` 已经拥有会话级文件观察和版本；重复状态会增加同步风险，却不能消除根本的发现轮次。

**完全禁止宽范围 glob。** 拒绝，因为有些用户确实需要穷举 basename 搜索。本次修改把根目录广泛发现降为最后手段，而不是删除能力。

**每个实质性且已验证的修改都运行独立 judge。** 在基准测试显示这种做法虽然提高质量、却可能让 token 使用量接近翻倍后被拒绝。现在低风险工作只依赖新鲜确定性证据完成，语义 judge 仅在风险触发时运行，并受明确预算限制。

**把行为放入 agent-loop。** 拒绝，因为仓库要求中央 loop 保持精简。完成桥接位于 HARDNESS adapters，并复用现有 hooks。

## Consequences

正常快速路径减少一个强制模型轮次，并允许独立只读搜索重叠执行。已知精确目标不再需要 cwd 确认或全局重新发现。对于明确的错误契约和扩展性/资源要求，即使聚合测试通过，完成质量门槛仍会要求相应证据。

代价是高风险或明确要求审计的任务仍可能支付一次语义 judge 成本；如果 judge 真正发现 `needs_changes`，修复后还可能支付一次复审。低风险且已验证的修改不会产生 judge 模型轮次。基础设施故障不再触发重复语义审查，输入未变化时也不会重复运行已经成功的确定性验证。
