# Agent Note: Secure browser login card and shared vault access

Status: implemented

[English](2026-10-20-secure-browser-login-card.md) | 中文

## 问题

Windows PowerShell 未加载 DPAPI 程序集，导致 Secure Ask 输入的网站凭据可能在持久化前失败。浏览器手动入口没有传递检测到的页面字段，受保护表单替换了实时聊天活动，Computer 仍只读取旧凭据。

## 决策

Secure Ask 保持仅供用户输入，作为浏览器下方的紧凑卡片显示。手动入口检查实际页面字段，实时聊天独立保留。Windows 存储在加密前显式加载 System.Security，并在报告保存成功前确认回读。

凭据接口为所选精确 origin 身份提供内部串行状态与解析事件。明确拒绝具有权威性，只有记录不存在才允许查询旧存储。私密值只进入当前用户的原生浏览器管道，不进入模型参数或会话事件。原生登录把附加字段限定在所选表单内，并拒绝必填附加字段缺失或跨 origin 的提交目标。

Chrome 操作只解析一次端点，并发读取独立的 DOM、凭据存在状态和记忆的字段布局。不缓存授权，也不削弱导航验证。

Windows 手动构建根据已访问 PID、深度和时间限制重启桥接器的祖先发现。系统 PID 重用可能形成环；无法验证祖先时结束发现，不重启 Host。

## 考虑过的替代方案

**使用普通 Ask 输入。** 回答会进入模型可见的对话，不能携带网站机密。受保护表单采用相似视觉结构，同时保留直达主机的路由。

**把 DPAPI 值复制到旧存储。** 这会重复敏感数据并产生冲突授权状态。浏览器通过已有凭据接口解析所选身份。

## 影响

保存、身份选择与凭据使用共享同一权威加密记录。网站认证仍需要可观察的浏览器证据；提交表单本身不代表登录成功。MFA、验证码、歧义表单和不支持字段仍需要人工处理。验证采用虚构凭据和隔离存储。
