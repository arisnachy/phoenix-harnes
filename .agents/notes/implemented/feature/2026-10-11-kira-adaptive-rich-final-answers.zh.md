# Agent Note: Phoenix 聊天内自适应富文本最终回复

Status: implemented

[English](2026-10-11-kira-adaptive-rich-final-answers.md) | 中文

## Problem

Phoenix 已能够在聊天中渲染 Markdown 和受限的原生可视化产物，但完成任务后仍可能输出难以阅读的大段文字、原始 JSON 或重复的状态报告。如果没有共享的展示规则，体验会随模型供应商变化，用户也必须重复要求格式化。

## Decision

共享的人性化交互提示要求 Kira 在有实质结果时采用聊天内清晰的可视化叙述：先给出结果，按需要使用简短标题、重点文本、有意义的小图标和箭头、比较表格；只有经过证实的数值和时间信息适合使用图表或时间线。已验证结果、来源、限制和后续事项必须清楚区分。现有 Markdown、Canvas 和 Phoenix 可视化渲染器继续负责显示，不需要 HTML、强制卡片或独立工作区。闲聊、敏感话题和简短提问保持自然、克制。禁止暴露原始模型生成 JSON、编造指标或图表，以及完成后仅为装饰而额外调用模型或工具。

## Alternatives considered

**把每条回复自动包装成彩色卡片或图表。** 未采用，因为多数回复不需要图表或容器，过度装饰会掩盖证据。

**以模型生成 HTML 或可执行 UI 代码替代 Markdown。** 未采用，因为现有聊天渲染器已经具备所需能力，执行不可信代码会扩大安全边界。

**任务结束后再调用一次模型或工具完成排版。** 未采用，因为这违背通用停止规则并增加时延和 token 成本。

## Consequences

Kira 获得跨供应商稳定的展示偏好，不引入新依赖、新 schema、渲染管线或用户配置。渲染仍依赖真实数据和可用工具。此提示影响模型行为，不能保证所有模型始终生成完全相同的视觉布局；原有的确定性渲染与可视化工具仍负责实际验证。

## Verification

人性化交互协议测试涵盖原生格式、证据准确性、图表使用条件、原始 JSON 防护、简单回复的克制展示，以及禁止仅为装饰而重启模型循环。
