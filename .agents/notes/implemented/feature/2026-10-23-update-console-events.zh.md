# Agent Note: 更新命令结果可视化

Status: implemented

[English](2026-10-23-update-console-events.md) | 中文

## Problem

更新侧边栏此前只显示一个持久状态和模拟百分比。更新器执行隐藏的 Windows 命令或重启 Host 后，界面无法解释依赖安装、编译、启动测试和切换是否成功。新 Host 尚未健康时可能显示 100%，而预热失败后又可能一直停留在“正在重启”。

## Decision

可信任的更新器在仓库共享 Git 控制目录中写入有大小限制、只追加的 JSON Lines 事件记录。写入器只接受固定生命周期、进程步骤代码、结果及数字退出码；不记录原始 PowerShell 输出、命令参数、文件路径、凭据或环境变量。Windows 主管进程和暂存更新工作进程报告实际开始、成功和失败。仅当新 Host 在准确的目标提交版本上通过健康检查后，主管进程才写入持久的 `updated` 成功结果。预热异常时保留旧 Host 并写入持久失败状态。

已有的 Host Remote 只读取日志末尾有限的字节，并校验步骤代码、结果、时间戳和当前目标 SHA。此功能扩展已有更新状态快照，不新增特权路由。侧边栏以本地化的时间顺序显示实际执行结果与退出码；短暂断线显示正在重连，而非伪造成功或失败。百分比只近似表示阶段，不作为完成证明。近期的 `updated` 事件在短时间内保持可见，供用户检查。

## Alternatives considered

**直接向 Web 传输隐藏 PowerShell 的完整输出。** 不采用：任意命令输出可能包含凭据及本地路径；Host 重启造成的网络中断也会让纯实时流丢失最重要的交接事件。

**根据超时和估算百分比推断执行步骤。** 不采用：耗时估算不能证明命令或替换 Host 成功。

**等待 Host 更新完成后才写入任何记录。** 不采用：主管进程与更新工作进程才是实际的进程所有者，即使 Host 暂时不可用，也可以报告命令退出结果。

## Consequences

用户不必打开 PowerShell 窗口即可查看已验证的更新阶段和失败命令。Host 断线仍会中断实时轮询，但日志可以在恢复连接后重新显示。记录条数和大小受到限制，也不会公开原始终端文本或其他程序输出。原有激活、回滚审批和沙箱策略保持不变。除合约测试和组件测试外，仍需要在真实 Windows 环境中进行端到端验证。
