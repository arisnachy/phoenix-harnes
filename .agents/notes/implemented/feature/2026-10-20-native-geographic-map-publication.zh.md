# Agent Note：基于证据的地理地图原生发布

Status: implemented

[English](2026-10-20-native-geographic-map-publication.md) | 中文

## Problem

原有地理渲染器支持声明式 geo_map 数据，但 Kira 没有将地图以真实聊天制品发布的专用模型工具。它有时仅在回复文字中声称地图已发布，实际上没有可见地图。缺失地图时，恢复按钮还会将真实的公共卫生地理需求误导为虚构世界的 scene_map。

## Decision

在现有 hardness 工具注册中增加 phoenix_geo_map。它验证受限的 WGS84 坐标、数据来源、图层 ID 和数值变量，自动计算可视视角，并发出 GeoMap 已支持的不可执行原生 MIME 制品。与虚构地图工具一样，返回的 artifactId 仅证明数据载荷已发出，并不证明终端用户屏幕实际显示成功。聊天界面继续使用现有 React 地图，不需要 MiniBrowser 或新图形框架。

缺失地图的恢复操作现在会将真实地理任务交给 phoenix_geo_map，虚构地图则使用 phoenix_scene_map。科研和医疗领域中，小型研究样本不能直接转换成省级患病率、热力图或地区排名。如果缺少经过验证的地点或必要数据，系统必须报告限制，不得编造坐标。

## Alternatives considered

**始终要求模型输出特殊 JSON 代码块。** 未采用，因为实际故障是只有文字的成功声明；工具调用可提供可审计的制品发布记录。

**重新构建地图渲染器或启动外部浏览器。** 未采用，因为 GeoMap 已提供原生 2D/3D 视图、图例、选择和导出；浏览器绕行会重复不可见渲染故障。

**自动补入研究点位或省份多边形。** 未采用，因为这会将局部研究样本误认为较大人群的结果，从而误导公共卫生地图。

## Consequences

地理任务现在可以通过可重放的工具输出和聊天原生渲染器交付。新增测试覆盖工具回执、错误地理数据、前端渲染和恢复路径。真实来源验证仍由研究流程负责；工具只能验证结构，不能证明流行病学代表性，也不能证明用户实际看到或点击了地图。缺少可信地理数据时，说明无法制作地图是正确结果。
