# Agent Note: KIRA activity strip and agent rail

Status: implemented

[English](2026-09-29-kira-activity-strip-agent-rail.md) | 中文

## Problem

原来的 KIRA 实时团队界面会把每个子代理显示成一张较大的悬浮卡片。并行工作时，这种方式视觉负担较重，会与主会话争夺注意力，而且活跃代理越多，界面的视觉复杂度越高。多代理会话需要稳定的几何尺寸，新增工作代理不应持续放大主要控制区域。

## Decision

KIRA 现在采用固定高度的活动条和右侧窄代理轨道。活动条无论团队人数多少都保持 44 px 高，最多叠放三个活跃头像，其余代理用 `+N` 溢出计数表示。活动条中央显示当前选中的代理、状态、专业方向，以及在存在时由该子模型真实生成的活动文本。

右侧代理轨道是所有活跃代理的持久选择器；团队较大时可独立滚动。选择轨道中的头像只会切换活动条所代表的代理，不会立即离开当前会话。激活活动条中的当前代理会打开对应的可继续子会话。活动条下方还可以按需展开一个扁平的详细列表；默认关闭，并且不再为每个代理创建卡片。

整个功能继续注册在 `shell.overlay` 中，并继续发布 `setWorkspaceOccupant('subagent', false)`，因此活动条和代理轨道都不会占用会话宽度。当最后一个活跃或等待中的子代理结束后，整个覆盖层会消失。

## Alternatives considered

**保留悬浮团队卡片，只缩小 padding。** 被拒绝，因为嵌套卡片结构仍会随着代理数量增加而膨胀，并且在视觉上仍与主工作区割裂。

**为每个活跃代理增加一个横向 chip。** 被拒绝，因为团队变大时顶部区域会不断扩展或换行，破坏稳定尺寸。

**只显示一个代理，把其他代理隐藏在菜单中。** 被拒绝，因为并行工作应该可以快速浏览并直接选择，而不需要额外打开菜单。

## Consequences

多代理活动现在只占用可预测的主要屏幕空间，同时仍可直接访问每个活跃工作代理。活动条负责状态展示而不是堆叠卡片，右侧轨道负责代理选择，详细列表只在用户需要时出现。在较窄的移动布局中会隐藏代理轨道，活动条继续作为主要的实时团队界面。
