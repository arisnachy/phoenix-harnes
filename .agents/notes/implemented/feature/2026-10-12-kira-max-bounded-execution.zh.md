# Agent Note: Kira Max 有界执行与知识恢复

Status: implemented

[English](2026-10-12-kira-max-bounded-execution.md) | 中文

## Problem

Kira Max 的 persona 描述广泛能力和团队身份，却重复路由指令，没有把任务拆分与相关记忆、文件所有权、停滞团队恢复及可观察的交付关联起来。更多指令和工作代理本身无法证明推理更好或交付更快。

## Decision

随产品提供的 [Kira Max 组合配置](../../../../apps/cli/config/agent-presets/kira-max/agent.cordis.yml) 包含统一执行契约。Kira 使用现有 HARDNESS 工作流规则、有界项目记忆及相关 skills；需要可检查计划时使用 `hardness_workflow`，需要受治理的任务执行或能力获取时使用 `hardness_run`。常规任务直接执行。检索记忆必须与当前证据核对，经过验证的经验可以进入持久记忆，但不得包含秘密。

独立专家收到 fresh 简报，其中明确目标、所有权、约束、相关决策、所需证据及完成标准。Kira 保留关键路径，随结果到达进行整合，复用已有专家并停止重复工作。单次等待超时不表示工作代理失败；多次等待没有变化后，Kira 执行有用工作或请求一次有界的部分结论。通过 `followup_task` 恢复 inactive 成员。

现有模型路由及团队身份保持权威。选定模型负责 Kira 的规划和监督；Codex 专家使用配置的 Luna Max profile，其他提供方继承当前选择。预设明确保留普通完成判断器的自适应预算：快速工作零次语义审查、标准工作一次、深入工作最多两次。正式 HARDNESS 任务保留独立判断器的单独要求。

此预设契约补充[持久 Agent Teams 决策](2026-08-05-agent-teams.zh.md)、[有界 Luna 工作代理决策](2026-09-29-phoenix-auto-parallel-luna-worker.zh.md)及[选定规划模型交接决策](2026-10-04-codex-selected-planner-handoff.zh.md)。这些决策的运行时所有权和路由机制保持不变。

## Alternatives considered

**每次提示都加载全部知识。** 完整历史记录和无关 skills 增大请求，并可能遮蔽当前证据。有界项目检索保留来源信息，只选择实际任务需要的知识。

**修改路由或关闭所有判断器。** 现有路由已经尊重选定提供方，普通判断器已有快速路径。缺少已证实缺陷时替换其中任一机制，都会改变有效的权限或质量契约。

**增加工作代理数量。** 缺少独立所有权的额外代理会重复调查并产生编辑冲突。保留一个、两个及例外情况下三个专家的有界自适应层级。

## Consequences

此变更强化模型可见的执行指令，并明确现有审查默认值；不引入新的调度器、模型能力或权限。实际质量和延迟仍取决于模型、任务及工具。不声称已测得端到端加速，也不声称与其他助手能力相同。交付报告区分实现、测试、发布和实际运行验证。

## Verification

无需密钥的 Kira Max 执行场景加载随产品提供的配置，使用真实 AgentLoop、Spawn 和 Agent Teams 路径以及脚本化提供方。定向记忆、工作流及团队路由测试覆盖现有支持契约。脚本化执行验证 harness 行为和组合，不证明已认证模型的推理质量。
