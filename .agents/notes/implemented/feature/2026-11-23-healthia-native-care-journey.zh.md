# Agent Note: Healthia 原生临床诊疗流程

Status: implemented

[English](2026-11-23-healthia-native-care-journey.md) | 中文

## Problem

嵌入式 Healthia 起初只提供受保护的患者登记和会诊编辑。虽然加密 Host 已经具备预约、检查医嘱、处方、收费、人员分配和长期随访等真实资源，原生工作区却无法操作。临床人员缺少明确的复核与签署步骤，完整病历还可能超过单字段长度限制。每日概览曾使用示意卡片而非授权记录。

## Decision

Healthia 继续以现有经过认证的本地 /health Host 作为临床记录、CSRF、专业角色和版本检查的唯一负责方。原生工作区现在包括真实数据仪表盘以及按角色过滤的预约、随访、实验室和影像检查、处方、内部账单、人员创建及患者授权表单。表单复用 Host 已有的受保护状态转换；负责医生复核并签署会诊前，医嘱与处方仍被禁止。专业用户可以回答 Host 生成的 Ask 访谈问题，不向普通聊天泄露患者资料。

临床编辑器把医护人员书写的内容分成病史、查体、评估和计划分别保存，拒绝悄然截断，并能够重建编辑内容。签署前必须明确复核和确认。人口学资料将出生时登记的生物学性别与自述性别认同分开，并通过有版本保护的更新保存。概览展示真实的授权患者记录与预约，不使用虚构数字。

原生打印通过用户明确操作生成转义处理后的独立文档，未签署病历明确加水印，内部账单注明不是税务发票。剂量辅助工具只对医生提供并独立核实的 mg/kg 和单次剂量上限进行算术计算；它不提供特定药物的推荐剂量，也不声称已经检查药物相互作用。患者门户仍然与专业账户分离，并需要明确开启。

## Alternatives considered

**把医疗资料存入聊天或浏览器 localStorage。** 拒绝，因为临床身份、来源、凭证和签署必须归属于 Host 已加密且可审计的记录边界。

**把 AI 草稿当成已签署医疗决定。** 拒绝，因为建议、临床提问和算术剂量计算不能替代负责专业人员的复核和认证签名。

**为嵌入式应用重建第二套临床数据库。** 拒绝，因为重复记录和不一致的患者标识将破坏纵向连续性和团队权限。

## Consequences

专业人员可一次选定患者，完成会诊、记录访谈回答、复核签署，并使用现有受保护接口开出检查和处方。行政角色只接触授权的日程、人员、分配和内部账单功能。未签署记录不会被标注为已开具处方。临床界面不再伪造每日统计。

现有患者门户仍需明确开启，并由专业人员控制信息发布。真实药物相互作用自动校验、经过验证的药物剂量目录、税务电子发票签发、完整 AI 诊断准确度及跨机构云端同步均不被宣称已经实现。

## Testing

无密钥测试覆盖角色限定的收费、带 CSRF 的受保护账单创建、安全打印、明确的剂量算术计算、临床笔记完整性、人口学资料版本更新与长篇病历内容。发布前还需通过完整 TypeScript 编译、网页客户端回归、双语文档配对和 Windows CI 检查。
