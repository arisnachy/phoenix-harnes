# Agent Note: 主动首页关注与持久兴趣任务

Status: implemented

[English](2026-09-29-proactive-home-attention-and-interest-missions.md) | 中文

## 问题

Phoenix 已经能够持久化定时任务、条件 watch、事件驱动 wake trigger、认知注意、后台 Job 与已授权 MCP 工具，但空白会话首页不会呈现这些后台工作的有用结果。用户可以明确要求 Phoenix 持续学习或监控某个主题，运行时也能够执行后台工作，但重新打开 Phoenix 时仍然显得被动，除非定时 chat turn 主动打断对话。

把这一缺口做成通知仪表盘会让首页变得嘈杂，并重复 Task Center 的职责。这里需要的是更窄的约定：持久用户意图驱动后台智能，而首页只在证据真正值得关注时显示极少量经过排序的投影。

## 决策

明确的持续目标可以成为一个持久的循环 `phoenix_task_create` 任务，并使用 `delivery: work`。主动协议会区分长期意图与随口提及；当已连接来源能够发出相关事件时优先使用事件驱动 wake trigger，并在后台执行时使用已经授权的 MCP/connector。长期兴趣授权分析与监控，但不会自动授权交易、下注、买卖、消息、预订、转账或其他外部写操作。

循环工作会在执行提示中收到最近的摘要。没有实质变化时，worker 返回精确哨兵 `NO_MATERIAL_UPDATE`；有变化时返回适合首页展示的简洁可行动摘要。任务元数据可以让首页投影选择 `auto`、`result`、`upcoming` 或 `off`，设置保守的相对优先级，并提供简短的即将发生事项文案。这些字段只影响展示，不改变执行、权限、调度或 catch-up 行为。

Host 提供只读 loopback `/phoenix-tasks/attention` 投影，它只从已经可见的任务状态派生。该投影排除尚未揭示的 surprise，抑制没有变化的循环结果，把结果年龄与 upcoming 窗口限制为七天，把最近失败排在重要后台结果与有用 upcoming 事项之前，并最多输出八条不含秘密的信息。原始任务指令、凭据、connector payload 与 provider exception 都不会进入该投影。

Web conversation shell 每分钟轮询一次这个本地投影，并在传输失败时保留最近一次健康快照。空白会话 Hero 只在问候语下方以内联方式显示前两条：小图标、标题、分隔符与弱化详情。不增加卡片、边框、badge、toast 或强制跳转；没有任何信号通过排序时，Hero 与安静基线完全相同。

## 曾考虑的替代方案

**在首页渲染完整 attention dashboard。** 这样能显示更多状态，但会在视觉上与 composer 竞争，并重复 Task Center 的职责。当前投影保持首页安静，把深入查看留给明确的 drill-down。

**把每个后台结果都作为 chat follow-up 发送。** 这样一定可见，但会把常规监控变成打断和额外模型 turn。首页投影可以在不制造对话的情况下呈现实质结果。

**从用户提到的每个主题推断永久兴趣。** 这样会产生意外的循环工作与资源消耗。持久任务需要明确的持续意图；普通问题仍然只是普通问题。

**让循环兴趣任务执行已授权 connector 能做的任何操作。** connector 授权是必要条件，但不足以证明用户对高影响写操作给出了长期意图。持久兴趣默认只授权分析与监控；只有任务明确授权该操作且正常 approval 仍允许时，才能执行外部写入。

## 后果

Phoenix 可以让明确的用户兴趣跨重启持续存在，使用当前已授权数据执行有界后台分析，并只通过用户开始对话前看到的安静首页呈现实质结果。定期课程准备和即将到期的一次性事项可以作为 upcoming 上下文出现，而循环分析任务在真正产生有用结果之前保持不可见。

首页 feed 是尽力而为的本地 chrome，不是交付保证。需要保证按时间或事件交付时，仍由持久 task、watch 或 wake-trigger 机制本身承担。浏览器一分钟轮询用非即时视觉刷新换取极低闲置成本；事件驱动执行完全独立于该轮询。
