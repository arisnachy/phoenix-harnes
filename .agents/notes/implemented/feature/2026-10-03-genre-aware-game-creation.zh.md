# Agent Note：按游戏类型创作

Status: implemented

[English](2026-10-03-genre-aware-game-creation.md) | 中文

## 问题

单一的高品质美术流程无法同时适用于几何浏览器解谜游戏和具象开放世界。仅列出复古 SDK 而不提供可执行的准备与验证指引，会使智能体无法区分现代复古风格和真正的主机产物。

## 决策

[内置游戏技能](../../../../apps/cli/config/agent-presets/standard/skills/game-development/SKILL.md) 使用简洁的路由指南，按需加载浏览器、Godot/Blender、原生复古和美术生产参考。两个智能体预设均要求游戏任务加载该技能。现有引擎保持主导；参考截图表达风格或质量，而非通用界面。

技能可执行程序检查选定的前置条件，仅通过固定的平台包管理器参数显式安装免费的 Godot/Blender。它不会在 Phoenix 启动时初始化编辑器、配置云服务或安装原生 SDK。检测到编译器不同于确认 SDK、导出和模拟器就绪。

[质量适配器](../../../../packages/hardness/adapters/README.zh.md) 结合上下文识别 PlayStation、Sega、GTA 和抽象游戏请求。抽象街机或棋盘游戏允许精心设计的几何形状、程序化音频和紧凑场地；具象世界保留美术生产要求。明确要求的资源仍需来源记录和合适工具。当前的技术检查、视觉检查和实际游玩仍是独立的完成要求。

## 考虑过的替代方案

**要求所有类型采用同一种丰富世界美术流程。** 这会给几何游戏增加不必要的资源搜索和 token 成本，并妨碍其预期呈现。

**自动安装所有引擎和主机 SDK。** 这增加大量下载以及平台特有的信任和许可要求，却不能证明任何请求的游戏可玩。

**将所有复古风格游戏称为原生自制游戏。** 这会误报兼容性；真正的 ROM 或光盘交付需要目标 SDK 和独立的模拟或硬件证据。

## 影响

平台配方仅在相关时加载。大型现代游戏可以通过完整的可玩部分扩展，既不缩减约定目标，也不将单个部分称为完成的 AAA 游戏。原生工具链仍是显式前置条件；未经测试的构建、模拟器、导出和视觉质量必须如实说明。验证覆盖真实技能加载器、可执行程序的失败路径和可用引擎命令，而不声称仅靠指引就能保证成品游戏质量。
