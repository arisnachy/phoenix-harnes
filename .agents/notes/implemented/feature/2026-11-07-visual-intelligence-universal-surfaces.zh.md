# Agent Note: 通用智能可视化界面

Status: implemented

## Problem

PHOENIX 已分别支持通用画布、表格、临床表单和地图，但缺少统一受限协议，不能按数据自动选择界面、探索大型数据、编辑文档、展示多媒体、核实来源或安全分享。简单的查询、排序或缩放往往需要重新调用模型。

## Decision

新增可验证的 `visual_intelligence` 组件，作为 `generative-ui` 的独立类型。它根据数据选择表格、对比视图、图表、图廊/Bento、指标面板、文档、临床表单及地图。保留现有 `ui_canvas`、临床计算引擎、地图和体育组件。查询、排序、图表交互、文档版本及 CSV/Excel XML/JSON/浏览器打印无需再次调用模型。

来源仅作为**声明的证据**展示，不自动声称已核实。图片仅从允许的 HTTPS 域名加载，其他链接需要用户点击。导出数据禁止表格公式注入。模型发出的操作由已有用户点击回调处理，不能执行脚本或伪造执行回执。实时面板只接受同源 `/api/...`，在真实服务器响应后才显示已连接。路线仅在用户点击后调用 OSRM，发送两个选定坐标。

可选的本地加密库使用 PBKDF2 + AES-GCM 和用户现场提供的密码，支持加密文件导入/导出及手动设备间转移。**这不等于自动云端同步**：机构部署仍须建立身份认证、角色权限及审计日志。PDF 使用浏览器打印，Excel 使用 SpreadsheetML XML，并不冒充 XLSX 文件。

## Alternatives considered

**允许模型生成可执行 HTML 和脚本。** 拒绝，因为注入、私密请求及未经批准的操作存在风险。

**每次操作都调用模型。** 拒绝，因为客户端确定性操作更快且可检查。

**把 localStorage 当成临床病历数据库，或声称文件导入就是云同步。** 拒绝，因为敏感资料需要加密、权限及可信的主机服务。

**默认声称实时数据或路线可用。** 拒绝，因为必须由真实提供方的响应确认。

## Consequences

PHOENIX 可以在聊天中展示根据数据选择的交互式界面；严格校验数据上限、链接、坐标、指标与操作。已增加解析及渲染测试。敏感临床资料的生产应用仍需主机端访问控制、安全同步和机构审计。地图路由、实时数据和浏览器打印需要进一步验证。
