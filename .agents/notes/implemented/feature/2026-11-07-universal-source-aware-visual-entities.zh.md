# Agent Note: 通用、带来源约束的视觉实体

Status: implemented

## Problem

PHOENIX 的通用 `ui_canvas` 已支持指标、图表和表格，但缺少带图片的实体行、具有对应图标的结果，以及覆盖医疗、科学、教育和业务的图标词汇。体育已有专用卡片，但其他领域仍容易变成平面表格。

## Decision

增加 28 个本地 SVG 线条图标，不下载第三方字体。通用画布新增 `entity` 结果行、需要替代文字和来源的 `image` 图片节点，并允许指标设置语义图标。现有组合布局、筛选、标签页和点击动作保持原状。

图片仅允许固定公共媒体 CDN 中的 HTTPS 地址；显示图片必须注明来源。渲染器拒绝未知字段、伪造域名、不安全的 URL 和模型生成的脚本。图片加载失败时显示本地图标。域名白名单并不等于内容已经验证；Kira 仍然需要先检查真实来源。

标准 Kira 预设明确了如何根据领域选择可用图标、结果行、参考图片及响应式布局，不重复内容，不凭空编造官方标志。

## Alternatives considered

**允许任意远程图片 URL。** 拒绝，因为会带来追踪、泄露和虚假来源风险。

**只增加 NBA 专用模板。** 拒绝，因为用户要求任何主题都能复用。

**安装第二套渲染框架或远程图标字体。** 拒绝，避免启动成本和双重控制权限。

## Consequences

通用 UI 能以更清晰的结构呈现实体、指标、真实参考图片和状态，同时继续使用受限 JSON 协议。外部图片搜索和图片生成并不包含在此次渲染器修改中。已添加针对渲染与输入拒绝的单元测试；构建和跨浏览器检查仍需 CI 验证。
