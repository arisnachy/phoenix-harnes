# Agent Note: 面向任务的 Healthia 工作区

Status: implemented

[English](2026-11-23-healthia-task-focused-workspace.md) | 中文

## Problem

嵌入的临床应用在日常会诊中重复显示角色选择、认证信息、机构徽标编辑和患者选择器。从患者目录切换到会诊时会丢失选定患者，使受保护的电子病历看起来像普通行政表单。

## Decision

PHOENIX 应用框架继续负责聊天与输入框。Healthia 使用紧凑的上下文标题，角色切换和技术诊断链接放入按需展开的控件，而不永久占据页面。经过认证的临床工作从可搜索的患者目录开始。切换到会诊时只保留选定患者的不透明标识，并提供继续为该患者就诊的明确操作。

机构标识和退出登录移至诊所选项内，不再与患者搜索、会诊选择和草稿记录编辑争夺空间。临床 Host 仍然负责身份认证、记录、版本检查和电子病历写入。应用不会把患者字段或病历发送给 Kira、localStorage 或通用应用蓝图。

## Alternatives considered

**在每个模块重复患者选择器。** 被否决，因为这迫使医护人员重复识别同一患者，增加选错患者的风险。

**把会诊内容转移到聊天模型上下文。** 被否决，因为受保护电子病历是临床记录唯一授权的拥有者，角色视图不能代替授权机制。

**用模拟仪表盘记录取代诊所服务。** 被否决，因为虚构临床数据或模拟后端会误导用户对实际就绪状态的判断。

## Consequences

常规操作有清晰的搜索优先流程、较少的永久控件，并在患者和会诊界面间保持上下文。技术与机构设置仍可按需打开。患者和医生视图仍需要 Host 的真实权限。此次体验改进不代表尚未实现的预约、收费、文档签发或云同步已经可用。

## Testing

针对性的 React 界面测试覆盖收起的技术选项、认证后的临床入口、受保护记录写入以及选中患者的导航。完整编译、界面和 Windows 检查仍由 CI 执行。
