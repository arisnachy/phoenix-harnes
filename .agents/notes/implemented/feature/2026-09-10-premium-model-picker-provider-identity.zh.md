# Agent Note: Premium model picker provider identity

Status: implemented

## Problem

Composer 的模型选择器直接暴露了面向适配器的目录标签，因此较长的技术名称、预览日期以及不一致的提供方大小写会以相同的视觉权重相互竞争。菜单也可能被异常长的 id 撑宽，并依赖浏览器原生 `title` 提示处理溢出。提供方只有文字标识，在多提供方的大型目录中不够易于快速扫描。

## Decision

Composer 的模型选择器继续把 provider/model id 作为唯一的路由事实，同时为面向用户的目录增加仅用于展示的表现层。已知模型标签会被规范化为更紧凑的显示名称，preview/experimental 后缀移动到次级元数据中，Preview 以徽标显示，而不是继续占据主标题。提供方标题采用一致、紧凑的视觉层级，模型面板使用受控且便于扫描的固定宽度，并禁止水平溢出。

已知提供方公司可以从 Simple Icons CDN 延迟加载 logo。解析器只使用保守的提供方别名白名单；任意自定义 gateway id 不会触发猜测性的外部请求。每个 logo 槽位会先渲染本地首字母占位，因此离线模式、网络阻断、CDN 失败和未知提供方都会静默降级，不会改变模型状态、弹出 toast，也不会延迟选择。图片失败时只隐藏失败的图片，本地占位仍保持可见。

模型触发器和模型行上的原生 `title` 属性被移除。无障碍名称使用相同的友好显示标签，而真正提交的选择仍然使用 Host 广告出来的精确 provider/model id。

## Alternatives considered

**保留原始适配器名称，只调整 CSS。** 这能保留技术名称的原样呈现，但无法解决最主要的扫描问题：后端导向的后缀和日期仍然会占据主信息层级。

**抓取任意提供方 favicon 或推断公司域名。** 拒绝，因为自定义/私有 gateway 可能造成猜测性网络请求、泄露标识符或显示错误品牌。固定别名白名单加本地 fallback 更可预测，也更符合 fail-closed 原则。

**把所有公司 logo 都打包进 Phoenix。** 拒绝，因为这会扩大随应用发布的资源面，并要求手工维护 logo。对已知提供方延迟加载可以保持应用更轻，同时本地首字母 fallback 保证离线可用性。

## Consequences

选择器在不改变路由语义和 Host 模型契约的前提下更易扫描。友好名称规则仅属于展示层，随着新命名家族出现可能需要继续扩展。已知提供方的 logo 只有在可以访问图标 CDN 时才会替换本地首字母，但 logo 从来不是模型选择的必要条件，加载失败也保持静默。
