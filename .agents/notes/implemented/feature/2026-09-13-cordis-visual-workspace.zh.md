# Agent Note: Cordis 可视工作区

Status: implemented

[English](2026-09-13-cordis-visual-workspace.md) | 中文

## 问题

Phoenix 已经能够在对话旁边呈现临时的子智能体 UI，但由 Cordis 驱动的可视内容没有共享的呈现区域。显示图片、视频、网页或辅助文本时，要么会替换对话上下文，要么打开无关的浏览器界面，要么直接覆盖聊天而不协调外壳布局。当子智能体界面与 Cordis 内容同时活动时，这个缺口尤其明显：两者都需要一个可预测的右侧区域，而且关闭任意一个都不能破坏另一个，也不能让外壳保持在错误的收缩状态。

## 决策

布局服务拥有一个共享的可视工作区租约，并定义两个命名占用者：`subagent` 和 `cordis`。第一个占用者会保存当前侧栏和详情栏宽度，收起导航侧栏，并预留标准右侧工作区宽度。后续占用者共享这组临时布局，不会覆盖原始快照。最后一个占用者关闭时，系统会精确恢复之前保存的布局。

`ui-subagent` 通过 `ctx.layout.setWorkspaceOccupant('subagent', active)` 声明其可视生命周期。`ui-workspace` 提供 `ctx.visualWorkspace`，其中 `show()` 和 `close()` 方法拥有 `cordis` 租约。用一个新的 Cordis 内容替换当前内容时不会释放并重新获取租约，因此连续展示内容时聊天区域不会来回跳动。

Cordis 界面注册到 `shell.overlay`，并与预留的右侧宽度对齐。仅 Cordis 活动时，它使用整个工作区高度。当子智能体占用者也处于活动状态时，Cordis 移到下半部分，让现有子智能体界面保留上方位置。整个过程中对话仍然保持渲染，而不是被可视内容替换。

Cordis 内容接口支持四种展示类型：`image`、`video`、`page` 和 `text`。网页 URL 仅允许 HTTP(S)，并在沙箱化 iframe 中呈现，同时提供显式的外部浏览器打开入口。视频使用原生控制和内联播放。这个公共控制器只负责展示：它不会在 iframe 沙箱之外执行网页代码，也不会因为 Cordis 展示能力而新增工具或操作通道。

即使不存在普通详情会话，AppFrame 仍会为可视工作区预留右侧区域。可视租约活动期间隐藏详情栏拖动手柄，因为浮动可视界面必须与网格预留宽度保持一致。普通工具详情的关闭请求不能收起被借用的工作区，侧栏切换也不能在租约活动期间重新展开导航覆盖该区域。

## 曾考虑的替代方案

**为 Cordis 创建独立且无关的模态窗口。** 这样无需修改布局状态，但会覆盖对话，也无法与现有子智能体界面组合，并且会在 Phoenix 内部引入第二套窗口管理模型。

**直接复用普通工具详情面板。** 详情槽位按会话作用域工作，并与所选工具调用语义绑定。Cordis 必须能够在没有所选工具调用时展示内容，甚至普通详情面板原本关闭时也能展示，因此接管该槽位会把两个不同的生命周期混在一起。

**一个界面打开时关闭另一个。** 这种做法简化了几何布局，但会丢失有用的并发上下文。明确要求是 Cordis 可以在已经打开的子智能体界面下方出现，因此拒绝互斥方案。

**关闭后恢复固定默认布局。** 这比保存快照简单，但会破坏用户调整过的面板尺寸。因此租约会精确恢复进入可视工作区前的侧栏和详情栏偏好。

## 测试

`ui-layout` 测试覆盖第一个占用者保存快照、两个占用者共存、最后一个占用者关闭后的恢复、侧栏与详情区域的保护行为、占用状态订阅、重复写入以及不持久化。`ui-workspace` 测试覆盖 Cordis 租约获取、原地替换内容、关闭与 dispose 释放，以及幂等拆除。AppFrame 行为还由现有布局组件测试套件覆盖，包括详情栏的空间让渡逻辑。

## 后果

Phoenix 获得一个协调一致的可视工作区，而不是多个临时拼接的覆盖层。Cordis 可以在保持对话可见的同时展示网页、图片、视频和文本；子智能体和 Cordis 界面可以共存；最后一个界面关闭后会恢复用户之前的外壳布局。代价是租约活动期间可视工作区使用固定的约定宽度，并且侧栏保持收起。未来如果引入可调整大小的多窗格工作区，可以替换这套固定几何布局，而无需改变命名占用者的生命周期约定。
