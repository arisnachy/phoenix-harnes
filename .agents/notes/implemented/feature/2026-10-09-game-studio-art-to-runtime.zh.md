# Agent Note: 将批准的游戏美术绑定到可执行角色

Status: implemented

[English](2026-10-09-game-studio-art-to-runtime.md) | 中文

## Problem

生成的人物参考图可能十分精美，但游戏中的可操作角色却由完全不同的方框或临时形状组成。Game Studio 的发布工具此前只检查基本 JSON 元数据和 JavaScript 是否存在，因此不会检测批准的主角图集、动作和场景是否真正内嵌并绘制。缺失 JSON 清单时的错误说明也容易与真正的启动故障混淆。

## Decision

真正的 `phoenix_game` 发布工具现在要求具象动作游戏明确声明美术生产状态。`prototype` 可以作为诚实的临时可玩结果发布，但发布回执标明未完成；`production` 则必须提供真正内嵌、支持透明度的 PNG 主角图集、与实际像素对应的帧网格、不同的跑动姿势、出处参考、场景背景 PNG，以及每个素材在 `drawImage` 中的明确使用。这些只是结构检查，不会宣称角色与设计图在视觉上完全一致。抽象或解谜类型不必虚构主角。原有的程序化 Jungle Echo 示例已明确标为原型。

本地素材打包工具在脚本执行之前将验证过的 PNG 数据写入 `<img>` 的 data URI 元素，从而避免依赖外部 CDN，也防止 JavaScript 在素材元素出现之前就读取它。另一个本地准备工具插入唯一且真实的游戏 JSON 清单，并拒绝不一致或不合法的数据。客户端能区分清单缺失与 JavaScript 运行时失败，还会在隔离预览中显示游戏异常。标准版与代码版 Game Development 技能以及 Game Studio 技能要求 Kira 将用户批准的设计与实际游戏帧比较，不得仅凭概念图就结束高品质游戏任务。

## Alternatives considered

**只信任清单声明，不检查素材的实际使用。** 未采用，因为可以同时存在一张精美但未使用的图以及完全不相关的可玩角色。

**在隔离浏览器内使用图像识别自动保证相似度。** 未采用，因为那是隐含的高成本和非确定性能力；仍必须获取真实截图，并与用户批准的设计进行比较。

**要求每个解谜或竞速游戏都包含主角精灵。** 未采用，因为抽象游戏可能完全不需要角色，而几何艺术仍可很出色。

## Consequences

发布工具不再悄悄把具象方框占位图认定为专业美术。作者必须提供真实图集和背景，也必须诚实声明原型状态。检查约束了受支持的内嵌 HTML 创作方式；原生引擎需要独立的导入验证。该门槛不能证明外观身份、动画流畅度、实际透明像素、音频质量或真实设备性能。
