# Agent Note: Kira 浏览器可见性与 YouTube 视频证据

Status: implemented

[English](2026-10-11-visible-kira-browser-youtube-inspection.md) | 中文

## 问题

先前只有用户明确要求“打开”或“访问”网页时，聊天界面才插入 MiniBrowser。Kira 在研究任务中使用 Chrome MCP 查看 YouTube 教程时，可能留下未展示的 CDP 标签页，偶尔只有音频。Chrome MCP 只能读取网页文本和截图，不能提供带时间码的字幕或教程视频的指定画面。

## 决策

现在，Chrome 或浏览器 MCP 的导航、YouTube 搜索、视频检查和新标签操作也会将当前用户轮次标记为浏览器任务。普通搜索、网页文本读取和文件操作不会触发浏览器卡片。每张卡片属于原始对话轮次；新页面首次显示时会滚动到聊天中的可视区域，但不会在用户阅读时持续抢夺滚动位置。隔离的无头 Chromium 浏览器保持静音；YouTube 官方播放页在聊天中呈现默认不自动播放的预览，用户可明确点击按钮播放有声视频。

Chrome 连接器新增 `youtube_video_inspect`：只接受 HTTPS YouTube 视频链接与 YouTube 的 `/api/timedtext` 字幕服务。该工具读取可用的 JSON3/XML 字幕、时间标记与截断状态，优先选择西班牙语，其次为英语。取得浏览器操作权限后，它可定位视频时间点并附上最多三张真实 Chromium JPEG 画面作为多模态证据。不推测无法读取的语音，不假装进行音频识别，不绕过登录或 DRM，也不调用额外付费服务或生成假截图。

## 验证

针对性的测试覆盖间接浏览器工具调用、其他工具排除、视频分析请求、无自动播放预览、明确播放按钮、返回 Chromium 的操作、无头浏览器静音，以及视频链接和字幕服务校验、语言优先级、字幕时间码和缺失情况。真正的 Windows Chrome/YouTube 运行仍需验证 CI 及浏览器环境，不能仅凭代码断言多媒体完全可用。

## 备选方案

没有采用要求用户始终手动粘贴字幕的方案，因为应该首先读取可访问的公开视频字幕。没有采用自动弹出桌面 Chrome 窗口的方案，因为这会破坏聊天内浏览器的设计。没有采用把单张截图当作已解码视频证明的方案，因为截屏可能只包含缓冲或空白区域。

## 结果与影响

Kira 可以分析真实、可访问的 YouTube 时间码字幕及部分视频画面。研究任务中打开的浏览器页面会显示在 MiniBrowser 中。独立的无头 CDP 标签保持静音，只有用户在聊天中的播放器点击播放时才播放声音。公开视频访问、播放和字幕可用性仍受视频本身、YouTube 服务及权限限制。

## 限制及恢复

YouTube 可能拒绝字幕请求、隐藏播放器数据或阻止可靠的跳转取帧。工具会明确指出缺少字幕或图像，不会把标题与简介假装成完整视频分析。JPEG 仅证明 Chromium 捕获了图像，无法保证视频像素已成功解码，模型需要检查实际画面。其他网页继续使用 CDP 截图，浏览器操作权限不变。未来可另行增加自愿启用的本地音频转录能力。
