# Agent Note: HumanOS 有证据的操作自我状态

Status: implemented

[English](2026-10-22-humanos-grounded-operational-self-model.md) | 中文

## Problem

Phoenix 已具有 Kira 人性化交互协议、会话学习、认知关注、主动任务、现实观测和 HARDNESS 工具注册表。这些模块各自保留事实来源，但模型可能把能力描述误认为当前可以调用的工具，也可能混淆当前会话与其他 Agent 的未完成任务。再建立一套人格或可写记忆库只会增加歧义。

## Decision

完整 Agent preset 通过现有可进入会话日志的运行时上下文机制注册只读 `hardness:humanos-self-model`。它在上下文组装时读取已加载的 HARDNESS 状态与当前 Agent 或全局可见的持久任务，计算汇总数值。只公开模型选择状态、能力状态数量、到期任务数量与提示性关注标签；不公开任务标题、账户身份、模型名称、其他 Agent 的任务和隐藏惊喜。不调用服务商、不读取文件、不创建后台任务或新的记忆库，也不更改审批。

模型侧提示明确区分“已验证的元数据”与“工具实际可用”，要求通过现有权限和任务流程解析、核验具体能力。Kira 原有身份、Eclipse 路由和模型服务商选择均保持不变。HumanOS 不宣称机器具有主观情绪或意识，也不授予无限制执行权。

第二层有界观察会读取已有 HARDNESS 案例注册表，比较描述符当前版本与最近的验证记录，统计成功、失败、拒绝、矛盾及旧版本记录。最多分析 64 个能力及每个能力 12 条记录，并明确说明未检查数量；历史样本不等于工具当前可用。此变更不增加存储、模型调用或自动恢复权限。

## Alternatives considered

**新建 HumanOS 记忆数据库。** 不采用：会话学习、认知运行时和主动任务已经管理相关事实，重复状态增加不一致及隐私泄漏风险。

**自动唤醒并修复所有故障能力。** 不采用：全局能力状态既不能证明任务相关，也不能授权修改依赖。

**将全部工具名和任务名称注入模型上下文。** 不采用：元数据可能过时、敏感或带有对抗内容；低成本元认知提示只需要可信汇总。

## Consequences

Kira 得到基于真实注册状态、按 Agent 隔离的有限自我观测，但社交自然程度仍不等于意识。运行时工具必须单独解析和验证。当前实现是 HumanOS 的第一项工程能力，不是完整人类模拟或独立 AGI；晋升稳定版前仍须验证测试、Windows 启动和真实模型行为。
