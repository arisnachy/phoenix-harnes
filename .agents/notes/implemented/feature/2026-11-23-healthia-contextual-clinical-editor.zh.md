# Agent Note: Healthia 上下文临床编辑器

Status: implemented

[English](2026-11-23-healthia-contextual-clinical-editor.md) | 中文

## Problem

原生编辑器将生命体征和查体放在同一面板，要求重新输入纵向病史，且不能通过现有受保护模型适配器处理当前叙述字段。通用工作区检查没有公开临床导航目标。

## Decision

将编辑器分为六个步骤，同时保持持久化病历格式不变。只在明确请求后把已记录的纵向病史填入空白字段；不复用旧生命体征。仅提取明确标记的测量值，须临床人员确认后填入。BMI 和估算平均动脉压是算术计算，不是临床决策。

专用 Host 字段端点在模型推理前后检查负责医生、准确会诊版本、草稿状态和非保密记录。通过现有模型注册表和授权机制只处理明确选择的文本。模型输出是建议而非病历写入。源文本、版本或当前会诊改变时，编辑器拒绝过期结果。存在未保存修改时禁用复核、签署和打印。

现有自适应打开操作可导航临床步骤，并在绑定当前会诊和版本的预检查后启动本地草稿操作。公开检查只公开结构元数据，不公开该临时绑定或临床值。单独授权的上下文模型复核结合当前草稿和有限的授权纵向记录，结果只供专业人员参考，不自动写入临床字段。通用应用可独立恢复一个表单的上一修订版。临床身份、病历内容、字段值和凭据不会进入通用聊天事件总线。

## Alternatives considered

- 通用字段 AI 桥接：拒绝，因为临床数据不应进入通用聊天或其会话历史。
- 自动接受模型结果或复用旧体征：拒绝，因为必须验证来源。
- 新建电子病历数据库：拒绝，因为现有加密 Host 负责记录和授权。

## Consequences

原生编辑器支持明确请求的临床叙述优化和结构化手工录入。上下文推理仅覆盖有限的近期记录，而非全部病史。自动诊断编码、任意聊天修改病历以及自我改写医疗规则不属于本次交付。临床安全和实际模型执行仍需临床与提供方验证。

## Testing

编辑器测试覆盖纵向病史恢复、生命体征确认、明确模型授权和过期建议。存储测试覆盖责任归属、版本和草稿状态。CI 必须验证准确提交的编译与回归。
