# Agent Note：由用户控制的会话删除和批量清理

Status: implemented

[English](2026-10-23-session-deletion-and-bulk-cleanup.md) | 中文

## Problem

此前只要 Agent 已加载，系统就拒绝删除活跃的 Web 会话，妨碍用户主动要求的清理。

## Decision

普通活跃 Web 会话不会再仅因 Agent 已加载而被拒绝删除。Host 保留每个由自身创建或恢复的会话对应的 AgentHandle；删除过程中阻止并发创建或恢复；销毁所有者并取消及排空其任务；等待持久化退休屏障；最后实际删除会话日志并取消工作区成员资格。

永久删除网关仍会拒绝由不同生命周期拥有的 Agent，包括活跃子代理，直到相应所有者能授权销毁。这可防止迟到的写入者重新创建已删除会话。UI 提供批量清理面板，可按精确 ID、最后活动日期上限、包含边界的日期区间或全部会话选择；选择全部需要输入确认文字。每个选中的会话都通过通常的已认证单会话删除 RPC 处理，成功与失败分别计数。

范围仅限对话持久化和每会话日志目录，不包括共享项目文件或被全局引用的附件数据块。没有文件系统测量结果就绝不宣称回收了空间。未来的存储检查器与垃圾回收器可以按类别展示测量字节量，且只能安全清理零引用的数据块。

## Verification

已增加删除接纳及 Host 在冷恢复后继续保有所有权的单元测试，以及全部、日期、选择预览和无效日期默认拒绝的测试。它们均已纳入主要 Windows 测试门。真实 Windows 文件系统烟雾测试和共享附件引用计数检查仍待完成。

## Consequences

删除仅限可安全退休的会话；共享项目文件和被引用的数据块不在范围内。

## Alternatives considered

拒绝仅因会话活跃就禁止删除，或在未进行所有权检查时删除共享资源；前者妨碍用户清理，后者危及无关数据。
