# Agent Note：由用户控制的会话删除与批量清理

Status: implemented

[English](2026-10-23-session-deletion-and-bulk-cleanup.md) | 中文

## Problem

过去只要 Agent 仍处于加载状态，Web 会话就会被拒绝删除，导致用户要求的清理无法完成。

## Decision

普通活动 Web 会话不再仅仅因为 Agent 已加载而被拒绝删除。Host 为每个由自己创建或恢复的会话保留 AgentHandle，在删除进行时阻止并发创建或恢复，随后销毁拥有者（取消并等待其工作退出），等待持久化退休屏障，再物理删除会话日志并注销工作区中的成员关系。

永久删除网关仍拒绝删除由其他生命周期拥有的 Agent，包括活动子代理，直到相应拥有者能批准销毁。这可防止迟到的写入者重新创建已删除会话。UI 提供批量清理面板，可按精确 ID、最后活动日期截止值、包含边界的日期区间或全部选择；选择全部需要手动输入确认。每个选中的会话仍调用正常的、经过身份验证的单会话删除 RPC，成功和失败分别计数。

此功能只处理会话持久化和每个会话自身的日志目录，不删除共享项目文件或全局引用的附件数据。未经文件系统实测，不得声称已释放多少空间。未来的存储检查和垃圾回收器可以按类别展示实际字节数，并只清理引用计数为零的对象。

## Verification

单元测试涵盖删除准入、冷恢复时 Host 所有权保留、全部/日期/单选预览语义以及无效日期安全拒绝。这些测试已加入 Windows 主门禁。仍需完成 Windows 上真实文件系统的冒烟测试和共享附件引用计数检查。

## Consequences

删除范围仅限于能够安全退休的会话；共享项目文件和仍被引用的附件对象不在本功能范围内。

## Alternatives considered

拒绝仅因会话活动而禁止删除，也拒绝不检查所有权就删除共享资源；前者阻止用户要求的清理，后者危及无关数据。
