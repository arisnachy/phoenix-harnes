# Agent Note: Kira 主会话所有权

Status: implemented

[English](2026-10-01-kira-main-chat.md) | 中文

## 问题

除非父会话接收持久化的公开记录，真实子代理回复仅保留在子会话日志中。仅有实时活动轨道不能让用户跟踪团队、引用发言或添加表情。按照活动任务顺序重新推断名称会在代理完成后改变身份，浏览器断线后的重试也可能重复执行工作。

## 决策

Agent Teams 在根会话中拥有对模型隐藏的记录，保存真实的仅追加子代理文本及不可变的任务身份。现有 Session 流和会话组装器把这些记录送入现有主聊天。接收记录的变化明确关联为同一消息行的更新。浏览器通过投影获得规范的参与者名称、头像及职责，不导入服务器实现值。

主输入框面向已有的可继续直属子代理，并在重试时保留请求 ID。每个目标的持久化接收记录，以及子代理收件箱和历史中的接收标记支持部分发送后的恢复。Kira 接收静默且去重的监督通知；通知的接收先于监督检查点写入持久化存储。表情使用已验证的运行身份、幂等的参与者和表情集合以及现有投影流，不唤醒模型。聊天操作共享 Team 的接收截止、取消信号和有界卸载等待。

## 考虑过的替代方案

**独立子会话。** 这可显示子代理历史，但违背共同会话的要求，并迫使用户切换聊天才能参与。轨道改为突出显示已有的公开发言。

**界面生成团队对话。** 模拟回复不能证明真实代理作者或可靠发送。只有真实子代理文本被发布；私有推理和工具内容仍被排除。

**跨插件导入角色。** 将服务器目录导入浏览器插件违反客户端构建边界。规范身份以传输数据提供；头像资源由客户端拥有。

## 后果

服务器保留一份对模型隐藏的有界公开文本表示，因此增加持久化日志体积。源消息身份避免历史回填重复。读取会话不会启动未加载的代理。一次性子代理仍可见，但不能接收可继续回复。完整表情选择器按需加载，原生字符避免访问图片 CDN。部署保持两个专家的限制；简洁协作指导和有界模型读取控制额外上下文，但不声称已测量整体成本降低。

## 验证

服务测试覆盖真实普通子代理输出、无效表情、准确参与者和根会话权限、下一步骤的上下文回复、多目标部分发送、幂等重试、监督恢复及服务卸载。JSONL 和 SQLite 测试覆盖 Unicode 表情的持久化重放和移除。真实会话组装器将接收状态更新及完整重放合并为一条用户消息。浏览器传输测试位于 `apps/web/tests/kira-team-chat.e2e.ts`。
