# Agent Note：Game Studio 直接发布工作目录内生成的 HTML

Status: implemented

[English](2026-10-18-game-workspace-file-publisher.md) | 中文

## Problem

Phoenix 能发现 Game Studio 技能，但发布工具要求 Kira 在模型工具参数中再次传入整个 HTML5 游戏。大型程序及嵌入的美术和音频会使调用冗长、昂贵，即使源文件已经生成。用户只应该描述想要的游戏，不应该指定内部路径或工具调用。

## Decision

在现有 `phoenix_game` 工具中加入可选的 `file_path` 输入，与内联 `html` 二选一。文件必须是代理自身真实工作目录下的普通 `.html`，大小不得超过 16 MiB。拒绝符号链接逃逸、外部路径、URL、缺失文件、缺失工作目录和含糊的双输入。发布器只读取一次文件，执行现有清单绑定与校验，并将通过验证的完整 HTML 保存在调用结果中，避免之后的文件修改改变聊天里的作品。

小型游戏仍可使用原来的内联 `html`。Game Studio 技能要求 Kira 自行编写、校验并发布工作目录中的源文件，不需要用户了解工具名或文件路径。

## Tests and evidence

测试覆盖生成文件的真实发布、修改后的快照一致性、可执行游戏 MIME、仓库内的单关动作游戏，以及非法路径、过大文件和冲突参数的拒绝。浏览器里的真实玩法验证仍需独立执行。

## Consequences

这个变更消除了不同类型游戏共享的发布瓶颈，但并不意味着美术、AI、音乐和完整游戏测试已经实现或通过。

## Alternatives considered

继续要求模型在工具参数中传入完整 HTML。此方案会重复传输工作目录中已生成的作品，扩大提示词负担，并在较大型游戏中失败，因此未采用。
