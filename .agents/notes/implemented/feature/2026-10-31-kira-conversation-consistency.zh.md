# Agent Note：Kira 会话一致性与未完成的团队任务

Status: implemented

[English](2026-10-31-kira-conversation-consistency.md) | 中文

## 问题

主会话可能把专家对用户的直接回答标记为内部对话；当真实队友仍在工作时，Lead 回合却可能看似完成。“la compañera”等泛称隐藏了持久名单中的真实身份；只有状态的更新难以表明交付物是否真的完成交接。

## 决策

使用持久化收件人与回复信息区分直接用户回答和团队内部发言，模型引擎与代理身份分离。评估任务结束时，从现有 Session 事件读取当前任务参与者的最新状态。working、running 和 provisioning 阶段保持任务未完成；done 和 failed 解除该状态限制，但不会覆盖独立的目标、清单和任务凭据。Lead 的对话指导要求使用真实专家姓名，不重复等待状态，交付完成声明之前必须核实证据。

## 备选方案

额外调用语言模型润色消息会增加成本，并可能虚构交接或结果。隐藏所有团队消息会损失协作透明度。把所有活跃名单成员永久当作未完成则会阻碍正常关闭已结束的任务。

## 后果

不增加模型或网络调用。正在工作的队友可以阻止过早自动关闭；直接面向用户的回答与团队内部交接明显区分。参与者状态本身不能证明交付物通过功能测试，其他执行证据与任务门槛依然有效。

## 验证

专项测试涵盖 Kira 的具名汇报要求、参与者未完成状态及直接用户回复的可见收件人。推广到 main 和 stable 前仍需要完整应用快照和 CI。
