# Agent Note: 基于证据的 Eclipse Terra 与 Luna 协调

Status: implemented

[English](2026-11-02-eclipse-evidence-based-coordinator.md) | 中文

## Problem

长期使用 Terra 协调器及固定的 Luna Max 专家会在不需要协调决策时消耗大量令牌。用户报告的对照试验将质量从 76% 提高到 86%，但消耗了五小时额度的 22% 和每周额度的 6%。这些额度占比只是观察值，并非 API 令牌计数、可复现基准或单一模型的成本归因。

## Decision

Eclipse 自动模式默认由 Luna 执行和协调。只有收到新的团队结果、非琐碎问题、评审或决策时，已配置且账户可见的 Codex Terra 路由才替代既有的 Luna 请求；不会额外增加一次模型调用。同一轮最多允许两次 Terra 参与，同一步重试沿用路由，同一团队消息不会再次处理。简单格式问题、普通工具结果以及 Sol 的规划和故障恢复不会切换到 Terra。自动模式中的协调器偏好不会让 Terra 长期占据协调席位。

Eclipse 自动模式下 Kira 的 Luna 路由始终使用 Max，包括 Sol 规划结束后的执行交接；Luna 队友也保持 Max，不再根据任务启发式降至 Medium 或 High。旧版 Codex Sol 到 Luna 的交接也恢复为 Max。Terra 仍仅在出现新的团队决策证据时短暂替代 Luna，而不永久担任协调者。Hybrid 和 Manual 继续尊重用户明确指定的模型及推理档位。Eclipse 设置允许选择首选 Terra 模型及账户支持的档位，而不会自动退出 Automatic。所有路由保持在已选择的 Codex 提供者内，主协调者身份始终是 Kira。

## Alternatives considered

**始终使用 Terra 协调。** 普通工具步骤没有新增决策，却仍需支付协调成本，因此不采用。

**按固定步骤数切换模型。** 步数和工具调用数并不能证明需要协调，因此不采用。

**禁用 Sol 和所有独立评审。** 复杂策略变更和高风险修改仍需适度验证，因此不采用。

**将 Terra Low 强制设为全局默认。** 支持的推理档位应以实时账户目录为准，而不是硬编码假设，因此不采用。

## Consequences

基于证据的切换不会增加模型轮次，但一次 Terra 请求的令牌用量可能与 Luna 不同。没有实质性团队消息时，Kira 仍使用 Luna Max；每轮最多有两条不同的团队消息触发 Terra。强制简单 Luna 请求也使用 Max 可能增加推理令牌，因此这是优先保证质量的用户偏好，并不是已经证实的节省。Sol 到 Luna 的交接保留唯一 Kira 身份，但仍依赖可见规划和正确的会话事件交接。需要衡量各模型的会话用量、任务质量、总令牌、延迟和人工干预。本变更本身不能证明用户五小时或每周额度下降。

## Verification

针对新旧团队证据、两次切换上限、Sol 恢复路径、提供者限制、自动模式下 Luna 对话与执行均使用 Max、队友 Max 路由、Hybrid/Manual 明确选择，以及自动模式下选择 Terra 模型的行为均添加了专门测试。在声称令牌实际减少或质量提高之前，还需完成 CI 和完整会话基准测试。
