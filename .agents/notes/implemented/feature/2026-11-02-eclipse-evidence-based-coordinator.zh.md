# Agent Note: 基于证据的 Eclipse FÉNIX Terra 咨询与 Luna Max 协调

Status: implemented

[English](2026-11-02-eclipse-evidence-based-coordinator.md) | 中文

## Problem

长期使用 Terra 协调器及固定的 Luna Max 专家会在不需要协调决策时消耗大量令牌。用户报告的对照试验将质量从 76% 提高到 86%，但消耗了五小时额度的 22% 和每周额度的 6%。这些额度占比只是观察值，并非 API 令牌计数、可复现基准或单一模型的成本归因。

## Decision

Eclipse 自动模式中只有 Luna Max 担任 Kira 的执行协调者。FÉNIX 是确定性的证据门控和仅供主代理使用的 `fenix_consult` 工具，绝不会在后台把主代理切换到 Terra。只有真实团队消息报告实质性矛盾、验证失败、缺失要求或集成风险，并且 Kira 提供该消息 ID 和一个具体问题时，才会使用已配置的 Codex Terra 路由。咨询启动临时 Terra 队友，并向 Luna 汇报一次聚焦的评审；每轮最多咨询一次，持久化的 `team/fenix-consult` 事件防止恢复会话后重复调用。没有账户可用的 Terra 配置就不进行咨询。额外的专家调用需要令牌，但门控本身不调用模型。

Eclipse 自动模式下 Kira 的 Luna 路由始终使用 Max，包括 Sol 规划结束后的执行交接；Luna 队友也保持 Max，不再根据任务启发式降至 Medium 或 High。旧版 Codex Sol 到 Luna 的交接也恢复为 Max。Terra 仍仅在出现新的团队决策证据时短暂替代 Luna，而不永久担任协调者。Hybrid 和 Manual 继续尊重用户明确指定的模型及推理档位。Eclipse 设置允许选择首选 Terra 模型及账户支持的档位，而不会自动退出 Automatic。所有路由保持在已选择的 Codex 提供者内，主协调者身份始终是 Kira。

## Alternatives considered

**始终使用 Terra 协调。** 普通工具步骤没有新增决策，却仍需支付协调成本，因此不采用。

**按固定步骤数切换模型。** 步数和工具调用数并不能证明需要协调，因此不采用。

**禁用 Sol 和所有独立评审。** 复杂策略变更和高风险修改仍需适度验证，因此不采用。

**将 Terra Low 强制设为全局默认。** 支持的推理档位应以实时账户目录为准，而不是硬编码假设，因此不采用。

## Consequences

基于证据的切换不会增加模型轮次，但一次 Terra 请求的令牌用量可能与 Luna 不同。没有实质性团队消息时，Kira 仍使用 Luna Max；每轮最多有两条不同的团队消息触发 Terra。强制简单 Luna 请求也使用 Max 可能增加推理令牌，因此这是优先保证质量的用户偏好，并不是已经证实的节省。Sol 到 Luna 的交接保留唯一 Kira 身份，但仍依赖可见规划和正确的会话事件交接。现有最多 1,800 字符的专家简报现在保留长篇持久计划的开头和结尾，包括末尾验收标准，并明确标记中间内容为摘录，不再把片段冒充完整计划。需要衡量各模型的会话用量、任务质量、总令牌、延迟和人工干预。本变更本身不能证明用户五小时或每周额度下降。

## Verification

新增测试验证真实团队风险、排除普通成功结果和伪造消息、保留计划末尾验收标准、FÉNIX 仅供主代理使用、未配置 Terra 时拒绝、Luna Max 路由及 Sol 交接。尚未通过基准证明令牌节省或咨询质量。当前通过提示要求临时 Terra 队友只进行分析，此限制不是独立强制执行的工具沙箱。在声称令牌实际减少或质量提高之前，还需完成 CI 和完整会话基准测试。
