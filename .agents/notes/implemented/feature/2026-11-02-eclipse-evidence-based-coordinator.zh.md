# Agent Note: 基于证据的 Eclipse Terra 与 Luna 协调

Status: implemented

[English](2026-11-02-eclipse-evidence-based-coordinator.md) | 中文

## Problem

长期使用 Terra 协调器及固定的 Luna Max 专家会在不需要协调决策时消耗大量令牌。用户报告的对照试验将质量从 76% 提高到 86%，但消耗了五小时额度的 22% 和每周额度的 6%。这些额度占比只是观察值，并非 API 令牌计数、可复现基准或单一模型的成本归因。

## Decision

Eclipse 自动模式默认由 Luna 执行和协调。只有收到新的团队结果、非琐碎问题、评审或决策时，已配置且账户可见的 Codex Terra 路由才替代既有的 Luna 请求；不会额外增加一次模型调用。同一轮最多允许两次 Terra 参与，同一步重试沿用路由，同一团队消息不会再次处理。简单格式问题、普通工具结果以及 Sol 的规划和故障恢复不会切换到 Terra。自动模式中的协调器偏好不会让 Terra 长期占据协调席位。

Eclipse 自动模式的专家对普通任务使用 Medium，对复杂和特殊任务使用 High，而不是所有委派都继承 Max。明确指定的 Max 专家或推理档位仍被保留。Hybrid 和 Manual 继续采用原有的固定路由语义。Eclipse 设置允许选择首选 Terra 模型及账户支持的档位，而不会自动退出 Automatic。所有路由保持在已选择的 Codex 提供者内，主协调者身份始终是 Kira。

## Alternatives considered

**始终使用 Terra 协调。** 普通工具步骤没有新增决策，却仍需支付协调成本，因此不采用。

**按固定步骤数切换模型。** 步数和工具调用数并不能证明需要协调，因此不采用。

**禁用 Sol 和所有独立评审。** 复杂策略变更和高风险修改仍需适度验证，因此不采用。

**将 Terra Low 强制设为全局默认。** 支持的推理档位应以实时账户目录为准，而不是硬编码假设，因此不采用。

## Consequences

基于证据的切换不增加模型轮次，但单次 Terra 请求的令牌用量可能与 Luna 不同。自动模式下的普通专家默认采用较低的推理档位。没有实质性团队消息时仍使用 Luna；每轮最多有两条不同的团队消息触发 Terra。较低的专家推理档位可能牺牲困难任务首次尝试的质量，因此必须通过对照基准检验质量收益。需要衡量各模型的会话用量、任务质量、总令牌、延迟和人工干预。本变更本身不能证明用户五小时或每周额度下降。

## Verification

针对新旧团队证据、两次切换上限、Sol 恢复路径、提供者限制、显式 Max 专家设置，以及自动模式下选择 Terra 模型的行为均添加了专门测试。在声称令牌实际减少或质量提高之前，还需完成 CI 和完整会话基准测试。
