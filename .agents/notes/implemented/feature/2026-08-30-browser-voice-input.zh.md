# Agent Note: 浏览器原生语音输入

Status: implemented

[English](2026-08-30-browser-voice-input.md) | 中文

## 问题

PHOENIX 的对话编辑器没有语音入口。添加云端语音依赖会使麦克风使用更难解释，并且可能在产品级同意流程之外把音频发送到用户的浏览器之外。

## 决策

当浏览器提供 SpeechRecognition 或 webkitSpeechRecognition 时，编辑器显示麦克风控件。识别只在用户明确点击后启动，使用浏览器语言环境，仅接受最终转录片段，并通过现有草稿和光标路径插入文本。识别结束或编辑器卸载时会停止并丢弃识别器。此功能不持久化音频或转录内容，也不会自动发送语音输入。

## 考虑过的替代方案

**录制音频并上传到服务器。** 这需要新的持久化音频附件和同意约定，而且会让看似本地的控件在用户发送消息前就传输音频。

**默认使用 OpenAI 语音端点。** 这需要 API key 或主机凭据，并且不是免费的本地能力。

**在不支持的浏览器中隐藏控件。** 没有原生识别器时不显示控件，因此编辑器不会展示无法工作的操作；支持的浏览器会通过识别器生命周期报告明确的权限或错误状态。

## 后果

支持原生识别的 Chrome/WebKit 浏览器可以在现有编辑器中听写，同时不改变审批、附件或提交语义。浏览器支持和识别服务可用性仍是外部依赖；适配器会报告不支持、权限拒绝和普通错误，而不会静默丢失输入。朗读助手回复和跨浏览器离线识别器仍是后续独立能力。

## 测试

`packages/client/ui-conversation/tests/voice.client.spec.ts` 验证不支持浏览器、语言和配置、最终片段过滤、权限错误以及普通识别错误。ui-conversation TypeScript 程序通过，输入栏和语音测试共 2 个文件、79 个测试通过。
