# Agent Note: 按游戏类型设计与协调的 2D 动作

Status: implemented

[English](2026-10-09-game-studio-genre-motion.md) | 中文

## Problem

Phoenix Game Studio 的第一个原型已经能够运行横版射击游戏，但它的结构检查让**所有**游戏都必须包含枪械、平台物理以及双阶段首领。原来的简单人物也没有协调双膝、手肘、双手、枪管角度和弹丸运动方向。这不适用于解谜、竞速等不同类型，并容易夸大美术质量。

## Decision

Game Studio 工件检查接受可选的显式 `gameType` 类型配置，并依照对应类型检查控制、动画、场景数据和音效。未知的显式类型会导致检查失败。自定义类型需要声明玩法机制。原有横版射击契约仍受支持，但清单元数据不能被当作真实游玩证据。

一个可嵌入浏览器的独立运动工具包提供分析式双骨骼反向运动学，以协调腿和手臂，以及方向瞄准、程序化人物绘制、动画帧计算、视差计算和有界敌人决策。Jungle Echo 将这些代码内嵌，以在隔离环境中演示方向性弹丸和清晰的敌人攻击预警。Lumen Circuit 则通过真实谜题状态、键盘/指针操作及程序化音效验证了第二种可游玩类型。两者均为原创技术示例，不是商业级精美美术成品。

面向创作者的可复用流程要求 Kira 先选择游戏类型、研究真实参考、制作原创视听素材、使用真实骨骼或图集数据，并在声称品质达标前收集截图、动作和音频测量证据。示例仍为独立 HTML，不使用外部 CDN。

## Alternatives considered

**所有游戏继续强制遵循射击契约。** 未采用，因为这会让合理的非战斗游戏无法通过检查，并鼓励伪造首领或武器元数据。

**仅凭程序化骨架承诺完美精灵美术。** 未采用，因为反向运动学只约束关节；美术风格、解剖结构、光照、纹理一致性、音乐与手感仍需要专门制作的素材以及可视化和听觉测试。

**通过 CDN 加载游戏库。** 未采用，因为 Phoenix 内嵌预览处于网络隔离环境且优先离线运行。

## Consequences

类型化检查和两种可游玩示例解决了一个功能障碍，并奠定了可复用动作基础。这并不意味着已有通用生产级引擎，也不能证明每款生成游戏都具有专业画质。运动工具包仍需要每个角色特有的视觉素材；引擎相关的 3D 工作流程和真实设备录制也仍须单独验证。
