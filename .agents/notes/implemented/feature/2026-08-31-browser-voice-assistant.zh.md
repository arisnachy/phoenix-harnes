# Agent Note: 浏览器语音助手

Status: implemented

[English](2026-08-31-browser-voice-assistant.md) | 中文

## 问题

语音输入在听写后结束，并且要求用户另外点击发送和 assistant 的语音控件，因此 Phoenix 不能表现为免提语音助手。

## 决策

对话编辑器拥有明确的浏览器原生语音助手模式。用户在浏览器授予权限后通过麦克风启用该模式。最终识别片段会作为排队提交，浏览器分段结束或轮次完成后识别器会重新启动，结算的 assistant 尾部会通过本地 `speechSynthesis` adapter 播放一次。语音输出会移除代码和链接标记，在浏览器提供语音列表时选择最匹配的自然或增强语音，并使用适中的语速、音调和音量。再次点击麦克风会取消识别和当前播放。持久激活时间戳和消息 key 集合会避免播放旧的 transcript 历史或重复渲染的消息。

人类决定采用相同的非阻塞交互模型。每个问题都会获得主机发出的 60 秒截止时间，浏览器显示剩余秒数和自动选项，即使重新连接或浏览器关闭，主机也会应用确定性的推荐。显式选项元数据或推荐后缀优先；没有推荐的单选确认使用 Cancel、No、Reject、Refuse、Stop 或 Read-only 等保守标签，多选只选择显式推荐的选项。

该模式有意保持本地化并依据能力检测。输入需要原生 `SpeechRecognition` 或 `webkitSpeechRecognition`，输出需要 `speechSynthesis` 与 `SpeechSynthesisUtterance`；它不会静默替换成远程实时服务。权限、浏览器支持、忙碌会话和模型执行仍是识别器的明确停止条件，用户可以再次启用模式重试。

## 考虑过的替代方案

**只有用户点击发送后才提交**：拒绝，因为这会保留听写不是 assistant 交互的问题。

**播放每个 assistant 节点或每次 transcript 渲染**：拒绝，因为流式输出和投影重渲染会造成重复或打断；只有带稳定 key 的新结算轮次尾部才符合播放条件。

**加入特定提供方的实时语音依赖**：本基础版本拒绝，因为它需要凭据、传输生命周期和新的提供方定义；浏览器能力可以提供无需声称存在该服务的本地路径。

## 结果

麦克风会在普通轮次之间保持启用，并在浏览器识别分段结束后自动恢复；播放期间会暂停识别以避免回声，并在播放结束后恢复。用户必须明确启用该模式并授予麦克风权限。语音可用性取决于浏览器和本地语音引擎；缺少 `speechSynthesis` 时无法自动播放回复。

## 测试

语音 adapter 测试识别状态、最终片段聚合、权限错误、激活时间隔离、语音去重、语音清理、语音选择和播放生命周期。InputBar 测试验证自动排队提交，并确认最终片段后 assistant 模式仍保持启用。ChatView 与 conversation 测试验证结算的 turn-tail 集成。User-question、主机和 UI 测试验证 60 秒截止时间、保守的自动选项、重新连接回放和倒计时到期。聚焦回归套件通过了 48 个测试，现有语音助手覆盖仍有 136 个测试。
