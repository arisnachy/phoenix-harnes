# Agent Note: Persistent learning ledger

[English](2026-08-29-session-learning-ledger.md) | 中文

Status: implemented

## Problem

Phoenix 需要保留交互、成功工作和失败中的有用证据，同时不能把隐藏的模型状态、凭据或权限当作学习数据。

## Decision

`@phoenix-ai/dsh-session-learning` 服务观察持久化会话事件流和操作性的 `agent/error` 事件，将选定结果转换为有界记录，并把它们写入 harness home 下仅限用户访问的追加式 JSONL 日志。记录包含带品牌的记忆 ID、会话 ID、来源序号、类别、摘要、来源事件类型、置信度和时间戳。来源事件去重使重新加载和重试保持幂等；遗忘操作追加墓碑；搜索只返回带来源信息的活动记录，并按最新优先排序。服务挂载在基础组合中，`@phoenix-ai/dsh-tool-session-learning` 向模型提供有界的 `memory_search` 和 `memory_remember` 操作。显式记忆仅限于当前会话中的偏好、经验和技能；常见凭据赋值会在持久化前脱敏。工具返回证据和置信度，不会静默修改提示词、权限、凭据或受信任插件。

日志是学习监督器的第一层持久化。用户消息中的明确保留信号（例如重要、记住、始终和偏好陈述）会在无需调用记忆工具的情况下自动提升为高置信度偏好记录；普通交互仍作为较低置信度历史保存。经过 judge 筛选的经验、技能提升、语义检索、记忆管理命令和 UI 投影仍由独立消费者负责，因此每项策略都能在不改变会话循环或持久化对话格式的情况下演进。已提供的学习工具通过 `recall()` 最多添加八条记录：先选择高置信度的持久偏好、经验与技能，再补充最近的非交互证据；原始交互仍需显式搜索，记忆不会授予权限或被当作指令。

## Alternatives considered

**只把记忆存储在会话日志中。** 这样只有一个文件，但会把派生学习和规范对话流混在一起，并且不便于遗忘或重新评分。

**立即使用带嵌入的第二个数据库。** 检索更丰富，但会在学习策略经过验证之前增加新的持久化和迁移范围；对于基础版本，确定性的有界搜索已经足够。

**自动把记忆写入系统提示词。** 这样很方便，但会在没有明确读取的情况下让用户数据进入模型上下文，隐藏来源，并让过期或矛盾记录静默影响工作。

## Consequences

服务立即学习确定性的观察结果，并能在进程重启后恢复，但不声称具有人类认知或自主修改能力。追加式 JSONL 易于检查和恢复，而搜索仍是基于词语的，之后可以在不改变服务 API 的情况下替换。当前实现已有聚焦测试和类型/构建验证；真实用户记忆迁移、judge 反馈和浏览器控制仍需要各自的契约和测试。优先策略让明确标记为重要的记忆在后续噪声活动中仍可被自动召回，但不宣称实现了人类认知。
