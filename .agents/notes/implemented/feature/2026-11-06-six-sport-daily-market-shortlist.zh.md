# Agent Note: 六项运动每日盘口候选清单

Status: implemented

## Problem

PHOENIX 的每日扫描通常只返回 12 场比赛，最多 20 场。带报价的彩票工具仅接受四个运动键，默认只查询胜负盘，无法系统性比较已核实赛程中的其他盘口。要求每日 4 到 6 组选项时，流程可能过早结束。

## Decision

每日扫描现在最多返回 36 场已核实、尚未开赛的比赛。Kira 可以通过 `sports_chat_daily_market_shortlist` 请求默认五组候选（范围四到六）。工具仅对赛程中存在的赛事调用已配置、获授权的真实报价适配器，查询胜负盘、让分盘与大小分盘，并限制并发为三条、运动键最多十个。

每条报价必须与一个 ESPN 赛事按运动、联赛、双方名称及开赛时间匹配。双方对立盘口需要完整对应的结果和盘口线；足球三项胜负盘必须包括平局。报价必须仍然有效且带有更新日期。返回清单使用同一家博彩公司，每场比赛最多一组，并在有数据时优先展示非胜负盘选项。

第一阶段的价格全部标记为 `quote-only-research-pending`。启用 `deep=true` 时，系统最多对十或十一组候选进行有来源的历史表现、交锋、伤病、新闻与场地调查，并将博彩公司两侧的真实价格与近期得失分对照，结果标为 `descriptive-support`、`uncertain` 或 `unavailable`。这些标记和无水位盘口份额都不是校准概率、期望收益或必胜保证。最终仍需核对官方伤病、首发与结算条款。当至少四项候选通过深入检查且属于同一家博彩公司时，操作也返回原生的已报价票据卡片，包含精确价格、盘口线和每腿的描述性/条件性说明；它不代表有盈利保障的组合、已接受的投注或经过独立校准的预测。工具不会下注。

对于获授权的供应商，`sports_chat_event_market_menu` 使用 The Odds API v4 的真实事件 ID 检索额外让分/大小分、MLB 前几局、篮球/冰球分节及球员特殊盘口，并保留球员描述、盘口、时段、线值、博彩公司和更新时间。这是菜单发现，不是道具盘预测模型。

## Alternatives considered

**无论数据是否完整都强制生成六组。** 拒绝：可能把缺失赔率、已开始的比赛及不完整盘口冒充为可投注选项。

**单纯按赔率高低排序。** 拒绝：高回报不等于正期望值，不同盘口需要各自的预测模型。

**将同场相关投注视为独立。** 拒绝：需要由博彩平台提供组合价格和规则。

## Consequences

默认扫描覆盖更多赛事，单次请求最多查询六个运动键对应的可核实盘口。增加请求可能消耗付费 API 配额，因此有明确上限，并且只查询确实有比赛的联赛。基础扫描涵盖 20 个已知联赛；其他足球赛事仍需分页发现。新增事件级适配器可以发现球员特殊盘口及分节盘口，但独立预测模型与精确结算验证尚未实现。

系统以每日四到六组研究候选为目标，但当没有真实可用报价时会清楚说明不足，不会编造。离线行为由 `daily-sports-scout.test.mjs` 与 `daily-market-shortlist.test.mjs` 约束；真实供应商表现仍需要现场检查。

每日目标为五腿时，系统先调研最多十场有真实报价的候选；目标为六腿时最多十一场，然后筛选，不重复同一赛事。每日赛程按照多米尼加时间实际开赛日期过滤，而不是仅依赖上游查询日期。只转换明确列举的球队简称，不进行模糊配对。额外盘口首先通过 The Odds API 当前公布的真实盘口目录发现，以减少无效请求并披露未提供的盘口。

按圣多明各当地日查询赛程时，扫描器同时读取相邻的两个 UTC ESPN 日期分区，并按赛事 ID 去重；部分分区故障会明确报告，不会被误认为完整的空赛程。每日研究流程在确认同一家博彩公司完整而有效的常规盘口后，会调用受限的 `researchDailySpecialMarkets` 发现额外玩法。这些球员及分节盘口只标记为 `eligibleForTicket=false`，未经独立校准的市场模型不赋予预测概率。事件盘口目录无效时关闭后续付费查询，避免猜测不存在的盘口或泄露密钥。
