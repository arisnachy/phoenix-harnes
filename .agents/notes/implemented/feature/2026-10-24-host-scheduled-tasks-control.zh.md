# Agent Note: 计划任务中心的 Host 权限边界

Status: implemented

[English](2026-10-24-host-scheduled-tasks-control.md) | 中文

## Problem

Phoenix 全局任务中心能够列出持久主动任务，但 Host 的 `/phoenix-tasks` 通道原来只有读取和提示操作，浏览器无法真正创建或管理任务。

## Decision

复用现有的 loopback RPC 和持久化 `ProactivityEngine`，不在浏览器新增调度器。只接受严格验证的用户聊天任务：规范的未来 UTC 时间、非空且有限长度的标题与指令、单次或至少五分钟间隔的重复任务，以及固定的 `createdBy=user`、`senderIdentity=user`、`catchUp=latest`、`delivery=chat`。拒绝额外字段和特权身份。Host 支持用户明确选择已存在的活动根会话；只有恰好一个根会话时才允许自动选择。没有会话、无效会话或未明确选择多个会话时均拒绝创建。持久化引擎完成保存后才返回成功。暂停、恢复、取消、永久删除只针对用户可见任务，并在客户端通过持久化账本确认。永久删除会清除任务及其执行记录，但正在运行的任务不可删除。只有暂停或失败的任务可以恢复；正在执行的任务不可暂停后再次入队，从而避免重复执行。

## Alternatives considered

**使用浏览器 localStorage 和定时器。** 否决：关闭浏览器或重启系统后无法可靠工作。

**多个根会话时随意选择一个工作区。** 否决：可能造成跨工作区执行。

**浏览器直接创建 system 或 harness 任务。** 否决：会违反模型和 Host 的权限边界。

## Consequences

用户可在明确选择的活动根会话中创建和管理持久聊天任务；只有一个根会话时才自动选择。多个会话必须明确选择，无会话或目标无效时会拒绝创建。到期任务仍依赖 Host 启动；特权与条件任务继续走已有的授权工具。

任务中心使用 Host 已存储的有界执行记录展示历史，而不是从提示词推断结果。界面按语言设置呈现任务状态，安全地将结果摘要渲染为文本，不披露原始私有指令。

## Testing

测试覆盖输入验证、Host 持久化、暂停恢复取消及永久删除、运行期间的并发保护、会话所有权歧义、非法载荷以及前端对服务端确认结果的检查。提升到发布分支前仍需完整静态检查、覆盖率和 Windows 验证。
