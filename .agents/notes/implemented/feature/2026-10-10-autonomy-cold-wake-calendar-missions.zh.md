# Agent Note: cold wake, calendar recurrence and safe self-scheduling

Status: implemented

[English](2026-10-10-autonomy-cold-wake-calendar-missions.md) | 中文

## Problem

Phoenix 已经具备持久化计划任务、监视条件、连接器事件和只读关注界面，但事件驱动唤醒请求不能可靠地恢复**原始**会话：存储的目标不存在时，事件可能被发送到无关的活动对话。主动引擎也缺少原生的时区感知周度和月度重复任务，并且多个自主轮次可能提交重复的常驻工作。

## Decision

- 事件驱动唤醒通过 agent 注册表恢复已有的目标会话，并使用与计划任务相同的 Host 组合器重新组合其持久化预设。
- 对于已命名但不存在的目标，它绝不替换为其他活动会话；失败会保持失败，等待后续投递尝试，而不会被静默报告为成功。
- 冷唤醒会等待 agent 进入空闲状态后再记录成功，即使执行失败也会释放其租约。
- Phoenix 任务在 `timezone` 之外接受 `everyWeeks` 和 `everyMonths`。周度和月度重复任务会跨 DST 保持本地时间；短月份之后，月末第 31 日会在下一个有第 31 日的月份恢复。
- JSON ledger 会保留规范化的 `calendar` 重复规则和原始月日，因此重启不会丢失锚点。现有的 `once`、`interval` 和 `yearly` 快照仍然有效。
- Phoenix 发起的等价活动任务会去重；用户创建的重复提醒仍然允许。
- 面向模型的主动性规则会在已经授权的常驻目标内优先处理经过验证且收益较高的后续工作。事件、计划或模型提议都不会推断出新的权限。

## Alternatives considered

**把事件发送到任意活动会话。** 本决策保持已命名唤醒目标的隔离，并在该目标不存在时让投递保持失败。

**把重复任务限制为 `once`、`interval` 和 `yearly`。** 本决策加入时区感知的周度和月度日历重复任务，使本地时间锚点跨 DST 和短月份保持有效。

**去重所有重复提醒。** 本决策只去重等价的 Phoenix 发起常驻任务，同时允许用户明确创建的重复提醒。

## Testing

- 唤醒目标隔离、冷重新组合、空闲完成以及失败时的清理。
- 跨 DST 的周度挂钟时间。
- 跨短月份和进程重启的月末第 31 日恢复。
- 使用 `catchUp: skip` 处理错过的月度工作。
- 重复创建后不产生重复的 Phoenix 管理常驻目标，同时不阻止用户明确创建的重复提醒。

## Consequences

- Host 必须运行或重新启动，时间和事件触发器才能执行。当 UI 和本地进程未运行时，需要 Windows 服务/任务或始终在线的远程 worker；当电脑关机时，需要远程 worker。
- 后台工作仍需要可恢复的会话和可用的已配置 provider。传入的连接器事件需要正常运行且经过认证的 ingress。
- 此变更不会增加广泛的无提示网页/邮件监视、无限工具权限、任意 cron 语法或无需权限的外部写入。
- 在声明生产就绪之前，完整构建、Windows 启动和实时 OAuth/provider E2E 仍然是必须单独通过的证据。
