# Agent Note：在对话中原生发布通用图表

Status: implemented

[English](2026-10-20-native-universal-diagrams.md) | 中文

## Problem

模型可能声称已经发布家庭基因图或关系图，但聊天界面没有可渲染的对象。原有的叙事地图和地理地图并不能表示任意实体及其关系。

## Decision

新增模型工具 `phoenix_diagram`：它验证有界、无脚本的节点与边数据，通过既有输出流程发布 `application/vnd.phoenix.diagram+json` 工件，并只确认数据已发出，不声称已经检查客户端渲染。`DiagramSurface` 在工件和 `generative-ui` 文本两条路径中共用该数据结构，原生显示可选择的 SVG 节点、路径、信息和 SVG 导出；不接受未知节点、可执行属性或屏幕外坐标。基因图、流程图、思维导图和网络图是同一通用渲染器的不同用途，代理核心循环无需修改。系统提示将图形请求路由到发布工具，缺失的原生图形会触发文本警告。

## Alternatives considered

**全部使用 MiniBrowser 中的 HTML。** 否决：浏览器状态与聊天工件分离，依赖脚本且可能显示空白。

**把所有关系都变成地图。** 否决：地理位置无法准确表示家庭关系、连接点和流程方向。

**把工具回执当作界面成功证明。** 否决：服务端事件不证明浏览器的可视化和交互结果。

## Consequences

原生渲染离线、可复用，与现有工件和 UI 路径兼容，但节点位置需要模型提供，拥挤布局仍可能需要调整。首版不提供所有图的自动布局、不保证高级临床家系图规范，也不验证亲属关系事实。家庭和临床数据必须由用户提供。自动化 DOM 测试覆盖挂载和交互，实际视觉质量仍需要浏览器验收。
