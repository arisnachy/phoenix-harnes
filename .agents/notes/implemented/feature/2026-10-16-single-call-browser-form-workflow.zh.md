# Agent Note: 单次工具调用完成经验证的浏览器表单流程

Status: implemented

[English](2026-10-16-single-call-browser-form-workflow.md) | 中文

## Problem

一个十二字段表单耗时超过五分钟，但没有向模型提供任何截图。Phoenix 使用十三次浏览器调用、二十个模型步骤；记录中的模型执行约四分钟，而浏览器工具时间约十秒。建议项选择和猜测回执文字需要多次模型决策，成为主要耗时。

## Decision

Chrome MCP 连接器提供 `complete_form`：在一次 `inspect_page` 后，Kira 传入最多四个有序阶段（总共不超过三十个有类型的 DOM 操作）、最多三十项验证预期，以及可选的明确授权提交目标。后端在同一 Chromium 标签页执行各阶段和验证，并在阶段间留出简短的响应式渲染时间。任何操作或验证首次失败时，在提交前停止。已验证的表单最多提交一次，工具返回有长度限制的 DOM 内容、最终 URL 和耗时。可验证调用方明确指定的回执文字，但不会在没有该文字时编造确认结果。

原有 `fill_form`、`verify_form` 和 `submit_form` 仍保留，以支持需要分开执行操作的情况。Kira Max 的浏览器指令优先使用新的确定性流程，避免常规表单中的多余 HARDNESS、工具发现及模型路由步骤，并一次性报告结果，而非逐步播报。

## Alternatives considered

**只加快 CDP 截图和鼠标操作。** 实测工具时间仅占总耗时的一小部分，因此单独优化传输无法消除反复模型推理。

**提交后猜测成功提示。** 测试网站使用不同措辞，造成额外等待和虚假的工具失败。返回有限的页面内容，既保留证据也不猜测。

**先提交，之后再修复。** 重复提交可能造成副作用，不能用于恢复尚未确认的自动补全选项。

## Consequences

一次模型工具调用即可填写、选择、验证并提交一次经授权的表单，从而减少可预测表单任务中的模型交接。依赖 React 的控件可划分成简短阶段。缺少回执时绝不重复提交，也不绕过现有权限检查。结果区分提交尝试和已确认回执。此工具不承诺普适的实际耗时上限，不处理跨域对话框，也不能保证模型发现未知字段的速度。

## Testing

无需密钥的 DOM 测试涵盖已确认的自动补全标签、仅提交一次、选项缺失时提交前停止，以及回执文字不匹配时不重发。仍需真实浏览器验收来测量端到端延迟。
