# Crear y continuar cómics

La solicitud natural «hazme un cómic de…» activa la habilidad Phoenix Comic Studio sin exigir al usuario instrucciones de CLI. Abrir `.agents/skills/phoenix-comic-studio/SKILL.md` y `docs/phoenix-comic-studio.md`. Utilizar los comandos ejecutables de `scripts/phoenix-comic-studio.mjs` para biblioteca, cronología, personajes, importación de ilustraciones y maquetación. Generar arte real mediante la capacidad de imagen disponible, utilizando los IDs y referencias aprobadas; no fingir que un brief equivale a ilustración. Por defecto entregar PORTADA + INTERIORES con viñetas dinámicas (diagonales, verticales, circulares/inserto cuando ayuden a la narración) + CONTRAPORTADA, no una maqueta de tiras iguales. Generar imágenes reales independientes de portada y contraportada, importarlas y ejecutar `covers SERIE ENTREGA cubiertas.json`; la edición completa debe producir PDF si Chrome está operativo. Usar `layout.mode=auto` para una composición profesional variada o `layout.mode=freeform` para siluetas y posiciones detalladas. Antes de trabajar, y siempre después de un turno interrumpido o al escuchar «sigue», ejecutar `node scripts/phoenix-comic-recovery.mjs status SERIE ENTREGA [workspace]`; conservar plan, respuestas originales y arte verificado mediante `plan`, `record` y `accept`. Continuar únicamente las imágenes pendientes, sin adivinar ID de Canva ni confiar en JSON inválido o IDs de otro tipo. Tras auditar y ejecutar `render SERIE ENTREGA`, invocar directamente `phoenix_comic({title,series_id,issue_id})` y verificar su recibo. El usuario no debe escribir instrucciones técnicas, ni abrir MiniBrowser, ni ver Phoenix navegando dentro de sí mismo. Si no hay generador de imágenes o arte real, informar el bloqueo sin anunciar un cómic inexistente. Conservar datos en el directorio persistente y publicar solo lo que realmente exista. Verificar consistencia visual y revisión humana antes de comercialización.
