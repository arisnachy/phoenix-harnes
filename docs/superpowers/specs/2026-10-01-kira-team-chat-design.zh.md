# Kira 团队会话

[English](2026-10-01-kira-team-chat-design.md) | 中文

Kira 协调有限且真实的工作。子代理的实际输出与成员间消息一起出现在父会话的主聊天中，并使用稳定名称和头像。用户可以回复可恢复的成员，任何参与者都可以在用户、Kira 或成员消息上添加或移除有效的 Unicode 表情反应。

现有 Agent Teams 服务负责持久化仅用于聊天的记录与远程操作。捕获子会话中的实际文本，排除继承的 fork 历史、私有推理和工具内容。捕获不向模型历史注入内容，也不唤醒代理。稳定来源身份避免重放重复；受限读取向代理提供消息 ID。用户回复使用现有的获授权 continuation 操作。反应按参与者和表情幂等更新，在根日志持久化并投影到浏览器，不运行 LLM。

UI 扩展现有 Kira 渲染器，为普通用户和助手消息添加共享操作槽。维护中的表情选择器按需打开，支持搜索和肤色变体；常用反应仍有快捷按钮。保留部署中的成员限额，默认两名专家。协作指导要求有用证据、受限范围、简洁沟通，以及完成前由 Kira 审核。

验证涵盖来源身份、推理排除、fork 后缀、无效表情、切换与重试竞争、冷恢复权限、重载恢复，以及反应不调用模型。真实 Loader 和浏览器场景验证完整交互；持久事件或工具变化时同步 SDK 投影和文档目录。

所有交互都在现有主聊天和输入框中。回复保留原始消息上下文。用户可以同时提及多个现有成员，但只生成一条人类消息；持久接纳和逐目标回执确保重试安全。Kira 接收安静的监督上下文，保留任务责任并交付最终结果。侧边头像显示真实在线状态并高亮该成员现有发言，不打开另一会话。身份与所选模型相互独立。不展示 UI 生成的对话、工具记录、替换 surface 或私有推理。

Codex 中由所选模型负责规划、监督和解困，配置的 Luna Max 执行受限任务；其他提供方默认让成员继承所选模型。失败创建保留诊断和名称，但不占用成员容量。
