# 自适应 Harness、通用沙箱与专家实验室

English | [中文](2026-08-29-adaptive-harness-design.md)

## 目的

PHOENIX 必须在计划获批后持续推进任务，避免反复创建小计划；必须用一个自适应界面展示所有生成的产物；还必须能把用户指定的领域变成持久化、可验证的专家实验室。

## 产品要求

### 一个任务计划与有界审批

目标驱动器为任务生成一个完整计划。只有初始计划需要用户明确批准。后续审批请求携带策略计算出的建议、逐秒可见的截止时间，并在到期时自动作出决定。决定在任务继续前持久化。

自动决定按风险分类。低风险、只读且可逆的操作可以采用允许继续的建议。破坏性、携带凭据、涉及网络或不可逆的操作到期时默认拒绝，并触发现有的替代策略路径。任何审批都不能无限期等待。

### 自适应产物界面

所有模型产物使用一个持久化信封，其中包含媒体类型、执行能力、源数据、可选结果和尺寸提示。客户端根据这个信封选择渲染器，而不是为每种语言创建独立面板。静态文本、JSON、表格、Markdown、图片和源代码内联显示。可运行的 HTML/JavaScript 在隔离 iframe 中运行。Python 与进程产物通过已配置的沙箱执行器运行，并显示输出、错误与生成文件。

界面测量内容并在可配置上限内自动调整高度；内容更大时在界面内部滚动。每次运行都有停止、重启、复制、下载和展开控制。源数据和结果事件持久化，重放会显示相同产物而不会重复执行。

### 持久化专家实验室

专家领域保存主题、目标、成功标准、来源、数据集、假设、实验、指标、发现、生成技能、刷新策略和 judge 结论。状态依次为 `scoping`、`researching`、`hypothesizing`、`experimenting`、`evaluating`、`ready` 与 `blocked`。每次转换都是追加式会话事件，并折叠成持久视图。

实验室复用现有网页、文件系统、沙箱、技能和 judge 能力，并记录来源 URI、获取时间、内容哈希和出处。实验可由输入产物与声明的命令重现。只有独立 judge 根据成功标准验证证据后，专家才会变为 `ready`。评估失败会生成有界的改进任务，并从最后检查点继续。刷新是可选且受频率限制的；系统不会运行无界的后台学习循环。

敏感领域默认只做分析。体育博彩专家可以评估历史数据和不确定性，但不会下注、承诺保证收益或隐藏证据限制。

## 架构

审批截止时间扩展现有审批能力和会话事件。客户端使用统一的 `ApprovalCountdown` 显示待处理审批；到期和点击都经过同一 API，因此重放和实时执行共享同一路径。

产物扩展现有 HARDNESS 产物信封和 `HardnessArtifactNodeView`。`UniversalArtifactSurface` 选择纯渲染器，并通过沙箱 RPC 委托执行。只有拥有的 iframe token 发出的尺寸消息才会被接受；宿主在调整布局前应用最小值和最大值。

专家实验室是新的能力接缝，包含服务定义、持久 fold、工具消费者和客户端投影。它组合现有目标 supervisor，不修改 agent loop。目标 supervisor 每次只调度一个有界实验室步骤，并记录 judge 反馈、策略变化和终态。

## 失败处理

过期审批只有在校验建议的策略版本与风险分类后才会采用保存的建议。建议过期或无效时，请求拒绝，supervisor 选择另一策略。沙箱执行有进程超时、输出上限和取消路径；失败运行会成为产物结果，不会破坏任务日志。实验室来源失败会记录有界错误，并在达到尝试上限后替换来源或给出明确的 `blocked` 结论。

## 验证

焦点单元测试覆盖截止时间 fold、风险默认值、产物标准化、渲染器选择、iframe 尺寸验证、沙箱取消、实验室事件重放、实验可重复性和 judge 状态转换。Web 测试覆盖桌面与窄屏布局、长内容、可执行 HTML 及完整专家运行。构建测试验证组合应用加载新的 slots 与 RPC 声明。
