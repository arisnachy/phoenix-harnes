# Phoenix Research Studio 2.1 — 总体实施计划

[English](phoenix-research-studio-2.1.md) | 中文

本文件规定可验证的科学研究、文档发布、浏览器自动观察与授权分发的实施要求。它扩展 Phoenix Universal 3.0 和 UME，并沿用现有受控工具。计划文件不等于功能已经完成的证据。

## 完成标准与证据

- 简单事实查询只需在聊天中提供有来源的答案，不应制作不必要的文件；深入研究和学术文档请求需要屏幕可读报告及用户所要求格式的真实、已验证文件。
- 科学报告完成前必须具备论断来源关联、准确日期、研究局限、经检查的文档及实际存在且可打开的文件路径或下载链接；文字声称或虚构回执不能算完成。
- 报告状态与邮件、Telegram 的分发状态必须独立：REPORT_READY 不等于 SENT，ACCEPTED 不等于已阅读，某个渠道失败不影响有效报告。
- 在 Sol/Luna 切换、进程重启和故障重试之间保存原始用户目标、审批记录、任务检查点、产物及回执。

## 浏览器与会话体验

- 实时 MiniBrowser 活动侧栏需要独立于主 ChatView 滚动区域，自动跟随最新代理消息，包括流式文字和界面尺寸变化。
- 用户主动向上滚动时停止自动跟随，直到用户回到尾部或点击明确的返回最新消息按钮；不能抢夺键盘焦点或干扰网页操作。
- 优先自动使用现有 Chrome/CDP DOM 工具、截图、视频帧检查、公开字幕及可访问的页面内音频捕获，再请求用户协助。
- Chrome getDisplayMedia 的标签页、窗口、屏幕和音频选择需要用户通过原生选择器真实授权；不得伪造手势、绕过权限提示或秘密录制外部标签页。
- 无法显示 PDF、XML/JATS 或学术 HTML 时，应提供受支持的阅读/提取方案和可见错误，不能把空白界面当作已读取的证据。

## 研究项目与证据流程

- 持久保存项目记录，包括问题、范围、方法、检索表达式及时间、授权来源、参考文献、证据断言、章节草稿、数据、图表、格式配置、文件和渠道偏好。
- 根据任务选择适当的真实连接来源，如 PubMed、Europe PMC、ClinicalTrials.gov、Crossref、OpenAlex、官方政府数据和体育数据流；候选目录不得冒充已经认证的 API 连接。
- 按 DOI/PMID/URL 去重，并记录断言来自全文、摘要、元数据、原始数据还是尚未核验的搜索片段。
- 仅从实际获取的材料提取研究设计、样本、结局、方法、利益冲突、局限和撤稿情况；不得虚构队列、效应量、显著性、筛选数量或文献。
- 支持叙述性综述、系统综述、范围综述、具有充分数据的元分析、研究方案、临床与政策报告、期刊文章、专著和学位论文。
- 只有在真正完成相关程序并获得可验证数据时，才使用 PRISMA、STROBE、CONSORT 或学科专用报告要求。

## 文档模型与学术输出

- 建立统一的持久化结构化报告模型，包含章节、可追溯论断、参考文献、数据集引用、图形、表题、脚注、版面元数据和可选附件。
- 支持 APA 7、Vancouver/ICMJE 与机构专用规则，正确同步正文引用和参考文献；DOI/PMID/作者/标题/年份不一致时必须明确报错。
- 从同一个经验证模型生成真正可编辑的 DOCX、经过打印检查的 PDF，以及忠实、可访问的聊天 HTML 预览；没有安装实际渲染器时不得承诺 DOCX/PDF。
- 仅利用可复现数据集生成矩阵和定量图表，并提供标签、单位、来源、方法和图号；不得虚构图表来装饰报告。
- 只有在验证文件存在、可解析、页边距、表格裁切、图像完整性、引用对应关系和可读性后才能进入 REPORT_READY。

## 机构封面设计器

- 允许用户上传经授权的原始机构标志，并编辑机构、学院、院系、作者、导师、课程、日期、项目及学术标题。
- 提供可复用的学生 APA、专业 APA、生物医学 Vancouver、大学论文与自定义机构模板。
- 提供 Letter/A4 纸型、页边距、页码、前置部分及稳定 DOCX/PDF 输出的实时封面预览。
- 不得捏造标志、作者身份或学术隶属；个人信息仅保存在获授权的对应项目中。

## 交付中心：Phoenix、邮件、Telegram

- 在外部分发前或不依赖外部分发，先在 Phoenix 显示完整阅读视图、执行摘要、引用及真实 DOCX/PDF 文件操作。
- 如现有 Kira AgentMail 邮箱已激活则沿用，验证收件人、发件人状态以及服务是否真正支持文件附件；仅发送文本不能当作附带报告。
- 只有确认 Telegram 机器人令牌、聊天目的地、发送工具及权限后才使用 Telegram；不得把以前提到的机器人直接认定为当前已连接。
- 支持仅 Phoenix、邮件、Telegram、两者同时以及每项目审批偏好；外部发送必须遵守授权范围及敏感报告的额外隐私要求。
- 使用持久化幂等键排队发送，避免崩溃、重试或模型切换后重复发送。
- 独立记录每个渠道的结果，包括提供商消息 ID、附件或链接证据、时间戳，以及明确的 RETRYABLE_FAILURE/BLOCKED 状态。
- 对大型文件使用具有到期时间和适当访问控制的授权链接；不得泄露 localhost 地址或无保护的私人文件路径。

## 效率、模型路由与恢复

- 在项目中复用已验证来源、文章内容、引用与章节草稿，避免重复获取或把整份文档反复发送给语言模型。
- 限制搜索、截图、重试、提取文本、模型上下文、并发和单来源费用，同时不牺牲必须达到的科研质量。
- 记录实际耗时、提供商调用、检索查询、输入输出 tokens、缓存命中、覆盖率、验证错误和渠道回执状态。
- Kira 负责统筹；仅在确有需要时使用 Sol 规划/修复，确有独立子任务时才使用有限数量的 Luna 专家；不能为每个代理复制完整任务。
- 从持久检查点恢复中断研究；检查已生成的文件，并且只有在回执证明尚未完成发送时才重试外部发送。

## 实施阶段

1. 修复活动侧栏自动滚动、用户接管、优先自动检查浏览器视频/音频及明确的原生共享回退。
2. 建立持久研究项目、经过验证的学术来源导入、去重与论断来源矩阵。
3. 加入语义参考文献管理、APA/Vancouver 格式、学术写作器、图表和封面编辑器。
4. 通过真实安装的文件渲染器创建并检查 DOCX、PDF、HTML，并在 ui-deliverables 中登记真实产物。
5. 集成获授权的 AgentMail 附件与 Telegram 文档发送，包含用户偏好、提供商回执和可靠幂等任务。
6. 优化并进行端到端回归测试；仅在 Phoenix main guard 通过后发布经过验证的提交到 main 并同步 stable。

## 必须完成的验收演示

- 完成一次跨领域的体育、官方多米尼加比索汇率及神经科学文献研究，保存来源日期及不同观点。
- 确保运行中的 MiniBrowser 活动侧栏跟随流式代理文字，同时尊重用户的手动滚动。
- 验证 Kira 在显示 Chrome 手动录制回退前，先尝试允许的自动 YouTube 观察。
- 在聊天中生成具有原始参考文献、清晰方法和局限说明的可读研究报告。
- 生成并重新打开真实可编辑 DOCX 与可打印 PDF，且只包含数据支持的表格或图表。
- 渲染用户选择的机构封面和标志，不破坏版面或参考文献。
- 证明在用户授权后，邮件和 Telegram 具有独立真实提供商回执，或准确报告阻断状态。
- 中断并恢复任务，证明不会重复发送邮件、Telegram 消息、重复来源或昂贵工作。
- 对每项验收要求报告证据、风险、耗时、真实资源使用量和状态；阶段尚未完成时不得宣称科学套件完整。

## 当前实施边界

- 已实施：实时浏览器侧栏跟随流式聊天；research_search 仍是范围受限的联合网页搜索，research_scholar 则通过 Europe PMC 官方 API 获取真实出版物元数据。
- 已实施：phoenix_research_publish 根据带来源关联的结构化手稿创建并检查实际 DOCX/PDF/HTML，保存项目 JSON，支持 APA/Vancouver 引用、用户提供的机构标志和有数据依据的柱状图。发布工具**不会**独立证明来源元数据或研究方法正确。
- 已编写交付代码：phoenix_research_deliver 使用原生审批、经过验证的 Kira 邮箱或已绑定的所有者 Telegram 聊天、真实提供商 API、独立结果记录，并拒绝盲目重发。在用户账户完成认证并返回回执前，真实端到端外部交付仍未验证。完整交互式封面编辑器、通用数据提取与系统综述引擎及完整跨模型研究任务编排尚待实施。
