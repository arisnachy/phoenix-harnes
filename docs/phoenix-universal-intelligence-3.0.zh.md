# Phoenix 通用智能引擎 3.0 — 实施契约

[English](phoenix-universal-intelligence-3.0.md) | 中文

本文档描述 Phoenix Universal 的第一阶段集成实现。工具套件集成到现有的 `@phoenix-ai/dsh-tool-web` 插件，并沿用当前的 `ctx.web` 提供者、凭据、超时策略、AbortSignal 和 HARDNESS 任务与授权边界。

## 本次变更已交付

- `research_sources`：列出二十多个领域的候选来源。这些只是**候选搜索站点**，并非已连接或授权的 API。
- `research_search`：规范化用户问题、识别领域、执行一次覆盖面较广的搜索及最多两次限定权威站点的搜索、去除重复 URL、在单项查询失败时保留其他成功结果，并返回明确的状态、部分失败详情和来源 URL。
- 扩展能力操作协议：对持续变化的体育结果、汇率和天气数据优先使用原生实时数据源，避免夸大网页索引的实时性。
- 单元测试覆盖领域路由、查询数量限制、去重、提供者故障、空结果和输出限制。

## 宣称通用助手完成前的下一批验收门槛

1. 在 Sol/Luna 会话之外持久保存跨模型的任务检查点。
2. 将每项已执行动作映射到真实执行凭证及独立证据，防止错误地宣称任务完成。
3. 为官方体育、汇率、科学、健康、经济及更多领域提供经过独立认证的 API 连接器。
4. 建立受用户授权管理的 OpenAPI/MCP 发现和契约测试沙箱。
5. 使用 DOM/Playwright 优化浏览器操作速度和可测量的进度，同时保留视觉回退与必需的授权。
6. 验证多语言研究、来源日期及新鲜度、来源分歧、官方实时数据流和 API 配额，并使用实际提供者凭据测试。
7. 运行整个工作区的类型检查、代码检查、单元与集成测试以及 Windows 构建门槛。只有 CI 日志能够证明时才宣称测试通过。
8. 保持 `main` 和 `stable` 指向相同且经过验证的提交。

## 初始阶段明确不包含的范围

本阶段不宣称可以直接访问目录中列出的所有 API，不会自动安装任意第三方代码，也不保证有经过认证的实时体育结果或市场报价。搜索结果在查验一手材料之前仅是线索。模型的信心或工具调用成功不能替代交付证据。现有提供者的费用和速率限制仍然适用。

## 通用任务契约

每个请求都应转化为可验证的目标，选择权限范围最小且获授权的能力，使用现有受控工具采取行动，保留检查点，恢复暂时性故障，验证交付物，披露不确定性，并且仅从具有可靠证据的结果中学习。自主执行的外部更改必须通过相应的权限与用户审批边界。
