# PHOENIX 模型路由器

[English](phoenix-routing.md) | 中文

CLI 自带的路由器为每个新的用户任务或 agent relay，从两条已注册的 Harness 模型路由中选择一条。它观察公开的 inbox claim 事件；该事件发生在提示词组装之前。它不调用提供商、不发现模型、不管理凭据、不通过另一提供商重试，也不修改 Agent loop。

策略是确定性的，并完全暴露在组合配置中：

1. `[phoenix:local]` 强制使用本地路由。
2. `[phoenix:free]` 强制使用免费外部路由。
3. 文本长度达到或超过 `externalMinChars` 时使用免费路由。
4. 文本命中至少 `externalSignalThreshold` 个不同的已配置信号时使用免费路由。
5. 其他情况使用本地路由。

只有新的用户消息和 agent relay 会被分类。工具结果和注入通知沿用当前回合的路由。前缀会保留在模型可见请求中，因此路由不会静默改写用户内容。

## 模型体验

### 任务路由选择

#### 模型看到的内容

路由器不添加消息或提示词段。所选模型会看到普通任务，以及 `{{model}}` 变量指向同一路由的 persona。用户提供的 `[phoenix:local]` 或 `[phoenix:free]` 前缀仍然可见，因为路由器从不改写用户内容。

#### Token 影响

直接 token 为零。策略只检查已存在的任务文本，并且只写入请求路由配置。显式前缀只消耗用户自己提供的 token。

#### KV Cache 影响

从本地切换到免费通道或反向切换会改变提供商/模型，因此也改变缓存域。同一通道上的重复任务不会收到路由器添加的动态前缀，所以此包不会使该通道可复用的提示词前缀失效。

## 已知限制与延后工作

- 分类采用字面文本规则，而非语义模型。运维者应根据实际工作负载调整公开的信号列表和阈值。
- 强制前缀不会从提示词中移除。
- 提供商中断恢复由每条路由自己的重试策略负责。路由器不会在请求失败后切换提供商。
- 必须预先安装本地模型并运行 Ollama；外部通道需要 `ORCAROUTER_API_KEY` 凭据。
- 内置 PHOENIX bundle 只把免费通道绑定到 `orcarouter/free`；路由器没有付费回退，也不会选择 `orcarouter/auto`。
