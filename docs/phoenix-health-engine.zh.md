# PHOENIX Health Engine / Clinical Flow（试点）

[English](phoenix-health-engine.md) | 中文

PHOENIX Health 是 Host 的**可选模块**，不会替代 Kira、Eclipse 或其他引擎。其本地临床界面默认关闭，**尚未获准用于真实患者诊疗**。

## 已实现状态

- 只有当 Host 监听 `127.0.0.1` 时，`PHOENIX_HEALTH_ENABLED=1` 才启用 `/health`。
- 病历使用持久 SQLite，临床内容采用 AES-256-GCM 加密，带版本控制与 HMAC 链式审计；SQLite 整个文件与元数据**并非**全部加密。
- 临床界面要求本地工作人员身份验证、角色、CSRF、机构权限，以及每名患者的明确诊疗团队分配。
- 支持就诊记录、SOAP 文档、复核与登记签署、处方、检查申请和结果、事务性库存、预约、结算与随访。
- 通信同意必须有证据并可撤销；单独勾选复选框不等于有效同意。
- 本地备份采用一致性 SQLite 备份与完整性校验；不能替代异地加密备份和正式密钥恢复。
- Gmail 仅在核实真实发件账户身份后，发送经授权且不含敏感内容的提醒；不附带临床资料。

## 专业工作流程与 ASK

1. 医护人员在已验证身份的会话中进入临床门户，并访问分配给自己的患者。
2. Kira 使用 `health_interview_plan` 与 `health_copilot_ask` 提出通用问题；现有 ASK 让用户选择由 Kira、专业人员或双方引导。
3. ASK 将问题标为敏感，不确认自动、超时或缺失的回答；真实临床信息只能录入受保护的病历。
4. 专业人员使用 SOAP 记录就诊并核对病史、过敏、急症、体检和结果。AI 不得虚构阴性发现。
5. 检查申请、处方和笔记须通过服务器控制与复核；签名绑定到已复核的版本。
6. 预约与提醒仅在权限、同意证据和发件人身份均满足要求时才执行。

## 安全与生产限制

- `health_copilot_ask` 不会读取病历中可识别身份的数据或发送给模型；仍缺少受权限和同意保护的安全临床上下文代理。
- 过敏、剂量和相互作用检查要求人工确认；尚无自动验证的多米尼加共和国药品目录。
- 仍缺少医务执照与身份核验、具有法律效力的电子签名、真实浏览器 E2E 测试、独立审计及临床和法律验证。
- 仍缺少 FHIR/HL7、LIS、PACS/DICOMweb、保险集成、患者安全门户、异地冗余和正式恢复流程。
- 实际使用前仍需额外安全、隐私、测试与法规审批；**PR #1192 不代表已获得生产认证**。

## 用于合成测试的启动方式

```powershell
$env:PHOENIX_HEALTH_ENABLED = "1"
pnpm phoenix
```

试点操作控制见 `packages/bundle/web-app/HEALTH-OPERATOR.md`。完成验证前不得使用真实患者信息。
