# PHOENIX Health Engine / Clinical Flow（试点）

[English](phoenix-health-engine.md) | 中文

PHOENIX Health 是 Host 的**可选模块**，不会替代 Kira、Eclipse 或其他引擎。其本地临床界面默认关闭，**尚未获准用于真实患者诊疗**。

## 已实现状态

- 只有当 Host 监听 `127.0.0.1` 时，`PHOENIX_HEALTH_ENABLED=1` 才启用 `/health`。
- 纵向病历采用持久 SQLite，临床内容使用 AES-256-GCM 加密，具备版本保护和 HMAC 链式审计；整个 SQLite 文件与元数据**并未**完全加密。
- 临床界面要求本地员工身份验证、角色、CSRF、机构边界，以及每位患者明确的诊疗团队分配。
- 就诊记录支持问诊答案、临床人员填写的纵向病史、仅基于已记录回答的 SOAP 草稿、复核与签署；检查、结果、处方、库存、预约、结算及随访受服务器权限管理。
- 通信同意需要证据并可撤销；单独勾选复选框不够。
- 本地备份使用一致性 SQLite 快照和完整性检查，不能代替异地加密备份及正式密钥恢复。
- Gmail 仅在核对连接的发件人身份后发送经授权的中性提醒，不附带临床病历。

## 专业人员与 ASK 工作流

1. 已验证身份的临床人员进入临床工作区，访问已分配给其团队的患者。
2. Kira 使用 `health_interview_plan` 与 `health_copilot_ask` 提出通用问题；现有 ASK 提供者选择由 Kira、专业人员或双方引导。
3. ASK 使用敏感问题，不将自动、超时或缺失回答视为事实；可识别的临床回答只保存在受保护病历中。
4. 专业人员复核病史、过敏、紧急情况、体检和结果。主观 SOAP 草稿可使用已记录的问诊答案，但不能虚构阴性发现。
5. 检查、处方与病历须通过服务器检查，签名绑定复核版本。人工标记的危急结果必须由负责医生明确确认并通过直接临床方式升级处理；本模块**不会自动通知医生**。
6. 预约提醒要求已验证权限、可审计的同意和发件人身份。

## 安全与生产限制

- `health_copilot_ask` 无法读取病历中可识别身份的内容并发送给模型；仍需设计、验证受同意和角色控制的安全临床上下文代理。
- 过敏、剂量及相互作用检查要求医生确认；尚无自动验证的多米尼加共和国药物目录。
- 仍缺少医务执照核验、合法电子签名、真实浏览器 E2E 测试、独立审计及临床与法律验证。
- FHIR/HL7、LIS、PACS/DICOMweb、保险集成、安全患者门户、异地冗余与正式恢复尚未实现。
- 实际临床使用仍需额外隐私、安全、测试与法规授权；**PR #1192 不代表生产认证**。

## 使用合成数据运行测试

```powershell
$env:PHOENIX_HEALTH_ENABLED = "1"
pnpm phoenix
```

试点操作控制见 `packages/bundle/web-app/HEALTH-OPERATOR.md`。完成验证前不得使用真实患者信息。
