# Telegram — Kira 的消息接收与通信

[English](telegram.md) | 中文

## 配置

1. 在 Telegram 中通过 [@BotFather](https://t.me/BotFather) 使用 `/newbot` 创建机器人。
2. 在 Phoenix 中打开 **设置 → 连接器 → Telegram · Kira**。
3. 保存并验证机器人令牌。Phoenix 使用安全的凭证存储。
4. 点击 **生成绑定代码（15 分钟）**。即使 Phoenix 重启，代码也会在保险库中保留十五分钟。在与你的机器人的**私人聊天**中输入 `/start 123456`，将数字换成 Phoenix 显示的代码。
5. 机器人确认绑定后，向它发送一条文字指令。Phoenix 使用常规聊天网关创建或恢复一个会话，带上模型、预设和工具；代理工作期间会显示临时的「Kira 正在输入…」指示，并将 Kira 生成的回复作为第一条文字消息发出。如果模型失败，系统会说明故障，而不会假装有回复。
6. 点击 **刷新状态**，检查账号是否已绑定，以及接收器是否正常运行。

## 功能与限制

- 接收器使用 HTTPS `getUpdates`，并由唯一运行中的 Phoenix Host 处理。无需注册公开 webhook。
- Phoenix 关闭期间无法执行任务或回复。重新启动后会请求 Telegram 尚未清除的近期消息。
- 只有通过临时代码绑定的用户 ID 才能发送命令；群聊、机器人和未授权发送者都会被忽略。
- 偏移量保存在本地凭证中，消息按顺序处理；在完成处理前不会确认更新。
- 工作通过 `apiProxy.sessions.prompt` 网关发送，不会创建缺少配置的代理。输入指示约每四秒更新一次，任务结束即停止；即使 Telegram 无法显示指示，执行仍照常继续。结果由真实代理产生，执行故障不会被冒充为成功。
- Telegram 消息不会自动启用语音模式。此渠道**尚未实现**计划呼叫或语音消息接收。
- 更换令牌会清除之前的本地绑定。「断开连接」会删除本地凭证；如需同时在 Telegram 撤销令牌，请使用 BotFather。

## 故障排查

- **机器人已验证，但接收器未确认**：打开 Phoenix，并检查与 `api.telegram.org` 的连接。
- **尚未绑定用户**：生成新代码，发送 `/start CODIGO` 并点击刷新。对于新建的机器人，还需要先发起私人聊天。
- **telegram-webhook-active**：其他服务已注册 webhook；必须先在该服务停用 webhook，`getUpdates` 才能工作。
- **telegram-polling-conflict**：另一个进程正在使用同一机器人读取 `getUpdates`。请关闭该进程。
- **Kira 无法打开会话（`telegram-session-*`）**：从旧版升级后，保存的标识符可能指向缺少工作目录或预设的会话。恢复机制现可识别由网关创建的会话，在重启后自动迁移旧会话；如果原项目发生变化则创建新会话。不要删除机器人，也无需解绑；旧会话会保留历史记录。错误文本包含可安全用于诊断的代码。
- **收到确认，却没有最终答复**：旧版本可能创建没有模型或预设的 Telegram 代理。修复后的接收器通过网关创建完整配置的会话，并替换旧的活动会话，同时保留历史。更新并重启 Phoenix，无需重新绑定机器人。如果故障持续，请检查模型提供商与 Host 日志。
- **消息没有到达**：检查是否有其他安装使用同一个令牌消费 `getUpdates`。同一时间只能有一个接收器。

不要在聊天、日志或代码仓库中粘贴令牌。
