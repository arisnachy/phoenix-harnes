# Phoenix · 通用 PDF 编辑排版系统（v1）

[English](phoenix-editorial-pdf-system.md) | 中文

## 目标

PDF 并非只要能打开就算完成，它还必须清晰、忠于资料来源，并具有严谨的编辑排版。本能力是 Phoenix 通用引擎的**跨领域服务**，不限于医学研究。

## 展示模式

**发布原则：** 对外封面、页面、页眉与页脚不得带有「Phoenix Research Studio」「专业版」或「可验证文件」等内部标签和宣传表述。真实的作者、标题、机构、期刊与所属单位才是可见身份；技术生成来源属于内部回执，不属于正文。

**可用模式：**
- `academic`：严格的大学与机构格式，例如 APA 7，无装饰性封面。
- `journal`：供期刊审阅的中性稿件，不强制商业设计或目录。默认适用于 `document_type: "journal_manuscript"` 或明确目标期刊，除非用户另有决定。
- `hybrid`：有真实依据的图表和正文，加简洁的编辑封面。
- `editorial`：面向读者的报告、科普或商业产品，使用更鲜明的视觉身份。

- `academic`：优先遵守用户、大学或期刊的要求，不得以创意封面、配色或图表违反 APA、Vancouver/ICMJE 或机构模板。
- `editorial`：现代封面、稳定网格、清晰标题、导航和可追溯图表，适用于报告、提案、科普、诊断及商业资料。
- `hybrid`：科学写作与参考文献严谨，搭配克制的编辑设计，适合无需严格机构模板的现代专业科学报告。

## 现代风格目录（`design_preset` 选择器）

编辑展示模式 `presentation` 与封面的视觉 token 和矢量图形 `design_preset` 相互独立。因此 `hybrid` 能在十一种视觉身份间选择，而不会改变内容与引用。

| 值 | 封面风格 | 适用情况 |
| --- | --- | --- |
| `auto` | 上下文决定的确定性选择 | 按文档类型和标题主题选择的推荐默认值 |
| `editorial_navy` | 墨蓝、绿色轨道及金色细节 | 期刊、图书、专著及综合报告 |
| `clinical_teal` | 干净背景、垂直色带与精密圆环 | 医疗、科学、临床和证据综述 |
| `executive_amber` | 深色标题、几何块和琥珀色点缀 | 战略、公共政策、商业及高管报告 |
| `minimal_graphite` | 白色底、细线、低调字体 | 论文、技术分析、长篇阅读 |
| `creative_coral` | 紫红和珊瑚色、不对称图形 | 文化、设计、科普及创意提案 |
| `journal_ink` | 纯白细线网格及蓝灰色点缀 | 适合编辑式阅读的科学报告 |
| `research_violet` | 学术紫与点阵 | 数据科学、教育、量化分析 |
| `biotech_green` | 植物绿与矢量圆环 | 生物技术、自然科学、环境健康 |
| `ocean_blue` | 海洋蓝与波纹几何 | 环境、工程、技术 |
| `terracotta_report` | 大地色与不对称色块 | 社会科学、研究报告与人文学科 |
| `clinical_white` | 洁白配低调蓝绿点缀 | 健康及阅读型临床报告 |

| `academic_classic` | 无装饰设计 | 仅在 `presentation: "academic"` 下使用 |

自动选择先看**文档类型**，再看标题中的非敏感关键词。结果确定且不会在重试时随机改变；用户可用固定预设让多份文件保持一致，`academic` 规范优先于视觉偏好。

报告模型示例：
```json
{
  "title": "Informe de política sanitaria",
  "presentation": "hybrid",
  "design_preset": "executive_amber",
  "document_type": "policy_report"
}
```
此示例仅含展示字段。真正发布仍需 `phoenix_research_publish` 所要求的章节、可验证参考文献及其他数据。

## 自动化检查

CI 在 Windows 和 Ubuntu 上运行发布器，以 PDF 栅格哈希检查五种不同的封面，验证可见标题、元数据、内容边界、PDF/DOCX 完整性、`auto` 选择和严格学术模式。像素比较本身不能标记 `visual_page_review: passed`；仍需人工或真正具备页面视觉能力的评审。

**实际适用范围：** 当前预设已用于 `phoenix_research_publish`。其他 Phoenix 生产者未来可复用这套排版语言，但不能据此宣称所有现有产品都已采用。

## 排版规则

1. **封面**：矢量主视觉、清楚的标题、可选副标题，仅使用已提供的元数据，不虚构徽标、作者或机构，避免页面中只剩孤立文字。
2. **字体**：标题层级清晰、对比合适，A4 正文约 10.5–11 磅，合理行距、Unicode 支持和本地字体备用。
3. **配色**：深蓝 `#142b3a`、蓝绿 `#117e84`、琥珀色 `#d59a54`、柔和背景 `#f7faf9`，不能以颜色伪造统计确定性。
4. **网格**：安全页边距，页眉页脚不侵入正文，保留缩进，避免孤行、寡行与孤立标题。
5. **表格**：按文本内容分配列宽、重复表头、自动换行，只在完整行之间分页；过宽时用易读的证据块展示原始数据。
6. **图表**：必须依据真实数值、总体、时段与来源，标注单位、坐标轴、出处及解释限制，不虚构数字或制作纯装饰图表。
7. **目录与章节**：可点击书签、一致的标题、页码与低调分隔；DOCX、HTML、PDF 信息一致。
8. **引用**：保留 DOI、URL、选定格式及与正文引用的对应关系，不生成虚构文献。
9. **Phoenix 身份**：品牌不能冒充作者、机构或报告委托人的身份。

## 验证契约

宣告 `REPORT_READY` 前必须检查 PDF/DOCX 文件头、A4／Letter 页面、非空内容、链接、表格及没有裁切、溢出或重叠。自动结构验证不等同于实际视觉审查。若页面未渲染并实际检查，`visual_page_review` 应保持 `not_performed`。

内容准确高于设计。现代外观不能把叙述性综述说成系统综述，也不能为无证据的结论背书。

## 连续性

展示模式属于通用文档 schema。科学报告可以沿用现有数据模型，同一个排版引擎应面向图书、财务报告、技术文档、项目、商业计划和商业提案。结构化文档是事实来源，PDF 是渲染产物。

## 表格、图表与科学准备

排版独立于引用规范。每个表格和图形应有编号、标题、可核实的文献来源与注释；如果作者提供原始数据，还要保留单位、样本量 `sample_size`、方法、缩写、`interval_label` 和 `statistical_note`。编辑器**不得虚构数值、百分比、样本量、区间、统计显著性或所属单位**以填满页面。

支持 `bar`、`horizontal_bar`、`line`、`scatter`（需要与 `values` 对齐的数值型 `x_values`）和 `forest`（需要估计值、`ci_low`／`ci_high`、`method`）。其他图表应使用专门的可视化工具，不得造假。只有提供真实上下界和 `interval_label` 才绘制误差条；未知区间不能默认标成 95% 置信区间。PDF/HTML 包含图注，Word 可编辑文件保留数据与重复表头标记。

这些文件仅准备好接受**编辑审查**，不代表期刊录用、同行评审、独立核验或自动满足投稿要求。投稿前仍需检查当前作者指南、伦理、同意、署名、字数、结构化摘要、单独图表附件和最终人工审查。
