# PHOENIX GNOSIS — semantic operational intelligence

GNOSIS is a local, model-neutral read-only layer over the current scoped tool inventory and HARDNESS evidence. Inspired by the public concepts in NVIDIA Auto-Ontology; no source code, API, Docker service, vector DB or new dependency imported.

## Current release
- Build an on-demand graph of visible tools and declared visible dependencies.
- Search by tool names/descriptions with deterministic BM25-style retrieval and a small bilingual alias vocabulary.
- Report registration, exact descriptor-version audit evidence, conflicting outcomes, unresolved dependencies and missing candidates. Evidence is historical and not proof of live access.
- Expose phoenix_gnosis in the existing model-tool preset, with search, check, trace, conflicts and paginated inspect operations.
- No second memory store. Refresh reads existing canonical registries. No raw evidence payloads, secret paths, patient data, permissions or other-agent records are returned.
- Existing tools and approval/authorization remain execution authorities. No automatic model changes or background calls.

## Second slice
- Environment operation: allowlisted OS, selected model, provider registry, internet probe and fresh quota windows from existing Reality Context. No account identifiers, coordinates or paths; expired quotas are unknown.
- Context operation: compact advisory shortlist of up to five tools. It does not change prompt assembly or remove tools.
- phoenix_gnosis_memory: query canonical cognitive ledger only for the owning session, active records, technical entity relationships and source event references; no second ledger, no raw memory text, no automatic truth certification.
