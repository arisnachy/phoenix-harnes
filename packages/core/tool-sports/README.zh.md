# @phoenix-ai/dsh-tool-sports

[English](README.md) | 中文

Kira 的原生只读体育工具包括 `sports_chat_catalog`、`sports_chat_discover`、`sports_chat_games`、`sports_chat_mlb_pitchers`、`sports_chat_odds` 和 `sports_chat_ticket`。这些工具在现有聊天中返回有来源的赛事数据和声明式卡片，不增加新的导航菜单。

## 数据源访问

ESPN Site/Core 和 MLB Stats 是无需密钥的公开只读接口；公开访问不代表获得数据或图片转载许可。运营者可使用 `PHOENIX_SPORTS_ESPN_DISABLED=1` 或 `PHOENIX_SPORTS_MLB_DISABLED=1` 停用相应数据源。`THE_ODDS_API_KEY` 是用于获授权的商业赔率数据的可选密钥。没有该密钥时，仅呈现 ESPN 实际提供的报价；缺失的价格和盘口不会被虚构。`PHOENIX_SPORTS_ESPN_IMAGES_ALLOWED=1` 须先经过媒体使用权审核。密钥保存在主机环境中，工具不会输出密钥；请求仅发往固定的可信域名。

## Model Experience

### Verified sports fixtures and inline cards

#### What the model sees

Kira 从 `sports_chat_games` 获取有来源的赛事数据和声明式 `sports_game_card`，其中包含本地时间、球队、数据源以及仅在已核实时提供的首发投手、阵容和牛棚信息。`sports_chat_odds` 可以提供真实盘口，`sports_chat_ticket` 只进行票据模拟。

#### Token effect

每次请求仅将有限数量、有明确来源的赛事字段与卡片内容加入模型上下文；缺失的球员统计和赔率仍保持缺失，不会填入虚构数值。

#### KV Cache effect

实时赛事与赔率随请求而变化，因此工具返回内容可能改变上下文前缀并降低 KV 缓存的复用率；稳定的工具结构和静态指令仍可缓存。

## Known Limitations and Deferred Work

- ESPN 公开接口并非正式承诺的稳定服务，可能变更或中断；数据条款和图片再分发权限须单独核实。
- 所谓热门球队只是按已公布战绩推导的描述性趋势，既不是经过校准的胜率，也不保证胜出。
- 只有数据源确实提供的庄家赔率才可显示；系统不执行真实下注，也不支持直接交易。
- 助手必须在消息中输出有效的声明式 UI 卡片；单独获取工具结果不能保证卡片自动渲染。
- 某些项目没有逐球员比较、确认的首发阵容或牛棚数据；这些字段必须明确显示为不可用。
## 每日 4–6 组盘口研究清单

当用户请求当天彩票时，Kira 默认寻找五组**研究候选**（范围四到六），覆盖当天有赛程的 NBA、WNBA、MLB、NHL、NFL 和足球。 `sports_chat_daily_scan` 最多检索 36 场已验证的未来比赛。 `sports_chat_daily_market_shortlist` 使用获授权供应商的胜负、让分和大小分报价，核对联赛、双方球队、开赛时间、博彩公司与盘口线，拒绝过时或不完整报价，且不混合不同博彩公司。 `sports_chat_ticket` 现在支持查询六个运动键和多个基础盘口类型。

该清单**不是经过训练的预测或最终投注建议**：`marketNoVigShare` 只来自博彩公司的价格。Kira 还须核实官方伤病与首发资料、球员和对手表现、新闻、赛场背景及具体结算规则。球员特殊盘口、特定时段盘口和基础扫描外的全球足球仍需单独授权接入。若没有至少四组足够证据支撑的候选，系统会说明缺失，不编造赔率或保证中奖。工具不会自动下注。

可选的 `deep=true` 路径最多深入分析十或十一个有真实报价的候选，查询带来源的比赛历史、双方近期得失分，并将盘口两侧与描述性指标对照。每组选项会标为数据支持、仍有不确定性或研究不可用，但不会把简单的历史均值冒充经过校准的胜率或期望收益。若数据方向与赔率初选不一致，会保留真实的相反盘口及其价格，同时明确标注官方首发、门将/投手与伤病仍须核实。

获得授权的 The Odds API v4 密钥时，`sports_chat_event_market_menu` 能使用**该赔率商自己的比赛 ID**（不能是 ESPN ID）查询额外的让分/大小分变动盘口、比赛时段和球员特殊盘口。工具保留球员标识、时段、盘口线、博彩公司和更新时间，每次最多请求 12 类市场；目录并不保证博彩公司实际报价。每日探索器现在覆盖 20 个选定联赛端点，包括另外八个欧洲/南美足球赛事，但不代表覆盖全球所有比赛。

当至少四个候选具有同一家博彩公司可核实的最新报价时，每日深入研究工具还返回原生 `sports_ticket_card`，注明各腿的描述性证据或条件状态、具体盘口/线值/赔率，以及尚未下注的提示。它不代表已验证具有正期望收益的组合投注。

每日目标五腿时，研究工具现在可调查 **十场真实盘口候选**（目标六腿时最多十一场），再从中筛选，避免只考察六个热门选项。以 **America/Santo_Domingo** 的实际开赛本地日期为准；仅识别明确且无歧义的 ESPN/博彩公司球队简称。事件级盘口工具先检查供应商 **/events/{eventId}/markets** 实际发布的盘口，再消耗赔率查询配额，并列出所有已发布盘口键，同时优先跨球员特殊盘口、时段盘和变化盘口分配查询。发现失败会明确呈现，不把不支持或没有时间戳的报价当成有效赔率。

每日赛程扫描同时查询两个相邻的 UTC 比赛日期，再以圣多明各当地日期筛选，因为本地晚间比赛可能属于次日 UTC。系统按 ESPN 正式事件 ID 去重，并明确报告数据源部分中断。启用 `deep=true` 且配置 The Odds API v4 授权密钥后，每日工具会自动对同一家博彩公司报价的最多五或六场候选调用 `researchDailySpecialMarkets`。返回的 `specialMarkets` 保留真实比赛、球员、时段、赔率及更新时间，但明确标为**仅供研究**（`eligibleForTicket=false`、`estimatedProbability=null`）；没有专门的预测模型就不会直接加入最终组合。如果盘口目录不可用或不合法，不会盲目发起付费盘口请求。

每日候选列表会为每场已核实的 ESPN 比赛保留最多**两种其他有真实赔率的基本盘口**，而不是最初选中胜负盘后丢弃大小分及让分盘。`deep=true` 研究路径复用同一场比赛的独立调查结果比较这些盘口；`selectDailyResearchedMarkets` 再从每场比赛中选出描述性证据最强的盘口，避免重复赛事及混用博彩公司，并返回 `alternativeMarketsCompared`、`eventChoices`、`marketsReviewed`。盘口比较并不等同于已校准的胜率、正期望收益或必胜保证；证据不足的候选明确标为条件性建议，而非获批投注。

事件级报价目录进一步涵盖供应商文档中列出的**足球角球、黄红牌、射正与进球者盘口；NHL 门将扑救及封堵；MLB 投手续投出局数、前五局替代大小分及打者打点；NFL 四分卫传球与跑接综合指标；以及篮球抢断、盖帽、失误等**。目录只是可查询市场键；只有事件级 `/markets` 接口确认公布后才会查询真实赔率。未经过相应市场证据和独立模型核验的球员或分节盘口不会直接进入最终组合。

## 每日盘口价格审计与备选线

深度赛前调查会展示所选真实盘口的盈亏平衡概率、庄家去水份额、附加价和抽水。这些属于价格计算，**不是预测**。只有独立模型经过至少 24 场时间外留出比赛验证、与比赛/方向/盘口值完全一致且训练早于开赛，才可给出胜率和期望值；目前自动流程没有对让分和总分完成这种验证，因此明确显示未知。胜率门槛至少 80% 的热门队在缺乏校准时保持待核实，NHL 让分在首发门将及进球质量未经核实时不能直接纳入研究票。一个 ESPN 赛前档案可用于比较同场不同真实盘口线。原生价格卡仅包括有描述性证据的选择，不代表已证明盈利或投注成功。
